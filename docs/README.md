# 项目文档目录说明

`docs/` 保存对外接口契约、设计计划、实施记录和专题说明。文件对话改造的阅读顺序应始终以接口文档为先，再阅读阶段计划和代码目录 README；实现说明不能覆盖已发布接口契约。

## 子目录与文件说明

| 路径或文件 | 作用 |
| --- | --- |
| `接口文档/` | 对外 HTTP/SSE 契约的权威说明，文件对话相关接口以此为准。 |
| `更新记录/` | 已实施或持续维护的改造计划、设计决策和变更记录；阶段 1～12 的主计划位于此处。 |
| `plans/` | 较早的方案档案。仅作历史参考，不自动构成当前实现或接口要求。 |
| `feat/` | 专题功能总结。 |
| `superpowers/` | 早期调试页面的设计与计划档案。 |
| `llm-official-interface-test-guide.md` | LLM 官方接口测试指引。 |

## 文件对话文档工作流

1. 先阅读 `接口文档/文件对话.md` 与 `接口文档/文件对话新增接口.md`，确认请求字段、响应字段、状态码和 SSE 事件。
2. 再阅读 `更新记录/260707-文件对话功能改造计划.md`，理解阶段 1～12 的边界、实现顺序和未来基础设施约束。
3. 对照 `app/` 下各层 README 和测试目录 README 追踪代码落点与验证方式。
4. 若需求会影响公开接口，必须先确认并同步更新接口文档；禁止通过增删前后端参数绕过契约管理。

## 维护规则

- 接口文档优先级高于计划、代码注释和历史实施记录。
- 改造记录应说明设计决策、迁移风险、验证证据和未实现边界，不能把计划描述为已具备的分布式能力。
- 所有文档应明确当前 SQLite 单实例限制，并避免暗示已接入可靠队列或多实例协调。
