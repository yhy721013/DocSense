## 1. 文档目的

当前文件对话链路已经能支持基础 SSE 对话、历史查询和删除，但内部仍是同步代理式实现：

```text
Blueprint
  -> chat_service.py
    -> ChatDatabaseService
    -> legacy AnythingLLMClient
    -> AnythingLLM workspace/thread/stream-chat
```

该结构不适合继续直接叠加 `/llm/chat/title` 和 `/llm/chat/abort`，也不适合未来的多线程任务隔离、可靠任务队列、多实例部署、数据库一致性保障、高并发性能优化，以及整体 AnythingLLM 低耦合改造。

本文目标是提供一套可以逐阶段执行的重构计划，使文件对话链路最终具备以下能力：

1. 业务层只依赖供应商无关 Port/DTO，不直接依赖 AnythingLLM 具体类、HTTP 路径或原始字段。
2. 每次 `/llm/chat` 请求显式建模为一次 `chat_run`，支持状态机、并发互斥、中断、失败恢复和队列化。
3. 本地数据库成为对话消息、标题生成输入、中断语义和历史查询的权威来源。
4. AnythingLLM workspace/thread/document binding 具备持久化租约和可重试清理。
5. 初期兼容 SQLite 单机部署，结构上预留 PostgreSQL/Redis/可靠队列的替换点。

## 2. 与 2026-07-03 总计划的关系

本计划继承 `2026-07-03-AnythingLLM低耦合改造总计划.md` 的关键原则：

- 不继续向 `app/services/utils/anythingllm_client.py` 堆叠新跨 API 工作流。
- 业务层不得知道 AnythingLLM 的 API 路径、认证、HTTP 响应结构、`docpath/location/docId` 兼容细节。
- Client、Transport 和 Gateway 不是全局单例；每个任务或 HTTP 流式请求创建独立网络 Session。
- 外部资源生命周期必须可审计、可补偿，不能依赖进程内临时变量作为唯一事实。
- Blueprint 不承担 AnythingLLM 编排；业务通过 Port 表达意图。

本计划属于总计划阶段 10 的文件对话迁移细化方案。若本文与 2026-07-05 的新增接口短期计划冲突，以本文为长期实施基线；2026-07-05 可作为历史短期方案参考。

## 3. 当前结构问题

### 3.1 职责混杂

`app/services/llm_service/chat_service.py` 同时承担：

- SSE 事件格式化；
- `<think>` 流式过滤；
- 新旧对话判断；
- AnythingLLM workspace/thread 创建；
- 文档引用追加；
- 流式模型调用；
- 历史消息转换；
- 删除远端资源。

后续继续在该文件中添加标题生成、中断、队列和补偿逻辑，会使业务状态、协议输出和供应商编排进一步耦合。

### 3.2 Blueprint 承担过多业务和集成职责

`app/blueprints/llm.py` 的 `/llm/chat*` 路由直接：

- 查询 `kb_service` 校验文件；
- 查询原始文件名；
- 实例化 `AnythingLLMClient`；
- 传入具体 client 到业务函数；
- 手写 SSE Response。

这使接口层无法在不改路由的情况下切换 Gateway、队列执行器或消息持久化策略。

### 3.3 数据模型不足

当前 `ChatDatabaseService` 主要只有 `chats` 表：

- `chat_id`
- `file_original_names`
- `turn_timestamps`
- `workspace_slug`
- `thread_slug`
- `created_at`
- `updated_at`

它无法表达：

- 每次请求的 run 状态；
- 同一 `chatId` 活跃流互斥；
- 中断标记；
- user/assistant 消息本地权威历史；
- 被中断的半截 assistant 回答不入库；
- 标题生成输入；
- workspace/thread/document binding 的清理补偿；
- 多实例 owner/heartbeat。

### 3.4 跨进程和多实例不成立

当前 `threading.Lock()` 和未来如果采用进程内 abort registry，都只能在单进程内生效。多实例部署时：

- 第二个实例看不到第一个实例的活跃 SSE；
- `/llm/chat/abort` 可能打到非流式执行实例；
- SQLite 文件锁不能作为高并发分布式协调机制；
- 进程崩溃后没有可恢复的 running run 和资源租约。

### 3.5 历史依赖供应商状态

`/llm/chat/history` 当前从 AnythingLLM Thread 读取历史，再用本地 `file_original_names` 对齐用户轮次。问题：

- AnythingLLM 历史格式变更会影响接口输出；
- 中断后是否保存半截回答由供应商实现决定；
- `/llm/chat/title` 如果依赖供应商历史，会把标题生成建立在不稳定输入上；
- 本地无法准确判断一轮消息是否成功提交。

## 5. 目标数据模型

短期仍使用 `DOCSENSE_CHAT_DB` 指向的 SQLite 数据库，新增表必须 `CREATE TABLE IF NOT EXISTS`，不删除旧 `chats` 表。

### 5.1 `chat_sessions`

| 字段 | 说明 |
| --- | --- |
| `chat_id TEXT PRIMARY KEY` | 甲方传入的对话 ID |
| `workspace_ref TEXT NOT NULL DEFAULT ''` | 供应商无关工作区引用；迁移期可保存 AnythingLLM slug |
| `thread_ref TEXT NOT NULL DEFAULT ''` | 供应商无关会话引用；迁移期可保存 AnythingLLM thread slug |
| `status TEXT NOT NULL` | `active/deleting/deleted/error` |
| `created_at TEXT NOT NULL` | 创建时间 |
| `updated_at TEXT NOT NULL` | 更新时间 |
| `metadata_json TEXT NOT NULL DEFAULT '{}'` | 预留扩展 |

### 5.2 `chat_documents`

| 字段 | 说明 |
| --- | --- |
| `chat_id TEXT NOT NULL` | 对话 ID |
| `file_name TEXT NOT NULL` | 解析接口业务文件名 |
| `original_name TEXT NOT NULL DEFAULT ''` | 文件原名 |
| `document_ref TEXT NOT NULL DEFAULT ''` | 供应商无关文档引用 |
| `external_location TEXT NOT NULL DEFAULT ''` | 供应商外部位置，仅适配层解释 |
| `added_by_run_id TEXT NOT NULL DEFAULT ''` | 首次加入的 run |
| `created_at TEXT NOT NULL` | 加入时间 |

唯一约束：`UNIQUE(chat_id, file_name)`。

### 5.3 `chat_runs`

| 字段 | 说明 |
| --- | --- |
| `run_id TEXT PRIMARY KEY` | 每次 `/llm/chat` 请求的执行 ID |
| `chat_id TEXT NOT NULL` | 对话 ID |
| `request_id TEXT NOT NULL DEFAULT ''` | 幂等键，初期可为空 |
| `status TEXT NOT NULL` | `accepted/running/succeeded/failed/aborted` |
| `abort_requested INTEGER NOT NULL DEFAULT 0` | 中断标记 |
| `owner_instance_id TEXT NOT NULL DEFAULT ''` | 多实例 owner |
| `heartbeat_at TEXT` | 多实例心跳 |
| `error_message TEXT NOT NULL DEFAULT ''` | 错误信息 |
| `created_at TEXT NOT NULL` | 创建时间 |
| `started_at TEXT` | 开始时间 |
| `completed_at TEXT` | 完成时间 |
| `updated_at TEXT NOT NULL` | 更新时间 |

SQLite 阶段可通过事务内查询和更新保证同一 `chat_id` 只有一个 `accepted/running`。PostgreSQL 阶段应替换为部分唯一索引。

### 5.4 `chat_messages`

| 字段 | 说明 |
| --- | --- |
| `message_id TEXT PRIMARY KEY` | 消息 ID |
| `chat_id TEXT NOT NULL` | 对话 ID |
| `run_id TEXT NOT NULL` | 来源 run |
| `role TEXT NOT NULL` | `user/assistant` |
| `content TEXT NOT NULL` | 消息内容 |
| `status TEXT NOT NULL` | `pending/committed/discarded` |
| `sequence_no INTEGER NOT NULL` | 对话内顺序 |
| `created_at TEXT NOT NULL` | 创建时间 |

约束：`UNIQUE(chat_id, sequence_no)`。

### 5.5 `chat_message_files`

| 字段 | 说明 |
| --- | --- |
| `message_id TEXT NOT NULL` | 用户消息 ID |
| `file_name TEXT NOT NULL` | 业务文件名 |
| `original_name TEXT NOT NULL DEFAULT ''` | 文件原名 |

### 5.6 `chat_resource_leases`

| 字段 | 说明 |
| --- | --- |
| `lease_id TEXT PRIMARY KEY` | 租约 ID |
| `chat_id TEXT NOT NULL` | 对话 ID |
| `run_id TEXT NOT NULL DEFAULT ''` | 关联 run |
| `resource_type TEXT NOT NULL` | `workspace/thread/document_binding` |
| `external_ref TEXT NOT NULL DEFAULT ''` | 外部资源引用 |
| `status TEXT NOT NULL` | `planned/active/cleanup_pending/closed/cleanup_failed` |
| `error_message TEXT NOT NULL DEFAULT ''` | 清理错误 |
| `created_at TEXT NOT NULL` | 创建时间 |
| `updated_at TEXT NOT NULL` | 更新时间 |

### 阶段 11：可靠队列预留与事件流模型

**目标：** 为之后接入 Celery/RQ/自研队列或数据库队列做结构准备，但不立即改变对外 SSE 协议。

**新增表：**

| 表 | 说明 |
| --- | --- |
| `chat_run_events` | 保存 run 产生的 `chatInfo/textChunk/done/error/aborted` 领域事件，供 SSE 消费端读取。 |

**新增/修改文件：**

| 文件 | 修改内容 |
| --- | --- |
| `app/services/chat/run_executor.py` | 定义 `ChatRunExecutor`，当前实现同步执行；未来替换为队列 worker。 |
| `app/services/chat/event_repository.py` | 写入和读取 `chat_run_events`。 |
| `app/services/chat/stream_presenter.py` | 支持从内存生成器或 `chat_run_events` 消费事件。 |
| `tests/test_chat_run_executor.py` | 覆盖同步执行器和事件落库。 |

**设计要求：**

- 不在本阶段强行改 `/llm/chat` 为异步任务接口。
- SSE 可以仍由请求线程执行模型流，但事件结构要能被持久化。
- 未来队列化时，HTTP SSE 只消费 `chat_run_events`，worker 负责模型调用。

**验收目标：**

- 领域事件可以持久化并重放。
- 不改变现有外部协议。

### 阶段 12：多实例部署准备

**目标：** 抽象数据库锁、实例 owner 和 abort 通知，为 PostgreSQL/Redis 替换做准备。

**新增/修改文件：**

| 文件 | 修改内容 |
| --- | --- |
| `app/services/chat/lock_service.py` | 抽象 `ChatRunLockBackend`，SQLite 实现和 PostgreSQL 目标实现分离。 |
| `app/services/chat/abort_service.py` | 抽象 `AbortNotifier`，SQLite polling 和 Redis pub/sub 目标实现分离。 |
| `app/services/core/config.py` | 增加实例 ID、chat lock backend、abort notify backend 配置。 |
| `README.md` | 记录单机 SQLite 与多实例目标部署差异。 |
| `tests/test_chat_lock_backend.py` | Mock/SQLite 后端测试，不依赖 Redis/PostgreSQL。 |

**设计要求：**

- `owner_instance_id` 和 `heartbeat_at` 进入 run 状态更新。
- 实例崩溃后应能识别 stale run，后续可人工或巡检释放。
- 不把 Redis/PostgreSQL 具体 API 写入业务服务。

**验收目标：**

- SQLite 单机行为不回退。
- 业务服务只依赖 lock/notifier 抽象。
- 后续替换 PostgreSQL/Redis 不需要改 Blueprint 和 command service 主流程。

## 9. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 改动范围过大导致对外协议回归 | 每阶段只改一层，阶段 0 先冻结接口测试 |
| 新旧 `chats` 表兼容混乱 | 旧表只读兼容，新表作为新请求权威来源；迁移期日志明确标记 fallback |
| SQLite 高并发能力不足 | Repository/Lock 抽象先行，最终可替换 PostgreSQL |
| abort 在多实例下失效 | 数据库 run 为事实来源，Redis/pubsub 仅作通知优化 |
| AnythingLLM 流关闭后仍保存半截回答 | 本地历史以 committed 消息为准；不依赖上游历史判断中断语义 |
| 删除远端资源失败造成孤儿资源 | 资源租约持久化，删除失败进入 `cleanup_failed`，支持巡检重试 |
| 标题生成污染主对话 | 标题必须走独立临时会话或非历史调用，禁止使用主 Thread |
| 继续扩大 legacy Facade | 阶段 2 后新增对话能力只能进入 Chat Gateway，不再新增 `AnythingLLMClient` 方法 |
