# 文件对话接口引用文件细粒度展示与大模型思考过程过滤优化

本次更新主要针对文件对话接口（`/llm/chat` 及 `/llm/chat/history`）的健壮性、引用文件展示粒度以及大模型输出清理进行了深度重构与优化。

## 1. 背景与需求

随着前端页面交互体验要求的提升，针对原有对话系统暴露出以下几点不足：
1. **获取对话历史缺乏容错**：当传入不存在的 `chatId` 时，原接口直接报错 HTTP 404，不利于前端统一按照“开启新对话”的空状态进行处理。
2. **新对话强制引用文件**：原有逻辑规定开启新对话时 `fileNames` 必须非空，现业务需求支持无文件情况下的自由对话。
3. **全局引用文件缺乏关联性**：历史记录中 `fileNames` 是作为外层全局数组返回的，前端无法分辨用户在第几次交流中引用了哪几个文件。
4. **模型思考过程外泄**：集成的深度思考模型（如 DeepSeek R1）会输出带有 `<think>...</think>` 标签的内部推理过程，这些内容会在实时流式输出和历史记录中展示，影响终端用户的纯净体验。

## 2. 核心实现内容

### 2.1 异常响应状态优化

- **代码位置**：`app/blueprints/llm.py`
- 将 `/llm/chat/history` 中对于 `ChatNotFoundError` 异常的处理由原先的 HTTP 404 `{"error": "对话不存在"}` 修改为 HTTP 200，并正常返回 `{"chatId": chat_id, "messages": []}` 的空状态骨架。

### 2.2 新对话校验放宽

- **代码位置**：`app/blueprints/llm.py`
- 移除了新对话判定逻辑中 `existing_chat is None and not file_names` 导致的 HTTP 400 报错。现在不论是新对话还是继续对话，即使 `fileNames` 为空数组也均被放行。

### 2.3 数据库结构与粒度改造

为了实现引用文件追踪到每条具体的“用户发言”上，对底层的对话数据库结构进行了升级：
- **代码位置**：`app/services/core/database.py`
- **原设计**：`ChatDatabaseService` 中 `file_names` 为一维数组 `List[str]`。
- **新设计**：变更为二维数组 `List[List[str]]`。
  - `create_chat`：首轮对话文件直接存为 `[file_names]`。
  - `append_file_names`：后续回合直接执行 `existing.append(new_file_names)`，不再做数组扁平化和合并，以此准确记录用户的每一轮回合传入了什么。

### 2.4 对话业务逻辑重构

- **代码位置**：`app/services/llm_service/chat_service.py`
- **增量工作区解析**：由于底层存储变成了二维数组，`handle_chat_stream` 在判断是否需要推送文档到 AnythingLLM 时，会自动对已有的 `file_names` 进行展平与去重比对，但不影响增量存入数据库。
- **历史记录拆包**：`get_chat_history` 移除了最外层用于表示汇总的 `fileNames`，在遍历大模型返回的 `raw_history` 遇到 `role == "user"` 时，按次序取出对应的批次文件数组赋给消息体的 `fileNames` 字段。

### 2.5 实时流式传输与历史记录的 `<think>` 标签过滤

为了彻底隐藏大模型内部的推理输出，我们在流式传输和记录查询两端实施了双重过滤：
- **代码位置**：`app/services/llm_service/chat_service.py`
- **历史查询静态过滤**：在 `get_chat_history` 中利用正则表达式 `re.sub(r"<think>[\s\S]*?(?:</think>|$)", "", content).strip()`，剔除被保存的 `assistant` 回复中的 `<think>` 及包含内容。
- **SSE 流式实时过滤**：新增 `_filter_think_stream(generator)` 状态机封装流式迭代器。
  - 维护内部 `buffer`，对流式的 `textChunk` 实施缓冲和嗅探。
  - 若探出完整的 `<think>`，立即截断阻断推送并进入静默模式。
  - 若嗅探到部分前缀（例如 `<thi`），会将其暂时滞留（最长保留6个字符），其余正常部分立刻发送前端。
  - 遇到 `</think>` 闭合后重新恢复前端推送。确保实时推流绝不阻塞的同时过滤掉大模型冗余的思维发散过程。

## 3. 文档同步更新

- 更新了 `docs/接口文档/文件对话.md`：
  - 移除了外部顶层的 `fileNames` 说明与示例。
  - 在 `messages` 数组元素结构中为 `user` 角色增加了专属的 `fileNames` 字段说明。
  - 修正了“对话不存在”的 HTTP 200 返回状态范例。
  - 同步移除了已过期的 `fileNames` 判空报错提醒。
