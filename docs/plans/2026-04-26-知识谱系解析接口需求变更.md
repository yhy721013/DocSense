# 知识谱系解析接口抽取逻辑重构与新增按文件提问模式

在 `/llm/weaponry` 接口背后的知识抽取逻辑中，我们彻底重构了底层的检索交互链路，不仅对原有的“按 Chunk 独立询问”机制（模式 1）进行了透明化改造，还增加了一种“按数据来源文件分组聚合询问”的机制（模式 2），并通过环境变量配置项进行切换。

## 1. 背景与需求

原有实现中，知识抽取逻辑直接使用 AnythingLLM 的 `query` 模式对单个字段提问，我们无法精确控制底层的实际引用来源和提示词包裹，导致提取的内容和依据之间存在黑盒现象。

本次迭代的整体需求变更为：
- **重构原有的按 Chunk 提问逻辑（模式 1）**：先显式通过向量数据库检索到相关的片段（Chunk），再强制 LLM 分别只针对每一段 Chunk 进行独立阅读和信息提取。若无信息则过滤，保证每一条数据源都与结论明确对应。
- **新增按文件提问逻辑（模式 2）**：在检索到 Chunk 后，将其**按照源文件名称进行分组**。将属于同一文件的所有 Chunk 合并在一起向大模型提问，确保每份文件最多只得到一种提取回答。
- 对生成的结果进行封装时，模式 1 保持来源为 Chunk 原文；模式 2 需返回数据源的 `source` 为真实文件名，且 `translate` 字段变为对大模型结论 `content` 的翻译。

## 2. 核心实现内容

### 2.1 环境变量与开关

- **代码位置**：[.env](file:///c:/Files/Codes/DocSense/.env) (及业务代码读取)
- 新增 `WEAPONRY_ANALYSE_MODE` 变量：
  - `1`：代表按 Chunk 单独提问的模式。
  - `2`：代表按文件聚合提问模式。

### 2.2 提问 Prompt 适配

- **代码位置**：[prompts.py](file:///c:/Files/Codes/DocSense/app/services/core/prompts.py)
- **模式 1 专用 Prompt**：新增了 `build_chunk_based_field_prompt`。直接将单个 Chunk 的纯文本原样包入 Prompt 中，强制要求大模型“必须且只能基于以下提供的文本片段进行回答”。
- **模式 2 专用 Prompt**：新增了 `build_multi_chunk_based_field_prompt`。将同一份文件下的多个文本片段按“第1段Chunk是……”“第2段Chunk是……”顺序进行排列，明确告知 LLM “存在多个相关的Chunk”，要求其进行综合阅读和信息提取。

### 2.3 模式 1：按 Chunk 分别抽取的重构逻辑

- **代码位置**：[weaponry_service.py](file:///c:/Files/Codes/DocSense/app/services/llm_service/weaponry_service.py)
- 在 `_query_input_field()` 中彻底改变了原有调用流向：
  1. **显式向量检索**：先使用最初的字段描述直接执行 `client.vector_search`，显式获取所有相关的文档片段（并按相似度降序）。
  2. **循环独立提问**：遍历每个 Chunk，结合刚新增的专属 Prompt，使用 `chat` 模式逐个向大模型提问。
  3. **空结果过滤**：只要大模型判定该片段不含目标信息并返回“未找到”，立刻过滤丢弃该 Chunk。
  4. **采纳高信度结果**：提取成功的 Chunk 及回答会加入 `analyseDataSource`；外层的 `analyseData`（该字段的最终展示结果）则直接采纳第一个匹配成功的最佳回答。

### 2.4 模式 2：按文件聚合与抽取逻辑

- `_query_input_field()` 在获取 `vs_results` 后，若模式开关为 `2`：
  - **文件名提取与分组**：主动提取 `chunk.get("metadata", {}).get("title")` 或解析文本中的 `sourceDocument` 标签。若无有效文件名则直接抛出 `ValueError` 报错，中断非法调用。
  - **排序算法**：累积统计同一文件的最高 Chunk 得分，以此得分为依据将各文件进行降序排序。
  - **提问与组合**：遍历排序后的文件，向 LLM 发起合并多 Chunk 后的专属 Prompt。若大模型提取出有效信息，则组装 `mapped_source`。
  - **特殊字段映射**：修改了原有的数据源组合形式，将 `source` 强制指定为提取出的 `file_name`，将 `translate` 由此前的“翻译原文”改为“直接翻译大模型回答的结论（`_translate_if_needed(text_response)`）”。
  - 最终的外层 `analyseData` 同模式 1，采用最高置信度文件的首次成功提取结果。
