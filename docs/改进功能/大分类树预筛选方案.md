# 大分类树预筛选改进方案

## 1. 问题背景

文件解析接口 (`POST /llm/analysis`) 的分类流程依赖调用方通过请求参数 `architectureList` 动态传入分类树。当分类树较小时（如默认兜底的 11 个节点），本地 LLM 能够准确从中选择叶子节点完成分类。

但当调用方传入**大规模分类树（100+ 节点、多层级）**时，本地小模型（如 4B 参数级别）受限于上下文窗口和推理能力，经常出现以下问题：

- 无法准确区分候选节点，分类结果随机漂移
- Prompt 中注入过多候选导致输出格式不稳定
- 频繁回退到 `ARCHITECTURE_FALLBACK_ID = 1`，分类失去意义

## 2. 解决方案：按分类维度的传统搜索 + LLM 精选联合策略

采用**两阶段混合分类**架构：

```
阶段 1：按分类维度的传统文本检索（粗筛）
  ├── 输入：文档内容 + 完整分类树 + 分类维度配置
  ├── 算法：按根分类分组 → Token 重叠度打分 + 名称精确匹配加权
  └── 输出：各分类维度的 Top-K 候选叶子节点 + 完整祖先链

阶段 2：LLM 精选（原有流程）
  ├── 输入：文档内容 + 缩小后的候选列表
  └── 输出：最终 architectureId
```

**核心设计原则：最小侵入式改进，当前纯 LLM 方案作为天然降级策略。**

def prune_architecture_list(

## 4. 算法详情

### 4.1 分词策略

```
CJK 字符（中文/日文/韩文） → 逐字拆分（unigram）
Latin/数字序列            → 整词拆分（长度 ≥ 2）
```

分词前统一做 NFKC 归一化 + 小写折叠，消除大小写和全半角差异。

### 4.2 节点打分

每个分类节点的特征文本由 `name`、`remark`、`pathName` 三个字段拼接而成。

**打分公式**：

```
score = overlap(node_tokens, doc_tokens) / len(node_tokens)
```

**额外加权**：当节点名称（≥ 2 字符）在文档文本中原样出现时，额外 +2.0 分。

### 4.3 按分类维度的候选选择策略

1. 识别所有**叶子节点**（没有被其他节点引用为 `parentId` 的节点）
2. 通过 `_find_root_id()` 将每个叶子节点**追溯到其根祖先**，按根分类分组
3. 对每个根分类，查询 `category_config` 中该分类的配置：
   - **无配置**（不在字典中或值为 `None`）→ 该分类的所有叶子节点**全部保留**，不做裁剪
   - **叶子数 ≤ `prune_threshold`** → 该分类的所有叶子节点全部保留
   - **叶子数 > `prune_threshold`** → 按分数降序排列，仅保留 **Top-K** 个叶子节点
4. 为每个选中的叶子节点**保留完整祖先链**（沿 `parentId` 向上追溯 + `path` 字段中的所有 ID）
5. **始终保留全部根节点**（`parentId = None`），作为结构上下文和潜在回退选项
6. 最终结果保持原始列表顺序

### 4.4 分类维度配置

`DEFAULT_CATEGORY_CONFIG` 以根分类名称为 key，每个分类独立配置阈值和保留数：

```python
DEFAULT_CATEGORY_CONFIG = {
    "军事基地": {"prune_threshold": 4, "top_k": 5},
    "体系运用": {"prune_threshold": 4, "top_k": 5},
    "装备型号": {"prune_threshold": 4, "top_k": 5},
    "作战环境": {"prune_threshold": 4, "top_k": 5},
    "作战指挥": {"prune_threshold": 4, "top_k": 5},
    "数据标准": {"prune_threshold": 4, "top_k": 5},
}
```

| 字段 | 说明 |
|---|---|
| `prune_threshold` | 该分类的叶子节点数 ≤ 此值时跳过裁剪，保留全部叶子 |
| `top_k` | 触发裁剪时，该分类保留的最大高分叶子节点数 |

**其他常量**：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `MIN_DOCUMENT_TOKENS` | 2 | 文档最少需要的有效 Token 数，否则跳过 |

## 5. 降级策略

以下任一条件满足时，预筛选器**不生效**，完全走原有纯 LLM 流程：

| 场景 | 处理方式 |
|---|---|
| 所有分类的叶子数均 ≤ 各自的 `prune_threshold` | 直接跳过，无需预筛选 |
| 分类名称不在 `category_config` 中 | 该分类不裁剪，全部保留 |
| 文档有效 Token < 2 | 跳过（文本信息不足以做检索） |
| 预筛选结果 < 3 节点 | 返回原列表（避免过度裁剪） |
| 预筛选内部异常 | 捕获异常，返回原列表 |
| 无可识别的叶子节点 | 返回原列表 |

## 6. 执行流程

```
run_file_analysis_task()
│
├─ 1. deep copy params（隔离原始请求）
├─ 2. 下载文件
├─ 3. _apply_architecture_prefilter(params, downloaded_path, original_name)
│     │
│     ├─ architectureList 为空？ → 跳过
│     │
│     ├─ 读取文档开头 ~2000 字符
│     ├─ 拼接搜索文本 = originalFileName + fileName + 文档开头
│     │
│     └─ prune_architecture_list(完整列表, 搜索文本)
│           │
│           ├─ 分词 + 打分
│           ├─ 按根分类分组叶子节点
│           ├─ 逐分类判断：
│           │     ├─ 无配置 → 保留全部叶子
│           │     ├─ 叶子数 ≤ threshold → 保留全部叶子
│           │     └─ 叶子数 > threshold → 选 Top-K 叶子 + 祖先链
│           ├─ 始终保留全部根节点
│           └─ 返回缩小后的候选列表
│
│     params["architectureList"] = 缩小后的列表
│
├─ 4. build_file_analysis_prompt(params)  ← 仅包含缩小后的候选
├─ 5. LLM 精选分类（原有流程）
├─ 6. map_analysis_result()（原有流程）
└─ 7. 回调 + 存储（原有流程）
```

## 7. 效果示例

假设调用方传入 120 个分类节点（含 4 级分类，6 个根维度），文档是关于"DDG-1000 朱姆沃尔特级驱逐舰基本情况"的：

**预筛选前**：LLM 面对 120 个候选，难以准确选择

**按分类维度预筛选后**（假设"装备型号"下有 30 个叶子节点，超过阈值 4）：
- "军事基地"分类：叶子数 3 ≤ 4，不裁剪，全部保留
- "体系运用"分类：叶子数 2 ≤ 4，不裁剪，全部保留
- "装备型号"分类：叶子数 30 > 4，**触发裁剪**，保留 Top-5 高分叶子：
  - "水面装备" 及其子分类中匹配"驱逐舰"、"水面舰艇"等关键词的节点
  - "基本情况" 子分类因名称在文档中原样出现获得 +2.0 加权
- "作战环境"分类：叶子数 4 ≤ 4，不裁剪
- "作战指挥"分类：叶子数 3 ≤ 4，不裁剪
- "数据标准"分类：叶子数 2 ≤ 4，不裁剪
- 6 个根节点始终保留

**日志输出**：
```
Architecture pre-filter: 120 → 18 nodes (pruned categories: 装备型号)
```
