## 2. 本轮实际改动

### 2.1 永久关闭门禁

新增 `tests/test_weaponry_stage1d7.py`，以 AST/源码和显式配置字典长期检查：

1. 除遗留文件自身外，`app/**/*.py` 与 `run.py` 禁止导入
   `app.services.llm_service.weaponry_service`；
2. `llm_weaponry()` 函数体禁止 `threading/Thread`、旧 `AnythingLLMClient`、
   `run_weaponry_task` 或 analysis Worker，只允许 Parser、Document Scope、Submit、Presenter；
3. `.env.example` 和 `docker/.env.docker` 禁止出现活动的 `WEAPONRY_ANALYSE_MODE` 赋值，根 README
   和目录 runner 不得重新建议以模式 2 启动；
4. 遗留值 `1` 和其他非法值在配置装配、任何外部副作用前拒绝；值 `2` 仅作启动兼容，配置对象
   不存在可参与算法分支的 `analyse_mode`；
5. Weaponry Domain/Application 禁止依赖术语 workspace、目录、环境变量或具体 Terms Adapter；
6. Application 的字段链必须先构造 Retrieval Query、调用 Target Retrieval，再调用纯
   `select_evidence`；Extraction 函数禁止反向检索；
7. Provided-Evidence Adapter 禁止 `vector_search/update_embeddings/search_target` 或旧
   `send_prompt_to_thread`，模型调用固定 `document_ids=()`；
8. 只有 `test_weaponry_service.py` 可以直接导入/调用遗留 `run_weaponry_task`。

上述测试只做静态读取或使用显式内存配置，不构造生产容器、启动线程或访问网络。

### 2.2 清理活跃模式选择说明

  对值 `2` 的兼容不会改变固定策略，后续 1G 删除遗留兼容时再清理本地配置。

## 3. I01～I07 关闭证据

| 内部门禁 | 关闭证据 |
| --- | --- |
| I01 文档范围 | 受理时冻结不可变 Document Scope；Worker 只按 TaskId 解码 Schema v2，不按业务键重选同名文件 |
| I02 Query/Prompt 分离 | Retrieval Port 只接受 `RetrievalQuery`；Extraction Port 只接受带 Selected Evidence 的 `ExtractionPrompt`，反向类型在构造时拒绝 |
| I03 Candidate Selection | `WeaponryFieldExecutor._retrieve_and_select()` 是 Candidate 进入后续链路的唯一 Application 路径；score/rank、profile、来源、正文质量和去重均在纯 `select_evidence` 完成 |
| I04 来源隔离 | 每个来源 attempt 使用新空 workspace/thread，`document_ids=()`，供应商返回任意 RAG source 即整次拒绝；不存在共享父 Thread 回退 |
| I05 Evidence/rows 一致 | `EvidenceExtractionRequest` 构造时逐项校验 evidence ID、完整正文、document_key 与 Prompt rows 同序；公开 INPUT/TABLE rows 直接来自同一 Selected Evidence tuple |
| I06 外部副作用 | Audit reserve 与 Creation Intent 先于外部调用；创建结果未知只允许唯一查回/隔离，Callback/资源使用 lease/fencing，禁止盲目重放 |
| I07 任务隔离 | 同业务键原子 1 accepted/49 conflict；不同键输入、workspace/thread、审计、Progress、终态、Callback 和资源按 TaskId 隔离；重型执行由共享 limiter 限制 |

动态测试同时覆盖合法 score、合法 rank-only、score/rank 混合、非法/NaN/Infinity 分数、rank
缺失或冲突、profile/指纹不匹配、正文质量拒绝、重复 Candidate、不同文档相同正文和零 Selected
Evidence。协议损坏或全部拒绝时模型调用次数为零，不会将非法分数伪装为缺失或转为零。

## 7. 真实供应商与生产 readiness

本轮只执行只读配置/TCP 诊断：

- `ANYTHINGLLM_BASE_URL=http://localhost:3001/api/v1`；
- API Key 已配置，但 `localhost:3001` TCP 不可达；
- provider、embedding、documentProcessing、extractionModel 四类生产指纹均未配置；
- production attestation 路径未配置，也不存在可校验证明。

没有生成或伪造证明。`ApplicationServices.readiness_snapshot()` 在该状态下必须返回
`production_gate_ready=false` 和总体 `ready=false`。服务可用后仍须使用隔离临时资源验证四项
事实、清理所有临时资源并生成与当前 profile/指纹精确匹配的证明；不得修改现有 workspace/文档。
