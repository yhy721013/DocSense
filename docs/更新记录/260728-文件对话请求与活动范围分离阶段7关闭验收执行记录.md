# 文件对话请求与活动范围分离阶段 7 关闭验收执行记录

## 1. 最终实现

`POST /llm/chat` 已形成以下稳定状态机：

1. 新会话空 `fileNames`：冻结受理时刻全量已解析文件，创建
   `automatic_initial` Scope Revision；
2. 任意一轮非空 `fileNames`：整体替换 Active Scope，创建 `explicit`
   Scope Revision；
3. 后续空 `fileNames`：复用当前 Scope Head，使用 `active_scope_reuse`，
   不创建重复 Revision；
4. 后续知识库新增文件不自动进入既有会话范围；
5. Accepted 的显式范围即使随后执行失败，也不会回退 Head；
6. Workspace bindings 可以累计，但每轮模型只查询 Effective Scope；
7. `/llm/chat/history` 的用户 `files` 只展示该轮 Requested Scope，空请求固定为
   `[]`。

Scope Revision/Head、run input 和 pending user message 在同一 SQLite
`BEGIN IMMEDIATE` 事务中提交；Worker 只凭 `run_id` 从持久化事实恢复 Requested 和
Effective 两套范围。
