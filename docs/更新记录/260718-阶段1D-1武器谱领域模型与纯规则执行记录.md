# 阶段 1D-1 武器谱领域模型与纯规则执行记录

## 1. 执行结论

阶段 1D-1 已于 2026-07-18 完成并通过退出门禁。本波次建立 weaponry 四层目录，落地不可变
领域 DTO、专用 Retrieval Query、Candidate/Selected Evidence/Extraction Prompt 类型边界、来源
规则、Evidence 完整正文保留、INPUT/TABLE Prompt、TABLE 解析与合并、Callback 投影，并删除已经确认
废弃的模式 1 执行链。

本结论只关闭 1D-1 纯领域波次：

- `/llm/weaponry` 公开路由仍使用遗留执行链，没有切换到新 Application；
- 没有增删或重命名请求、响应、Callback、Progress 参数；
- 接口文档只把已批准的“模式 1 将删除”更新为“已在 1D-1 删除”；
- 没有把 1D-0R 的 evaluation-only profile、测试阈值或临时校准结果接入生产；
- 没有运行 `run.py`，没有连接模型、甲方 Callback、MySQL、RabbitMQ、Redis 或 MinIO；
- 没有数据 Schema 或历史数据迁移。

1D-0 的生产检索质量退出门禁仍未关闭。生产入库接线、可追溯原始来源、代表性多文档语料、
Candidate 级标注和版本化独立 relevance signal 完成前，1D-3B 与 1D-6 继续阻塞。

每层均包含 `__init__.py` 和 README。永久 AST 门禁已扩展为：

1. `domain` 只能导入批准的标准库和本模块 `domain`；
2. `ports` 只能依赖本模块 `domain/ports` 和批准的标准库；
3. `application` 只能依赖本模块 `domain/ports/application` 和批准的标准库；
4. weaponry 四层目录缺少包文件或职责文档时测试直接失败；
5. 静态检查不 import 生产模块，不触发容器、数据库、网络或后台线程。

## 3. 不可变领域模型

### 3.1 深冻结 JSON 模板

`FrozenJsonObject` 和 `FrozenJsonArray` 在边界处递归复制并冻结公开模板：

- 保留未知扩展键及原始插入顺序；
- 拒绝非字符串对象键、重复键、可变嵌套引用和非 JSON 类型；
- 拒绝 `NaN`、`Infinity` 和 `-Infinity`；
- 每次公开投影都生成全新的 `dict/list`，调用方修改投影不会污染 execution 快照。

### 3.2 身份、输入与输出 DTO

新增以下不可变对象：

- `WeaponryExecutionIdentity`：冻结内部 TaskId、64 位正整数 `architectureId` 和规范业务键；
- `WeaponryDocumentSnapshot`：冻结文档顺序、`document_key`、哈希名、甲方原名、实际入库名、
  来源分类和外部文档引用；
- `WeaponryFieldSpecification` / `WeaponryColumnSpecification`：冻结 INPUT/TABLE 字段语义、
  `fieldDescription`、列顺序和未知模板键；
- `WeaponryAnalyseDataSource`、`WeaponryFieldResult`、`WeaponryTableCellResult`：冻结按来源文件
  的结果、实际 Evidence rows 和 TABLE 二维结果；
- `WeaponryResult` / `WeaponryCallbackPayload`：从领域终态显式投影既有成功/失败 Callback。

字段映射严格拒绝缺失/小写/未知 `fieldType`、空 TABLE 行、非 INPUT 列类型、数字字段名和含混
键值容器。该规则与已批准目标契约一致；HTTP 400 精确错误文本仍由 1D-2 Parser 负责映射。

## 4. Retrieval、Evidence 与 Prompt 类型隔离

### 4.1 专用 Retrieval Query

`RetrievalQuery` 只携带字段检索语义：

- INPUT：字段名和 `fieldDescription`；
- TABLE：表名、表说明、列名和每列说明；
- 可选扩展词必须显式进入版本化策略。

回答格式、JSON 示例、“未找到”、多值分隔和模型角色指令不再发送给向量检索。

### 4.2 Evidence Selection

领域层区分以下不可互换对象：

- `EvidenceCandidate`：供应商召回候选、文档身份、rank、原始分数输入和 profile；
- `EvidenceSelectionPolicy`：随 execution 冻结的 provider/embedding/reranker/query 指纹、额外
  信号策略、候选批次和同文档精确去重策略，不包含 Evidence 数量或字符配额；
- `SelectedEvidence`：通过来源、分数、正文质量和额外相关性信号门禁的有序证据；
- `EvidenceSelectionResult`：完整 Selected Evidence、拒绝原因和去重事实。

`select_evidence` 是无 I/O 纯函数，固定执行来源/profile/分数校验、质量门禁、锚点或独立
reranker 信号、稳定排序和同文档精确全文去重。重复 Candidate ID 会被拒绝；低相关、非法分数
和 profile/指纹不匹配均不能为了填满 TopN 被补回；所有通过门禁的正文完整保留。

### 4.3 Extraction Prompt

`ExtractionPrompt` 只能接收同一 `document_key` 的 `SelectedEvidence`：

- `EvidenceCandidate` 不能直接构造 Prompt；
- Evidence ID、`rows`、文本和顺序逐项冻结；
- INPUT/TABLE `fieldDescription` 均进入最终 Prompt；
- `AuxiliaryGuidance` 是通用可选语境，Domain 不知道术语目录、workspace、环境变量或供应商；
- 辅助语境被明确声明为非事实来源，不进入公开 `rows`。

遗留模式 2 尚未经过生产 Selection，因此兼容链只把既有已选行标记为
`legacy-mode2-unprofiled` 后交给新 Prompt。该标识不能冒充 production profile。

## 5. 来源与 TABLE 纯规则

### 5.1 来源规则

来源规范化、历史 AnythingLLM 路径别名、甲方原名/哈希名映射和术语文件识别已迁入纯 Domain。
一个规范别名若指向多个文档会明确失败，不再依赖字典覆盖顺序猜测来源。

Evidence rows 只移除空白项并去除正文首尾空白，不按单条、总量或单文档行数/字符数截断。
公开 `rows` 与实际进入模型的 Selected Evidence 完整文本和顺序逐项一致。

### 5.2 TABLE 规则

TABLE 已迁移以下纯规则：

1. 清理 `<think>` 和 JSON Markdown 包装；
2. 解析数组、单行对象及常见列表包装，显式空列表不会被误当作根数据行；
3. 单元格值规范化，空值、未知值和非有限数字收敛为空字符串；
4. 按显式 row key、名称/型号/编号等列和稳定后备序号确定行身份；
5. 同一行首个非空单元格值获胜，逐列来源按输入顺序去重；
6. 保留列模板未知键，组装既有二维 `tableFieldList` Callback 形状；
7. 拒绝重复列、无序映射和 `values/sources` 列集合不一致，避免 `dict` 静默覆盖。

已删除：

迁移期策略固定为：

`run_weaponry_task` 在数据库写入、AnythingLLM 检索和模型调用前检查一次；字段兼容入口再次做
防御性检查。测试证明显式模式 1 时 Client 的检索和模型方法调用次数均为零。该迁移期变量已在
1D-5 新组合根中收口为固定 `file_aggregate_v1` 基础设施策略；生产路由切换仍属于 1D-6。

## 7. 审查中补强的问题

完整审查除主计划交付外又修复以下内部风险：

1. 直接构造 frozen dataclass 时列表仍可能被外部修改：现统一复制为 tuple；
2. 数字 `fieldName` 被 `str(...)` 静默转换：现严格拒绝；
3. `source_architecture_id` 未执行 64 位上限：现与 architectureId 上限一致；
4. Evidence 数量/字符上限可能丢失相关性依据：全面审查后已删除四类配额，只过滤空白行；
5. `{"rows":[]}` 可能回退解析根对象：现区分“找到空容器”和“没有容器”；
6. 同一来源别名映射多个目标时取首值：现明确报领域错误；
7. 重复 Candidate ID 可能在 Prompt 阶段才暴露：现于 Selection 稳定拒绝；
8. TABLE 中间对象的重复列/无序容器可能被 `dict` 覆盖：现构造时即失败。

2026-07-18 后续审查还确认：公开请求中的重复 TABLE 列维持“内部首列获胜、原模板保留”兼容
行为；宽泛“类型”列不再单独作为行合并身份。上述内部结果容器仍拒绝重复列，以防应用层自行
构造含混结果，与公开请求兼容投影的首列折叠并不冲突。

这些改动均位于内部领域边界，没有改变任何公开参数或 Callback 字段。
