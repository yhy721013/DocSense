## 2. 已完成的改造

### 2.1 当前/目标双基线

新增 `tests/contracts/stage1e0_reassign_contracts.json`，将同一接口的两类事实严格拆开：

1. **当前基线**：当前 Flask 路由的 400、500、200 JSON，原始 JSON 值比较、`int(oldArchitectureId)`
   的未包装失败时点、`newArchitectureId` 非严格校验、空 `doc_path` 仅本地更新，以及旧 workspace
   映射缺失时跳过旧删除的兼容行为。
2. **已批准目标**：接口继续同步且保持既有 400/500/200 外壳；远端显式 `false`、目标创建无 slug、
   本地 CAS 0 行和补偿失败均必须失败收敛，绝不能返回虚假 200。内部 Operation、lease、fencing、
   step 与恢复信息禁止进入公开响应。

目标矩阵不调用当前路由来断言尚未实现的结果。它只作为 1E-1～1E-6 的验收输入，因此不会让
“测试绿了”被误读为新 Saga 已经上线。

### 2.2 400、500、200 黄金样例

新增 `tests/test_stage1e0_reassign_contract_assets.py`，使用显式注入的临时 SQLite 容器验证：

- 已在接口文档精确列出的 `businessType`、`params`、`fileName` 与原始新旧 ID 相等的 400 文案；
- 文档不存在、分类不一致的既有 500 JSON；
- 空 `doc_path` 的既有 200 JSON 与“不得发送远端删除/加入”的兼容路径；
- `1` 与 `"1"` 的原始值不相等、旧 ID 不可转换时仍是未包装 500、`newArchitectureId=false` 仍未被
  严格拒绝等历史边界。

测试在 `setUp` 中将 `get_document_record` 默认值明确设为 `None`，避免 `MagicMock` 默认 truthy
返回值把未设置的业务前置条件误带入成功路径。

### 2.3 外部失败不得被 Mock 掩盖

以下三个现状通过显式返回值实证，而非依赖默认 Mock：

| 场景 | 当前遗留路由观测 | 后续 1E 目标 |
| --- | --- | --- |
| 旧 workspace 删除返回 `false` | 仍可能加入目标并提交本地，HTTP 200 | 先探测，禁止目标加入和本地提交；明确失败或 `recovery_required`，HTTP 500 |
| 创建目标 workspace 没有 slug | 跳过目标加入仍提交本地，HTTP 200 | 不得本地提交；恢复旧绑定或进入 `recovery_required`，HTTP 500 |
| 本地条件更新影响 0 行 | 返回值被忽略，HTTP 200 | 强制 `rowcount == 1`；失败后补偿或进入 `recovery_required`，HTTP 500 |

补偿动作自身失败的目标样例同样固定为 HTTP 500 + 内部 `recovery_required`，且禁止盲重试未知
外部写；这些内部状态不属于公开字段。

### 2.4 接口文档与代码观测的边界

执行中发现当前路由在 `oldArchitectureId=null`、`newArchitectureId=null` 时分别输出精确 400 文案，
但权威接口文档仅说明两个字段不能为 `null`，没有逐字列出这两条消息。由于本波次的明确门禁是
**不修改接口文档**，没有将代码观测反向提升为文档契约，也没有补写接口文档。

机器资产对此使用 `code-observed-not-explicitly-listed-in-interface-document` 标记：

- 该标记锁住当前兼容行为，避免 1E 无意改变；
- 只有 `documented-exact` 的文本才要求逐字出现于接口文档；
- 后续若要把这两条字符串写入或改写接口文档，必须先取得接口确认，不能由 1E 自动处理。

### 2.5 D0-09 离线预算

资产包含 `0.25s` 单次 HTTP、`1.0s` 总预算和 `0.2s` 补偿预留的**测试注入值**。测试只验证其
有限、正数和预留关系；它们不代表生产秒数。真实 P95/P99、供应商探测与补偿耗时仍由后续
集成环境校准，未在本波次伪造 production ready 结论。
