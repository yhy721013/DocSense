# 文件分析 RAG 图片占位文本移除执行记录

## 1. 背景与结论

RAG-only Markdown 投影原先在删除图片 Base64 payload 后，会生成包含 alt、媒体类型、SHA-256
和 payload 长度的“内嵌图片已移除”占位文本。这些字段属于安全审计/可观测信息，不属于文档
语义，却会随投影 Artifact 上传 AnythingLLM 并参与切块、向量化和检索。

本次将投影算法升级为 v2：完整的可渲染 Markdown data URI 图片语法只替换为一个 ASCII
空格，不再生成任何图片提示或元数据。单个空格用于防止行内图片前后的文本被直接拼接；源文件
原有换行继续逐字保留。canonical prepared Artifact、全文翻译、Callback 和业务正文不变。

## 2. 已实施改动

1. `_MarkdownProjectionScanner` 不再收集 alt，也不再计算或输出图片媒体类型和内容摘要；删除
   `_placeholder()`、alt/占位符长度常量及对应 Profile 参数。
2. Scanner 仍以固定块消费 data URI、严格验证 Base64 并统计无效/畸形图片；10 MiB 等大图片
   仍不会按整行或整文档载入内存。
3. 每张被移除图片只向目标写入一个 ASCII 空格。新增 `removed_payload_bytes` 任务级汇总日志；
   日志不包含 alt、Base64、正文、业务原名或图片摘要。
4. Processor fingerprint、algorithm version 与逻辑 step 均升级到 v2，Profile 明确冻结
   `remove-image-syntax-with-space-v2` 和 `single-ascii-space-v1`，禁止复用带旧占位文本的 v1
   Processing Record/Artifact。
5. 投影和 Analysis 上传测试改为反向门禁：输出不得包含提示、alt、媒体类型、摘要、payload
   长度或 Base64；同时验证英文相邻 Token 分隔、代码示例、外部图片和 canonical Artifact。

## 3. 接口与数据边界

- `docs/接口文档/` 零修改；未增删请求/响应参数、路由、状态码、Header、Callback、Progress、
  SSE 或 WebSocket 语义。变化只发生在内部 `RAG_PROJECTION` Artifact 内容与 Profile 身份。
- 无数据库 Schema 迁移。v2 Profile/step 会产生新的 step key，不复用 v1 投影 Artifact。
- 已经上传并向量化的历史 AnythingLLM 文档不会自动重建；如需清理，必须另行执行有审计的删除、
  v2 重新投影和重新上传，不能由本次发布静默修改外部资源。
- 当前 Analysis 接受快照尚未冻结具体 RAG 投影 Profile。发布时必须协调重启或先排空在途任务，
  禁止多实例滚动混跑 v1/v2；未来可靠队列/多实例阶段应把 Profile 身份冻结进任务输入并校验。
