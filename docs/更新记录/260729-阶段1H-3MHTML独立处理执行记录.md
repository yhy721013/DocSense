## 1. 领域规则与兼容边界

`domain/mhtml.py` 只接收文件名、头部字节和完整 MHTML 字节，不读取路径、不写文件、不启动浏览器。
规则保持：

- `.mhtml/.mht` 扩展名优先；
- 错误扩展名可由 multipart MIME 头识别；
- charset 不存在时按 UTF-8 容错；
- 普通正文排除 script/style/noscript；
- 检索正文优先 main/article，过滤 nav/footer/reference 等噪声并去重；
- HTML 不可用时使用纯文本候选，空正文严格失败。

原 Utils 文件只负责读取旧路径、写旧目标路径和调用新规则；它不再导入 Translator。

## 2. 浏览器、降级与未知结果

冻结的浏览器 Profile：

```json
{
  "fallbackPolicy": "markdown_on_confirmed_failure_v1",
  "noSandbox": true,
  "unknownOutcomePolicy": "reconcile_then_fallback_v1"
}
```

执行规则：

1. PDF 有效：发布 `normalized/pdf` Artifact；
2. 浏览器不存在、启动失败、非零退出且无 PDF、确认终止后的超时：主步骤记录失败，自动执行独立
   Markdown Profile，发布 `normalized/markdown` Artifact；
3. 超时后进程树终止无法确认：主步骤记录 `outcome_unknown`，不启动 Markdown；
4. 未知状态的 scratch 使用稳定 step key 命名并保留所有权标记，后续恢复器先检查既有副作用；
5. 主流程与降级流程使用不同步骤键和 Profile，但共享 task/source Artifact，Lineage 始终从同一
   source 出发。

默认执行器使用独立进程组：Windows 通过 `taskkill /T /F`，POSIX 通过 process group
SIGTERM/SIGKILL 有界终止。只有确认旧执行失去继续写入能力后，才允许 Markdown 降级。
