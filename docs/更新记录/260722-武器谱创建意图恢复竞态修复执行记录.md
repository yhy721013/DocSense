## 2. 故障链

原实现先读取全部 `pending` 创建意图，再读取远端 workspace 清单，最后直接登记并隔离资源。
这一流程没有区分“进程崩溃遗留意图”和“当前 Worker 正在执行的意图”，也没有在资源变更前重新取得
意图恢复权。因此会出现以下时序：

1. Worker 在发送 `create workspace` 前写入 `pending` 意图；
2. 维护器读取到该意图；
3. Worker 创建 workspace、登记资源并完成或即将完成意图解析；
4. 维护器仍按旧快照执行崩溃恢复，把任务资源改为 `quarantined`；
5. 后续字段调用 `ensure_ready` 时发现资源已不再是 `tracking`，任务失败。

这与现场日志中“创建和登记成功后，维护器立即以
`weaponry_creation_crash_window_reconciled` 隔离同一任务”的顺序一致。

## 3. 修复设计

### 3.1 运行实例归属

生产组合根为一次应用运行生成唯一 `instance_id`。所有新建 `pending` 意图在外部 create 发生前，
随创建事实一并保存 `owner_instance_id`。维护器查询候选时排除当前实例拥有的 `pending`，从入口阻止
同进程维护线程与活跃 Worker 竞争。

进程重启后会生成新标识，因此旧实例遗留的 `pending` 仍可进入恢复流程。当前支持的运行模式仍是
`single_instance`；该实例归属不宣称已经实现多实例 Task Attempt 执行权。

### 3.2 恢复 claim、租约与 fencing

创建意图新增内部状态 `recovering`，恢复器必须先通过 SQLite 短事务和版本 CAS 取得恢复权，才能
读取远端清单或修改资源现场。claim 保存恢复所有者、租约截止时间和单调递增的 fencing token：

- 未过期的恢复租约不能被其他实例抢占；
- 租约过期后允许新实例接管，并递增 fencing token；
- 旧所有者或旧 token 不能提交恢复完成/隔离结果；
- 候选读取后若 Worker 已先完成 `resolve`，claim 会因版本或状态变化失败，恢复器跳过全部资源变更。

恢复器在关键资源写入前再次核对意图版本、所有者和 token。恢复完成仍坚持“先保存资源事实，再终结
创建意图”的顺序，不在数据库事务中执行供应商网络 I/O，也不自动重发 create 或删除不确定资源。

### 3.3 Worker 侧关闭过期路径

检索和 Provided-Evidence 抽取适配器显式拒绝继续处理 `recovering` 意图。正常 Worker 仍只允许处理
自己预留的 `pending`；恢复器一旦合法接管，旧 Worker 不得继续修改资源现场。

创建意图恢复使用已有的有限超时 cleanup client，租约时长复用内部
`cleanup_lease_seconds`。这些均为内部基础设施配置，不新增环境变量或接口字段。

## 4. SQLite 兼容策略

`weaponry_creation_intents` 原位增补以下内部列：

| 列 | 默认值 | 用途 |
| --- | --- | --- |
| `owner_instance_id` | 空字符串 | 标识创建 Worker 或恢复器所属运行实例；空值兼容旧意图 |
| `recovery_fencing_token` | `0` | 恢复接管代次 |
| `recovery_lease_until` | 空字符串 | 带时区的恢复租约截止时间 |

初始化适配器会检测并逐列补齐旧表。旧 `pending` 意图因没有归属实例，会被视为可恢复的历史记录，
保持原有保守查回语义。新增列对旧数据使用默认值，不改变任务输入、结果或回调数据。

若需要回滚代码，应先确认数据库中不存在 `recovering` 状态记录并备份数据库；新增列本身可以保留，
但旧代码无法识别 `recovering` 枚举值。

## 6. 剩余边界

1. 本修复解决当前 `single_instance` 运行模式下的创建意图竞态，并为恢复接管提供局部 fencing；
   它不等价于完整的多实例任务执行权。后续仍需统一 Task Attempt、heartbeat、execution lease、
   checkpoint、Reaper 和数据库级 fencing。
2. 已经发生故障并进入 `quarantined` 的历史任务和资源不会被本次代码自动解除隔离，仍需按现有人工
   对账流程处理。
3. 术语 workspace 的 `vector-search 400` 属于可选术语上下文配置问题，与本次致命竞态无关，未在
   本次修改中处理。
