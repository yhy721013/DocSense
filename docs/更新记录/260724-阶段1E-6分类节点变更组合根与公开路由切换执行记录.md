## 2. 已完成改造

### 2.1 唯一 Application 组合根

1. `app/modules/reassign/composition.py` 新增并启用
   `compose_reassign_application_services()`：以同一 Repository、请求级 Knowledge Factory 和
   `ReassignmentExecutionSettings` 装配 `DocumentReassignmentService` 与
   `RecoverReassignmentOperation`。
2. `ReassignApplicationServices` 只公开前向与恢复两个 Application 用例，不公开 Repository、
   Port Bundle、执行设置或基础设施配置，阻止未来 Dispatcher/Worker 绕过 Application 直接收口
   Operation。
3. `app/container.py` 在启动装配时加载并校验分类节点变更的有限 HTTP/总预算/补偿预留配置，构造
   SQLite Repository、无状态请求级 AnythingLLM Factory 和实例级 lease owner；Container 不保存
   共享 HTTP Session、不启动恢复线程，也不直接调用恢复终态 Repository 入口。

### 2.2 恢复职责拆分

`RecoverReassignmentOperation` 保持唯一的外部 Application 外观和既有 Port/状态机语义，内部增加：

- `ReassignmentRecoveryObserver`：本地/远端观察与观察事实；
- `ReassignmentRecoveryCheckpointReconciler`：步骤事实收敛与补偿决策；
- `ReassignmentRecoveryCompensator`：固定“目标解绑、来源恢复”顺序；
- `ReassignmentRecoveryFinalizer`：终态收口或隔离。

四个协作器只保存不可变回调引用，不保存 Operation、客户端或全局可变状态。实际网络调用仍由已有
外观原子方法在短 UoW 外执行；严格 Fake 与恢复 SQLite 回归继续覆盖补偿顺序、fencing、观测和审计事实。

### 2.3 公开薄路由与契约保持

1. `app/adapters/web/flask/reassign_requests.py` 将遗留入站校验迁移为框架无关 Parser，保留原始 ID
   比较、旧 ID `int(...)` 转换时点、非严格新 ID 和既有 400 文案。
2. `app/presenters/reassign_result.py` 将最小 `ReassignmentResult` 映射为冻结的 200/400/500 响应，
   显式复刻 Flask `jsonify` 的 JSON 字节序列，且不暴露 Operation、lease、fencing、步骤或恢复事实。
3. `app/blueprints/llm.py` 的 `/llm/reassign` 不再构造 `AnythingLLMClient`、执行数据库编排或创建
   线程；参数错误始终优先返回原有 400，只有合法请求才要求 Application 运行链已装配。
4. `tests/test_routes.py` 已从遗留 `AnythingLLMClient`/`DatabaseService` Mock 迁移为强类型
   Application 外观注入，避免测试反向推动生产路由恢复直连基础设施。

## 5. 仍未关闭的生产边界

离线通过不等同于真实 AnythingLLM 故障演练、生产预算校准、供应商侧幂等证明或多实例容量验证。
当前 SQLite lease/fencing 只保护接入同一 Repository 协议的执行者，不能替代供应商侧的外部副作用
串行化。未来可靠队列/Worker 必须复用当前两个 Application 用例和强类型恢复分类，不能把
`operation_not_found`、`takeover_rejected` 或 `recovery_required` 误判为已恢复。
