# 对话历史文件原名（originalName）全链路支持

本次改造聚焦文件对话链路中"文件名"的展示问题：  
`GET /llm/chat/history` 返回的文件列表此前使用哈希后的文件名（如 `bded228dc94440519d87f97cfb6b520b.pdf`），需改为返回文件原始名称（如 `美军2025年度国防战略报告.pdf`）。

## 1. 背景与需求

### 1.1 问题描述

系统中所有文件名均为哈希后的文件名，因调用方上传文件时以哈希值作为文件标识。但对话历史接口面向用户展示时，用户需要看到可读的文件原名而非哈希值。

### 1.2 设计约束

- 文件解析接口 `/llm/analysis` 的 `fileName` 参数（哈希名）不变，新增可选参数 `originalName`
- 文件对话接口 `/llm/chat` 的 `fileNames` 参数仍然传哈希文件名，不改变调用方行为
- 映射关系由后端通过 `documents` 表的 `original_name` 字段维护
- 不需要兼容现有数据库（测试数据，尚未正式上线）

## 2. 接口变更说明

### 2.1 `POST /llm/analysis` — 文件解析接口

`params[]` 新增可选字段 `originalName`（String），传入文件原始名称。不传时回退使用 `fileName`。

### 2.2 `POST /llm/chat` — 文件对话接口

无变更。`fileNames` 参数仍然传哈希文件名。

### 2.3 `GET /llm/chat/history` — 获取对话历史接口

`files[].name` 字段语义变更：从返回哈希文件名改为返回文件原名。

### 2.4 其他接口

`POST /llm/chat/delete`、`POST /llm/generate-report`、`POST /llm/weaponry`、`POST /llm/check-task`、`WS /llm/progress`、`POST /llm/reassign` — 均无变更。

## 3. 核心实现内容

### 3.1 数据库层改造

- **代码位置**：`app/services/core/database.py`

**DatabaseService（`documents` 表）**：
- 建表语句增加 `original_name TEXT NOT NULL DEFAULT ''` 字段
- `save_document_record()` 增加 `original_name` 参数，写入时若为空则自动回退为 `file_name`
- `list_document_records()` 的 SELECT 列表增加 `original_name`
- 新增 `get_original_name(file_name) -> str` 方法：根据哈希文件名查询原名，无记录时回退返回 `file_name` 本身

**ChatDatabaseService（`chats` 表）**：
- `file_names` 列重命名为 `file_original_names`（存储文件原名而非哈希名）
- `create_chat()` 参数从 `file_names` 改为 `file_original_names`
- `get_chat()` / `list_chats()` 返回 key 从 `file_names` 改为 `file_original_names`
- `append_file_names()` 重命名为 `append_file_original_names()`

### 3.2 文件解析服务改造

- **代码位置**：`app/services/llm_service/analysis_service.py`
- `run_file_analysis_task()` 从 `params` 中读取 `originalName`（若无则回退为 `fileName`）
- 在调用 `kb_service.save_document_record()` 时传入 `original_name` 参数

### 3.3 对话服务改造

- **代码位置**：`app/services/llm_service/chat_service.py`
- `handle_chat_stream()` 增加参数 `file_original_names: List[str]`
- 创建/继续对话时将原名列表传入 `chat_db.create_chat()` / `chat_db.append_file_original_names()`
- `get_chat_history()` 从 `chat_record["file_original_names"]` 读取文件原名列表

### 3.4 蓝图层改造

- **代码位置**：`app/blueprints/llm.py`
- `/llm/chat` 路由在调用 `handle_chat_stream` 之前，通过 `kb_service.get_original_name()` 将每个哈希文件名映射为原名
- 映射后的原名列表通过 `file_original_names` 参数传入对话服务

### 3.5 调试预览适配

- **代码位置**：`app/services/utils/chat_debug_preview.py`
- `item["file_names"]` 改为 `item["file_original_names"]`

### 3.6 接口文档同步

- **代码位置**：`docs/接口文档/文件对话.md`
- 对话历史响应的 `files[].name` 字段说明改为"文件原名"
- 响应示例更新为原始文件名

## 4. 数据流总览

```
文件解析：
  POST /llm/analysis
    → params: { fileName: "hash.pdf", originalName: "报告.pdf", ... }
    → analysis_service 解析完成后
    → kb_service.save_document_record("hash.pdf", ..., original_name="报告.pdf")
    → documents 表: { file_name: "hash.pdf", original_name: "报告.pdf", ... }

文件对话：
  POST /llm/chat
    → params: { fileNames: ["hash.pdf"], ... }
    → 蓝图层通过 kb_service.get_original_name("hash.pdf") → "报告.pdf"
    → handle_chat_stream(..., file_original_names=["报告.pdf"])
    → chat_db.create_chat(..., file_original_names=["报告.pdf"])
    → chats 表: { file_original_names: [["报告.pdf"]], ... }

对话历史：
  GET /llm/chat/history?chatId=xxx
    → chat_record["file_original_names"] = [["报告.pdf"]]
    → 返回: [{ role: "user", files: [{ name: "报告.pdf" }], ... }]
```

  - `test_chat_accepts_empty_file_names_for_new_chat`：修复过时用例（与 `5290eef` 功能变更对齐）

## 6. 变更影响总结

1. 文件解析接口新增可选参数 `originalName`，向后兼容（不传时回退为 `fileName`）。
2. 对话历史接口返回的文件名从哈希名切换为原始文件名，前端可直接展示可读的文件名。
3. 对话接口 `fileNames` 参数不变，调用方无需调整对话请求逻辑。
4. 旧数据库需删除后重新初始化（`.runtime/*.sqlite3`），因表结构不兼容。
