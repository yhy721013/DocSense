## 1. 本轮完成范围

### 1.1 1C-0：建立当前与目标双基线

`tests/contracts/stage0_contracts.json` 新增 `reportGenerationBaseline.current/target`，明确
区分“当前代码事实”和“已经批准、但尚未切换的目标”：

| 维度 | 当前事实 | 已批准目标 |
| --- | --- | --- |
| 成功受理 | HTTP 202 + task JSON | HTTP 202 + 零字节响应体 |
| 同一活动 reportId 重复提交 | 覆盖最新可变行，并再启动一个 daemon 线程 | HTTP 409，既有单字段错误体 |
| 执行积压 | 每个受理请求创建一个线程 | 持久化积压 + 常量空间有界唤醒 |
| 任务事实 | 每业务键一行可变投影 | 追加式 execution + latest 投影 |
| 结果写入身份 | business type + business key | expected task ID 条件写 |
| 外部资源 | 任务内创建旧 Client，缺少确定性 close/清理 | 后续任务级 Adapter 和资源生命周期收口 |

双基线的目的不是认可当前缺陷，而是让 1C-3～1C-6 每次改变行为时都有明确迁移坐标，
防止旧行为在重构中被无意改变或目标行为被测试误写成当前事实。

### 1.2 已冻结的兼容行为

- 保留既有六类 HTTP 400 文本；
- `reportId` 继续接受整数或十进制整数字符串，不受 32/64 位机器整数范围限制；后续
  全面审查已按负责人批准补充 128 位十进制数字上限，并继续按整数值规范化；
- Progress 当前值固定为 `0.0 → 0.15 → 0.25 → 0.35 → 1.0`；
- 成功与失败 callback 的字段、状态和消息保持精确等价；
- `None`、空字符串和纯空白 RAG 结果均生成空 `<pre>` HTML，并按既有成功 callback
  处理；只增加内部 `empty_rag_result=true` 日志，不向公开载荷增加字段；
- MHTML 规范化失败继续使用原文件，Word 模板未提取到文本时在 RAG 前进入任务失败；
- MHTML 单元测试使用真实临时文件，并显式验证不依赖可选 PDF 转换器的 Markdown 降级
  路径，消除开发机安装差异造成的假失败。

### 1.3 已固定的当前缺陷

`tests/test_report_contract.py` 使用离线应用容器、AST 和临时 SQLite 证明：

- 当前成功仍返回 JSON，而不是目标零字节响应；
- 活动重复任务会创建新 execution ID、覆盖同业务键投影并启动另一个线程；
- 旧 execution 可以通过仅含业务键的写入修改新 execution 所拥有的最新行；
- 报告路由仍直接创建一个 daemon 线程；
- 旧报告服务创建 `AnythingLLMClient` 后没有显式 close；
- 当前 RAG 流程没有确定性的 workspace/thread/document 清理。

顶层非对象 JSON、混合 `params` 和 `filePathList` 非字符串/空白元素最初只作为待确认差异
记录；负责人随后明确批准严格 HTTP 400 口径，现已从“当前缺陷”转为已实现契约，见 2.6。

## 2. 1C-1 Report Domain/DTO

### 2.1 新模块结构

```text
app/modules/report/
├── README.md
├── __init__.py
└── domain/
    ├── README.md
    ├── __init__.py
    ├── errors.py
    ├── models.py
    └── rules.py
```

该目录当前只包含纯领域对象与规则，不包含 Application、Port、Repository、Dispatcher、
网络 Client 或组合根。它不会读取 Flask request、SQLite、环境变量、文件或系统时间。

### 2.2 不可变领域对象

- `ReportId`：同时保存公开整数和规范化十进制业务键，限制在 128 位十进制数字内，并
  拒绝 bool、不一致键或超限值；
- `ReportSubmission`：冻结受理命令，复制源 URL 容器，保留顺序和重复项；
- `ReportInputSnapshot`：保存后续按 task ID 恢复所需的完整版本化输入；
- `ReportResult`：同时保留 RAG 原始文本和稳定 HTML，并提供空结果质量标记；
- `ReportCallbackPayload`：强制终态、固定消息，并在每次导出时返回独立公开字典。

源 URL 只接受 `list/tuple` 这类有确定顺序的内部容器。`set/dict` 会破坏或歪曲顺序、
重复语义，因此统一抛出稳定领域异常。该内部不变量不等于已经收紧公开 HTTP 参数处理；
Web Adapter 的异常输入语义仍须按接口确认结果实施。

### 2.3 稳定错误分类

已建立参数内部不变量、活动冲突、stale execution、输入、模板、RAG 和 Artifact 等错误。
每类错误都有稳定 `code/stage`，后续 Application、日志和 Adapter 可以分类处理，无需依赖
供应商异常文本。领域错误本身不携带 HTTP 状态码，也不直接决定 callback 结果。

### 2.4 纯规则

- HTML 原样保留/纯文本转义/空内容规范化；
- 成功与失败 callback 的固定消息及精确公开结构；
- 报告执行 Context 和 Conversation 名称；
- 空 RAG 结果的可审计内部表示。

所有规则均无 I/O。架构门禁已经把 `report/domain` 纳入正向导入白名单扫描，禁止 Web、
数据库、队列、网络、日志设施和供应商 Client 进入领域层。

### 2.5 遗留兼容转发

`app/services/llm_service/report_service.py` 暂时保留原调用入口，但 HTML、callback 和名称
构造已经转发到新领域规则。报告执行顺序、Progress、SQLite 写入、线程模型和 callback
发送方式均未切换。兼容测试确认 Context/Conversation 名称、成功/失败载荷和 HTML 结果
与迁移前保持一致。

### 2.6 已确认严格请求校验的后续收口

负责人在 1C-0/1C-1 完成复核后确认三项公开错误语义，当前 Flask 路径随即完成：

- 非 JSON 对象顶层请求返回 400 `请求体必须是JSON对象`；
- params 任一元素不是对象时整次返回 400 `params元素必须是对象`；
- filePathList 第 N 项不是非空字符串时返回 400
  `filePathList中第N项不是有效字符串`。

解析集中在 `app/adapters/web/flask/report_requests.py`。它深复制请求、规范化 reportId，
并保证所有错误都发生在任务创建、初始 Progress 和线程启动前；Blueprint 不再自行拼接
这些字段校验。该收口没有切换成功 202、重复 409、SQLite 或执行器。

## 3. 全面代码复核结论

本轮复核额外消除了以下边界问题：

1. 拒绝将无序 `set` 或 `dict` 键静默冻结成源 URL 快照；
2. callback 状态先校验字符串类型，再进行集合判断，避免非法 list/dict 泄漏 Python
   `unhashable type` 异常；
3. callback 公开字典每次独立生成，调用方修改一次结果不会污染后续结果；
4. 遗留报告执行的 Context/Conversation 名称增加精确兼容断言；
5. MHTML 测试不再依赖不存在的路径或开发机是否安装可选 PDF 转换器；
6. 空 RAG 成功只写内部告警日志，不把质量标记泄漏到 callback、Progress 或 HTTP。

未发现 report Domain 对 Flask、数据库、网络、文件系统、队列或日志设施的反向依赖。
`ReportInputSnapshot.task_id` 使用框架无关文本，是为了避免 report Domain 反向导入
tasks 模块；后续 1C-2 已在 Application/Port 边界完成通用 TaskId 的显式转换，没有在
Domain 之间形成循环依赖。

### 4.2 数据与基础设施

- 未新增或修改 SQLite/MySQL 表；
- 未迁移历史数据；
- 未创建 RabbitMQ、Redis、MinIO 或 Celery 配置；
- 未实现 Repository、Outbox、Dispatcher、Callback Guard 或可靠队列；
- 未启动生产/开发主进程，也未调用真实外部服务。

因此，本轮全部代码仍处于开发分支和离线测试阶段，没有进入生产执行链。
