## 1. 迁移策略与结果

本波次只迁移测试价值，没有物理删除生产兼容源码。旧测试按“纯规则归 Domain、流程与故障收敛归
Application、供应商协议归 Integration/Adapter、文件处理归 DocumentProcessing、HTTP 投影归
Presenter/Route”的现行所有权重写；不再冻结旧类名、旧私有日志函数或旧补丁路径。

`tests/contracts/stage1g_legacy_test_migration.json` 已升级为 Schema v2，逐方法记录十个来源文件的
200 条旧测试方法、处置方式、现行 target tests 和语义边界。整改时先从 `HEAD` 恢复十个来源文件，
确认原安全网 200/200 通过，再执行迁移。新增永久门禁验证：

1. 六个已退出来源文件确实不存在，四个就地切换文件不再导入旧执行路径；
2. 每条旧测试方法都有唯一处置记录，所有迁移目标测试方法均可通过 AST 精确定位；
3. 九类旧模块/Facade 的 `test_execution` 引用均为零；
4. 只有三条 Argos 私有探测启发式测试按“不稳定实现细节”退役，并记录具体理由；
5. 方法级 `task_service` 兼容面明确延期至 1G-5E，不混入“已清零”结论。
