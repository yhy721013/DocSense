# 文件对话历史结构与轮次时间持久化改造总结

本次改造聚焦文件对话链路的两个核心问题：  
1）`GET /llm/chat/history` 实际返回结构与目标文档 `对话的历史结构.json` 不一致；  
2）`POST /llm/chat` 在本地数据库中缺少“每轮对话时间”持久化能力。

## 1. 背景与需求

### 1.1 历史接口结构不一致

原实现返回：

```json
{
  "chatId": "...",
  "messages": [...]
}
```

目标结构要求为顶层数组，消息项字段为：
- `role`
- `content`
- `timestamp`
- `files`（仅 `user` 消息存在，元素结构为 `{ "name": "..." }`）

### 1.2 每轮时间未落库

`ChatDatabaseService` 原先仅维护会话级 `created_at / updated_at`，未记录每次用户发送消息对应的轮次时间，导致历史时间字段完全依赖上游返回，不具备本地兜底能力。

## 2. 核心实现内容

### 2.1 `/llm/chat/history` 返回结构改造

- **代码位置**：`app/services/llm_service/chat_service.py`
- `get_chat_history()` 从返回对象改为直接返回消息数组（`List[Dict[str, Any]]`）。
- 历史消息组装规则调整为：
  - 公共字段：`role`、`content`、`timestamp`
  - `user` 消息附加 `files: [{"name": "..."}]`
  - `assistant` 消息不附加 `files`

### 2.2 历史接口空会话响应改造

- **代码位置**：`app/blueprints/llm.py`
- `/llm/chat/history` 捕获 `ChatNotFoundError` 后改为返回 `[]`（HTTP 200），与目标结构统一。

### 2.3 调试页读取历史适配

- **代码位置**：`app/templates/debug/chat.html`
- `loadHistory()` 从读取 `payload.messages / payload.chatId` 改为读取数组响应：
  - `state.historyMessages = Array.isArray(payload) ? payload : []`
  - 当前会话 ID 继续使用输入框中的 `chatId`

### 2.4 接口文档同步

- **代码位置**：`docs/接口文档/文件对话.md`
- “获取对话历史接口”章节已同步为目标结构：
  - 顶层数组响应
  - 增加 `timestamp` 字段说明
  - 新增 `files` 元素结构说明
  - 对话不存在示例改为 `[]`

### 2.5 数据库新增轮次时间持久化

- **代码位置**：`app/services/core/database.py`
- `chats` 表新增字段：`turn_timestamps TEXT NOT NULL DEFAULT '[]'`
- 初始化阶段增加兼容迁移：
  - 通过 `PRAGMA table_info(chats)` 检测列
  - 旧库缺列时自动执行 `ALTER TABLE ... ADD COLUMN`
- 写入逻辑更新：
  - `create_chat()`：创建会话时写入首轮时间戳（毫秒）
  - `append_file_names()`：每次继续对话追加文件批次时同步追加当前轮时间戳
- 读取逻辑更新：
  - `get_chat()` / `list_chats()` 解析并返回 `turn_timestamps`

### 2.6 历史时间字段本地回填机制

- **代码位置**：`app/services/llm_service/chat_service.py`
- 先尝试从上游消息提取时间（支持 `timestamp/sentAt/createdAt/updatedAt/created_at/updated_at`）。
- 若 `user` 消息上游无时间，则按轮次索引回填本地 `turn_timestamps`。
- 仅在无法获得时间时返回 `null`，满足当前开发阶段“正常应有时间”的要求，同时保留异常兜底。

## 3. 相关测试更新

- **代码位置**：`tests/test_chat.py`
  - `test_history_returns_empty_list_for_nonexistent_chat`
  - `test_history_returns_target_schema`
  - `test_history_uses_db_turn_timestamp_when_upstream_missing`
- **代码位置**：`tests/test_chat_debug_preview.py`
  - `test_create_and_append_chat_persist_turn_timestamps`

以上测试覆盖了：目标结构返回、空会话行为、时间回填逻辑、轮次时间持久化行为。

## 4. 变更影响总结

1. 历史接口对外协议已切换为目标 JSON 结构，前端与文档保持一致。  
2. 会话数据库具备了每轮用户消息时间持久化能力，并支持旧库平滑升级。  
3. 历史时间字段不再完全依赖上游，有本地回填保障，接口稳定性提升。
