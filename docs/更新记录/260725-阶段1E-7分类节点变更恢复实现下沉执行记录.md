# 阶段 1E-7：分类节点变更恢复实现下沉执行记录

## 1. 范围与契约结论

本阶段只重构分类节点变更 Saga 的内部恢复实现。目标是将此前集中在大型恢复 Facade 中的观察、
检查点收敛、固定顺序补偿和终态/隔离算法下沉到独立协作器，作为可靠队列与多实例恢复接入前的
结构前置条件。

本阶段**未修改** `docs/接口文档/分类节点变更.md`，也没有增删或改名请求参数、响应字段、
HTTP 状态码、Header、JSON/SSE/WS 格式或同步语义。接口文档 SHA-256 保持为：


fencing、观察与补偿事实继续禁止进入 `/llm/reassign` 的公开响应。

## 2. 已完成改造

### 2.1 真实协作器替代 callback 接缝

- `recovery_observer.py`：直接执行本地提交状态探测、远端 workspace/成员关系探测、每次远端调用前
  的 lease/claim 续租复核，以及恢复观察事实追加；
- `recovery_checkpoints.py`：直接执行前向、workspace 准备和补偿检查点收敛，持久化探测事实，
  并调用纯领域规则产出补偿决策；
- `recovery_compensator.py`：直接执行“目标解绑 → 来源恢复”的固定顺序补偿，保存写前意图、写后
  四分类检查点，并在每一步后重新探测远端状态；
- `recovery_finalizer.py`：成为恢复终态提交和 `recovery_required` 隔离的唯一协作器；
- `recovery_types.py`：承载内部命令、结果、lease 上下文、远端观察和检查点判定值对象，不引入 I/O。

四个协作器均通过构造函数接收其最小 Port 依赖，不保存 Facade 绑定回调、Operation 可变状态、
共享 HTTP Client 或线程。网络调用仍发生在短 Unit of Work 之外，全部写入仍携带当前 lease/fencing。

### 2.2 Facade 缩减与兼容性

- 新增 `recovery_facade.py`：`RecoverReassignmentOperation` 只保留命令校验、精确过期 lease 接管和
  local-only/远端高层流程选择；
- 原 `recover_reassignment.py` 改为兼容导出模块，既有 `application` 包、组合根和诊断脚本的 Python
  导入路径保持不变；
- Facade 首次下沉后的源码基线原为不超过 727 行；阶段 1E 整体审查增加 Application 命令入口预算
  锚点后，协调层基线调整为不超过 746 行。任何单方法的保守圈复杂度仍不超过 24；后续增长必须先
  评审是否应归属到对应协作器。
