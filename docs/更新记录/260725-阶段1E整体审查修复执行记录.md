# 阶段 1E：分类节点变更整体审查修复执行记录

## 1. 范围与契约

本轮修复阶段 1E 整体审查发现的提交确认歧义、同步预算起点、lease 计算时机、活动状态重复定义和
未来多实例计划边界问题。按负责人要求，本轮不处理“1E-7 文件尚未原子纳入 Git”，不执行
`git add`、提交或其他暂存区操作。

本轮没有修改 `docs/接口文档/`，也没有增删或改名 `/llm/reassign` 的请求参数、响应字段、HTTP
状态码、Header 或同步语义。所有调整均位于内部 Application、Port、Adapter、恢复协作器、测试和
重构记录；内部 Operation、Step、lease、fencing 与恢复事实继续禁止出现在公开响应中。

## 2. 已完成修复

### 2.1 事务提交确认丢失后的终态协调

- Application 本地映射提交和恢复 Finalizer 终态提交出现异常或非预期返回时，不再立即补偿或把
  Operation 隔离为 `recovery_required`，而是先通过新的只读事务重读持久化 Operation。
- 如果持久化终态已经是本次预期的 `succeeded`、`failed` 或 `recovery_required`，直接返回该真实
  终态；只有无法证明提交成功时，才继续既有补偿、冲突处理或 fail-closed 隔离。
- 新增“事务实际提交后，`__exit__` 再抛异常”的严格 Fake 和 Application/Finalizer 回归，防止将
  数据库提交确认丢失误判为业务提交失败，继而产生错误补偿或覆盖已提交终态。

### 2.2 同步预算与 lease 计时边界

- `DocumentReassignmentService` 和恢复 Facade 在 Application 命令入口记录单调时钟，创建请求级
  Knowledge Port 时传递已经消耗的时间；AnythingLLM deadline 从配置总预算中扣除这段耗时。
- 初次保留、执行续租、恢复接管和恢复观察续租的 `lease_expires_at` 均改为取得 Repository/UoW
  写事务后计算，避免数据库锁等待提前吞掉新 lease 的有效期。
- 时间输入增加 callable、有限数和非负校验；时钟异常时 fail-closed，不以不可信时间继续执行远端
  副作用。

这里的“总预算”是从 Application 入口开始累计的远端调用预算，不是当前 Flask/SQLite 调用栈的
强制取消器。SQLite 本地锁等待会扣减后续远端预算，但当前阶段仍无法中断已经进入的本地语句或锁
等待；因此文档不再将其表述为完整同步硬截止。

### 2.3 状态一致性与结构门禁

- Repository 的活动 Operation 状态由领域 `operation_holds_document_protection` 规则推导，不再维护
  第二份同层硬编码集合。
- `DatabaseService` 继续保持对领域模块的依赖隔离，但新增永久回归，要求其删除保护状态与领域规则
  逐项相等；以后新增状态时，未同步数据库删除门禁会立即失败。
- 恢复 Facade 因 Application 预算锚点协调增加少量代码，结构门禁基线由 727 行调整为 746 行；最小
  Port、禁止 callback-wrapper 和单方法圈复杂度门禁保持不变，恢复算法不得回迁 Facade。
- 修正 ArchitectureId 注释及模块说明中已经过时的宽松 SQLite 行为、同步补偿和组合根状态描述。

## 3. 未来计划修正

- 多实例阶段必须把 lease/claim 过期判断迁移到数据库权威时间，避免不同实例进程时钟偏差。
- 可靠队列和多实例执行前必须提供可取消的数据库锁/语句截止能力；在此之前不能把远端 deadline
  等同于完整请求硬截止。
- 未来新增 Repository Adapter 必须复用“提交已经发生但确认丢失”的故障测试，终态协调不得只依赖
  SQLite 驱动的当前异常表现。
- 领域活动状态与数据库文档删除保护状态的等价测试是长期门禁；新增状态不能只修改一侧。
