# 更新记录目录说明

本目录记录已经实施的功能变更、问题修复和可追溯的历史演进。它解释“实际改了什么、如何验证、仍有哪些边界”，但不替代 `docs/接口文档/` 的公开契约地位。

## 阅读原则

1. 先读 `docs/接口文档/` 确认当前公开合同。
2. 再读本目录的整合执行记录，了解阶段最终实现；不要按已删除的子阶段流水账重建中间状态。
3. 最后按问题需要阅读独立专题修复。测试数字是当时基线的历史证据，不代表当前全仓数量或生产容量。
4. 可靠队列、多实例、共享数据库、生产高并发和 exactly-once 只有在对应生产门禁完成后才能声明。

## 维护规则

- 同一专项的连续子阶段默认写入一篇整合执行记录，用里程碑表区分波次；只有具备独立合同、运维或故障语义的修复才单独成文。
- 实施记录必须写清实际修改、验证集合、排除项、回滚和未验证边界，不得把计划写成当前能力。
- 任何公开接口文档变更必须先确认；禁止擅自增删前后端接口参数。
- 删除的历史记录必须已被整合文档吸收并可由 Git 恢复；索引和交叉引用必须同步更新。
