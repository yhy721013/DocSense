# 文件对话请求与活动范围分离阶段 2 执行记录

## 1. Schema v4

Chat SQLite 正式迁移增加：

- `chat_scope_revisions`
- `chat_scope_members`
- `chat_scope_heads`
- `chat_run_inputs.requested_files_json`
- `chat_run_inputs.effective_scope_revision_id`
- `chat_run_inputs.selection_mode`

Scope Revision 和成员只允许追加，Head 通过 CAS 更新。`source_run_id` 在插入事务内校验与
`chat_id` 的归属，但不建立级联删除外键，避免未来清理历史 run 时删除仍被 Head 或其他
run input 引用的范围。

阶段 2 为保持旧生产链暂时可运行，保留 `legacy_input` 过渡默认值；正式 Scope 输入必须引用
同一 chat 的 Revision、使用三种正式 selection mode，并保持旧 `files_json='[]'`，避免把
全量成员重复复制到每轮 run input。

## 2. Repository

新增 `ChatScopeRepository`：

- 读取 Head、Revision 和有序成员；
- 追加 Revision 并 CAS 切换 Head；
- 列出会话全部追加式版本；
- 允许成员数为 0 的首次空范围；
- 拒绝错 chat 的 source run、scope head 和 run input；
- `ChatRunInputRepository` 分别恢复 requested 文件和 effective Scope 成员。

`ChatStore` 已装配 Scope Repository，但生产 Coordinator 尚未调用新写入链。
