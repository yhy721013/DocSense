## 2. 实施结果

1. 新增 Weaponry 公开请求 Application Command/Use Case，把 Document Scope 解析、运行策略注入和
   `SubmitWeaponryTask` 协调从蓝图移入应用层；`WeaponryApplicationServices` 从同一 Scope、策略和
   Submit 派生该用例，`dataclasses.replace` 不会形成半新半旧实例链。
2. 新增 check-task 无副作用 Flask Parser，完整校验所有项后按规范业务键稳定去重；原始请求数量
   单独保留，因此两个等价缺失键仍按既有批量 HTTP 200，而不是误变为单项 404。
3. 复用既有 `CheckTaskStatusService`，新增同步恢复路由 Adapter，将 file/report/weaponry 三条业务
   恢复链装配为 Tasks Port；恢复后按同一 TaskId 重读并校验持久状态，不退回遗留直发器。
4. 补齐内部合法 `outcome_unknown` Callback 状态，使显式未知结果重试能通过统一 Task Read；该状态
   不进入公开响应，也没有新增接口字段。
5. `app/blueprints/llm.py` 不再直接读取 `LLMTaskService` 或协调 Weaponry Scope/策略/Submit；
   check-task 和 Weaponry 均收口为 Parser → Application → Presenter。
6. 永久 AST 门禁覆盖直接基础设施构造、网络客户端、线程/daemon、业务文件 I/O 等禁用项，并有
   人工构造负例证明门禁能够失败。
