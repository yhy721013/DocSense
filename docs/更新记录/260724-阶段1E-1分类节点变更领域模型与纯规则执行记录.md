## 2. 已完成的改造

### 2.1 四层模块边界与永久门禁

新增 `app/modules/reassign/`，其中 `domain/` 已实现，`application/`、`ports/`、`adapters/` 仅建立
包标识与职责说明。`tests/test_architecture_boundaries.py` 已把该模块纳入永久目录门禁：每层缺少
`__init__.py` 或 README 都会失败；Domain/Application/Ports 继续使用 AST 正向依赖白名单，不 import
生产组合根，因此不会在架构测试中初始化 SQLite、连接 AnythingLLM 或启动 `run.py`。

### 2.2 不可变原始 ID、文档与执行事实

新增以下领域对象：

- `ReassignDocumentCommand`：深冻结新旧 ArchitectureId 原始 JSON 值，并只保存由 Web Adapter 已完成
  的 `old_architecture_id_query_value`。领域层不再调用 `int(...)`，不把 `1`、`"1"` 或 `false`
  重新解释为同一个 ID，也不追加新 ID 类型限制；
- `ReassignmentDocumentSnapshot`：冻结本地文档行、文件名、来源分类、`anything_doc_id`、`doc_path`
  和原始文件名。空 `doc_path` 继续表示未来本地条件更新路径，未被改成新的参数错误；
- `ReassignmentOperation`：冻结文档身份、来源/目标原始分类、状态、当前步骤和成组 lease/fencing
  事实，禁止半份 owner 信息；
- `ReassignmentStep`：冻结固定步骤名、幂等键、状态、写意图、外部引用和有界错误摘要。所有非
  `pending` 状态都必须先有 `write_intent_recorded`；
- `ReassignmentResult`：只保留成功/失败分类和公开 message，故意不携带 operation ID、lease、
  fencing、步骤或错误详情。

原始 JSON 包装会递归复制列表/对象、拒绝非 JSON 值与 NaN/Infinity，并在投影时创建新对象，避免
并发请求、恢复器和调用方共享可变引用。

### 2.3 状态机、幂等键和补偿决策

`domain/rules.py` 建立无 I/O 纯规则：

1. Operation 正常路径只允许 `reserved → running → succeeded/failed/compensating/recovery_required`，
   `compensating` 只能到 `compensated` 或 `recovery_required`；
2. `recovery_required` 默认没有普通请求出边，只有未来恢复服务在 Repository fencing 校验完成后
   显式提供 `recovery_authorized=True` 才能进入受控的运行、补偿或终态判定；
3. Step 固定为 `pending → mutation_started → succeeded/known_failed/outcome_unknown/compensating`，
   并要求先持久化写意图再启动外部写。结果未知和补偿失败同样只能走受控恢复分支；
4. 步骤幂等键覆盖 operation、步骤名、本地文档行、`anything_doc_id`/`doc_path`、来源内部/原始
   分类和目标原始分类，而不是把 `fileName` 当作唯一键或假定供应商天然幂等；
5. 补偿决策只接受已确认的来源删除、目标加入和本地提交事实。任何 `outcome_unknown` 直接进入
   `recovery_required`；目标绑定确认时固定先删除目标、再恢复来源；已确认本地提交成功时普通
   异常路径不得自动回滚。

纯规则不依赖日志设施，以保证同一已持久化事实在多个 Worker/实例中得到相同决策。后续
Application/Adapter 必须在写意图、调用、探测、补偿、lease/fencing 与终态边界输出脱敏结构化日志；
禁止记录 API Key、Authorization、文档正文、完整供应商响应或内部 ID 到公开响应。

### 2.4 仍刻意未实现的内容

- 未定义 Repository、Unit of Work、Knowledge Port 或严格 Fake；它们以 1E-2 的业务抽象为前提，
  因此没有用具体 SQLite/AnythingLLM 类型伪造接口；
- 未创建 SQLite Operation/Step/Event 表、部分唯一索引、lease、fencing、CAS 或审计事件；
- 未创建 AnythingLLM Client/Transport、workspace 适配、成员探测、删除、加入、Pin 或补偿执行；
- 未创建线程、内存队列、定时恢复器、Outbox、RabbitMQ、Redis、MySQL 或多实例协调；
- 未改动 Flask Parser、Presenter、Container、公开路由、接口文档或现有 `DatabaseService`。
