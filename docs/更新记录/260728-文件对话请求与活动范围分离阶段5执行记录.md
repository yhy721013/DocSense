# 文件对话请求与活动范围分离阶段 5 执行记录

## 1. History 语义

公开 `/llm/chat/history` 的结构保持不变，用户消息 `files` 只投影本轮 Requested Scope：

- 首次空请求返回 `files: []`；
- 后续空请求返回 `files: []`；
- 显式非空请求只返回该轮显式文件原名；
- 自动或继承的 Effective Scope 不进入历史；
- assistant 消息结构保持不变。

新增 1,000 个 Effective Scope 成员的内部压力样例，确认 run input 可恢复全部成员，而同轮空
Requested Scope 的 history 仍为 `files: []`。该测试通过内部上限参数构造大范围，只验证历史
投影不会线性膨胀，不放宽公开路由的 `DOCSENSE_CHAT_MAX_FILES`。

## 2. 调试页

`GET /debug/api/chat/bootstrap` 未增删任何字段。既有 `sessions[].fileNames` 的展示语义从
Workspace current bindings 校正为当前 Active Scope：

- 会话卡片明确显示“活动范围文件数”；
- 点击会话后恢复的选择精确等于当前 Active Scope；
- 累计绑定不再被页面误认为当前模型范围；
- Active Scope 与 Workspace bindings 的数量分别写入脱敏调试日志；
- 既有异常 session 缺失 Scope Head 时按空活动范围展示并记录告警，不扫描知识库猜测。

受“禁止增删前后端接口参数”的硬约束，Workspace binding 数量未作为新 JSON 字段增加到页面；
其独立观测由服务端调试日志承担。

## 3. 日志

受理、领取、执行事件记录和调试聚合日志已分开记录：

- `requested_file_count`
- `effective_file_count`
- `active_scope_member_count`
- `workspace_binding_count`
- `selection_mode`
- `scope_revision_id`
- `chat_id`
- `run_id`

日志不记录文件名、原始文件名、文档正文、远端文档 URL 或供应商响应。
