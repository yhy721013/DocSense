# 阶段 1H 关闭后全面审查修复执行记录

## 1. 范围与合同边界

本轮按 1H-R1～R6 顺序修复阶段 1H 关闭后全面审查发现的问题。每一波次均先完成代码、定向测试
和验收门禁，再进入下一波次。没有运行 `run.py`，没有连接真实 MinerU、OCR、浏览器、
LibreOffice、Ollama 或 AnythingLLM 后台服务。

本轮未新增、删除或重命名任何 HTTP/Callback/Progress/SSE/WebSocket 参数、字段、状态码或
Header；`docs/接口文档/` 未修改。MHTML 浏览器继续固定使用 `--no-sandbox`。

## 2. 已修复问题

### 2.1 PDF 降级与 Translation

- Analysis 扫描 PDF 恢复 `MinerU -> 内置 OCR -> 原 PDF`；Report 保持
  `内置 OCR -> 原 PDF`。
- 原 PDF 降级只作为 RAG Artifact，不再伪装成 Markdown/Text；全文翻译没有 prepared 文本时
  沿用业务可降级失败投影。
- 只有明确失败才能降级；`outcome_unknown` 必须先对账。
- Renderer 按表示类型保留 Markdown 标题、列表、表格、链接和图片；失败单元保留原文，不把异常
  类型写入用户正文。

### 2.2 MinerU 与 MHTML

- 真实 MinerU Converter 向 Processor 返回完整结果目录，统一执行“恰好一个 Markdown”门禁。
- 相对图片经路径包含、存在性、MIME、单文件和总大小门禁后内联为 data URI；scratch 清理后
  Artifact 仍可独立渲染。
- MHTML job 改为独占创建；既有无标记、外来标记或旧 DocSense 标记目录均不接管、不删除。
- MHTML 文件头只读取 1024 字节，不再先加载整个文件。

### 2.3 Processing Record、Profile 与 Artifact

- 新增内部 `ReconcileProcessingRecord`：陈旧 `running` 只隔离为 `outcome_unknown`；实际确认
  失败后显式写 `failed`，或用已通过完整性校验的 Artifact 原子恢复 `succeeded`。
- MinerU 外部操作记录提交意图、供应商 task identity 和明确 `succeeded/failed` 终态；unknown
  不自动重提。
- MinerU Profile 只保存 `local/remote` 和 endpoint fingerprint；URL、userinfo、query 密钥不
  进入 Profile 或 Processing Record。
- 新增通用 Artifact Catalog，登记 source 与派生产物并允许同一步骤多个 ordinal。旧结果表继续
  作为单主产物兼容投影，本轮不启用 GC。

### 2.4 单实例长运行安全

- 本地 Artifact 锁改为引用计数并在无使用者时回收。
- `open_reader` 在同一读租约中完成校验、seek 和句柄交付；进程内删除等待读租约释放。
- 宿主源文件只读取一次，header、SHA-256 和发布内容都来自同一受控快照。
- FIFO 许可增加最大进程内 waiter 数，超时/中断/取消均移除 waiter，防止幽灵队首。
- Ollama 非流式生成使用有界连接/读取超时。
- LibreOffice 超时后检查进程树终止结果；不能确认时返回
  `conversion_timeout_outcome_unknown`，禁止当作安全失败重试。

## 5. 未完成能力与后续计划

1. Analysis/Report accepted 事务尚未冻结全部 OCR、MinerU、Renderer、Translation Engine 和依赖
   版本参数。阶段 2 必须升级内部 Task Input Schema，并由 Worker 在执行前做 profile/fingerprint
   匹配；不修改公开接口。
2. Tesseract、PyMuPDF、MinerU、Markdown Renderer 等完整供应链指纹随上述 execution snapshot
   一并落地。当前 MinerU endpoint 已脱敏冻结，但不能据此宣称完整跨重启可重放。
3. SQLite、本地 Store、进程内锁/容量只证明单实例能力。MySQL/SQLAlchemy、MinIO、可靠队列、
   Outbox、跨实例 lease/fencing 与全局容量仍按阶段 2～5 实施。
4. Artifact Catalog 只建立所有权事实；自动 GC 必须等待引用、保留期、删除资格、租约/fencing、
   审计和对象存储门禁齐备，并另行确认具体保留策略。
5. 本轮没有真实服务 Smoke，不作 production-ready 声明。
