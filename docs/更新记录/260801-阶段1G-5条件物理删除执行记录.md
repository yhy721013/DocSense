### 2.2 1G-5B：Translator 与文件处理旧 Facade

删除 `app/services/translator/` 旧包，以及旧 MHTML、OCR Facade。当前唯一实现位于

`DOCSENSE_TRANSLATION_*` 配置名称继续由现行 Config/Adapter 使用，没有误删部署配置。

### 2.3 1G-5C：Debug Preview 旧 Facade

删除旧 Callback/Chat Debug Preview 文件。Debug 蓝图继续只调用 `app/modules/debug/` 的
Application、Adapter 和 Presenter；路径安全、JSON 错误、Active Scope 与脱敏计数测试均由现行
模块承接。

### 2.4 1G-5D：AnythingLLM 与 RAG 旧包装

先把 Report 本地上传文件准备迁入 `app/modules/report/adapters/upload_files.py`，再把四个运维脚本

Integration 并保留逐 workspace 失败隔离与 Transport 关闭。完成后删除旧聚合 Client 与旧 RAG
编排文件。`app/integrations/anythingllm/`、各业务 Adapter Factory 和 Callback 历史能力继续保留。

### 2.5 1G-5E：活跃大文件中的兼容方法

测试造数被明确拆成两类：历史兼容测试通过 `tests/task_service_fixtures.py` 构造只有公开投影的旧库
记录；并发受理、整批回滚和 Callback Guard 测试必须走现行 Analysis 原子受理、领取、终态提交和
同步恢复链。由此既保留旧数据兼容测试价值，也不会在生产 Service 上为测试保留可误用 API。

可靠队列、多实例一致性、生产容量、 exactly-once 或真实供应商可用性。1G-5 未发现需要修改公开
接口、扩大数据迁移或追加负责人决策的问题，可以进入 1G-6 关闭验收与阶段 2 交接；1G-6 仍须把

结论扩张为分布式能力完成。
