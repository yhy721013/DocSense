## 3. 已建立的架构规则

> 2026-07-16 审查修正：下表记录 1A-2 首次实施口径。当前门禁已经升级为按层级的
> 正向依赖白名单，tasks 禁止所有其他业务模块分层，并检测 `__import__`、
> `importlib.import_module` 及别名。最新实现与测试见
> `260716-阶段0与1A审查修正记录.md`。

| 检查范围 | 允许方向 | 当前拒绝内容 |
| --- | --- | --- |
| `app.modules.*.domain` | 标准库、本模块纯领域类型 | Flask/FastAPI、Celery、SQLAlchemy、`sqlite3`、`requests`、遗留 Service、Integration、application/ports/adapters 反向依赖 |
| `app.modules.*.ports` | 标准库、domain | Web/队列/数据库/HTTP 库、遗留或具体实现、application/adapters 反向依赖 |
| `app.modules.*.application` | domain、ports | Blueprint/request/current_app、Web/队列/数据库/HTTP 库、遗留 Service、Integration、相对或绝对 Adapter |
| `app.modules.tasks` 全模块 | 自有层和迁移期自身兼容 Adapter | chat persistence、其他业务模块 Adapter |
| `app.presenters` | 领域事件、框架无关应用结果 | Flask/FastAPI、数据库、`app.modules.*.adapters`、AnythingLLM Client、HTTP 客户端 |

### 3.1 为什么使用 AST 而不是导入模块

如果测试通过 `import app...` 收集依赖，Python 会先执行包初始化；未来可能因此构造应用容器、初始化 SQLite 或创建外部客户端。AST 检查只读取源码，不执行模块级代码，因此：

- 不需要 Flask context 或后台服务；
- 不会写入开发 `.runtime`；
- 能在依赖尚未安装时仍识别违规导入；
- 能输出源码文件、行号、规则、目标和中文原因。

### 3.2 相对导入不能绕过门禁

检查器根据源码所在模块解析 `ast.ImportFrom.level`。例如 application 中的：

```python
from ..adapters import legacy_task_service
```

会还原为 `app.modules.tasks.adapters` 后再判断，因此与绝对导入执行同一规则。

### 3.3 规则自证

测试在操作系统临时目录写入最小违规源码，逐项验证：

- domain 可以拦截 Flask、SQLite 和 requests；
- ports 可以拦截 application 反向依赖和 SQLAlchemy；
- application 可以拦截 Flask 全局、遗留 Service 和相对 Adapter；
- tasks 可以拦截 chat persistence 和其他业务 Adapter；
- presenters 可以拦截具体数据库和 AnythingLLM Transport；
- domain → 标准库、ports → domain、application → domain/ports 等合法方向不会被误拦截。

## 4. 模块边界的实际含义

### 4.1 tasks 不是 Celery 包

tasks 表达任务身份、状态读取、回调恢复和进度协作的业务控制面。Celery、RabbitMQ、Redis、MySQL 和当前 SQLite/Hub 都只能成为端口实现；队列框架不得成为领域模型。

### 4.2 tasks 不拥有 chat 数据

chat 继续拥有会话、消息、ChatRun、资源租约和清理任务。tasks 不能直接读取或写入 chat persistence；后续若需要关联，只能通过明确的应用契约、内部引用或事件设计。

### 4.3 当前生产路径没有变化

- `/llm/check-task` 和 `/llm/progress` 仍由 `app/blueprints/llm.py` 处理；
- `LLMTaskService`、`LLMProgressHub` 和现有 Container 装配没有改动；
- 新包没有模块级单例、线程、数据库 Session、网络 Session 或配置读取；
- 1A-1 已确认的目标契约仍要等波次 1B 才切换。
