## 3. 历史实现不变量

1. `fileNames` 与 `architectureId` 严格二选一；布尔值、非安全整数、超长或混合请求失败关闭。
2. architecture 会话首次受理时解析并冻结类别直接文件；后续同 ID 只复用旧 Head，不重新读取当前目录。
3. 会话 Binding 不可变；模式或 ID 冲突优先于容量/目录错误返回，防止错误优先级泄漏内部状态。
4. Binding、Scope Revision/Head、run input 和 pending message 在一个 SQLite 事务中提交。
5. Worker 仅凭 run_id 恢复冻结范围；远端 Workspace 额外文档不得进入模型范围。
6. architecture History 只保存规范化 ID，不动态展开当前类别成员；坏持久事实失败关闭。

## 4. 全面审查修正

- 将 `architectureId` 收紧为 JavaScript 安全整数，Domain、Parser、Codec 和 SQLite 约束一致。
- 增加持久 Admission Guard；同会话冲突先返回 409，容量异常也必须幂等释放 Guard。
- Schema v6 对 Binding、Revision、Head 和 message 关系增加对称完整性约束。
- 类别目录使用参数化 SQL 和显式上限；超限整体拒绝，不截取前 N 个文件。
- 远端 attach/binding 必须确认所请求文档均被供应商接受，缺少回执不得回退旧 document_ref 伪装成功。
- SSE `aborted` 表示中断已被执行流观察并收敛；`error` 表示执行失败，两者不能混用。

## 6. 后续取代关系

旧复合入口在业务身份、数据删除、History 和前端契约上耦合过重，后续已迁移为：

- File Chat 继续使用 `/llm/chat*` 与 chatId 身份；
- Weaponry Chat 使用独立 `/llm/weaponry-chat*` 与 userId + architectureId 复合身份；
- 两类对话共享内部 conversationId、Domain/Application/SQLite/AnythingLLM 核心，但公开路由和生命周期策略独立。

因此，本文的直接文件冻结、失败关闭、原子受理和恢复规则仍可复用；旧 selector、旧公开 History 字段和旧路由切换方案不得恢复。

## 7. 证据边界

SQLite 单实例、Fake 和离线协议门禁不证明真实供应商、多实例共享 lease、可靠队列、浏览器 UI 或生产容量。
