# 阶段 1H-6 业务调用方单路径切换执行记录

## 1. 结论

阶段 1H-6 已按 Utils → Report → Analysis → Translation/Weaponry 顺序完成生产组合根切换。
同一业务输入只执行一条 DocumentProcessing 流水线；Report、Analysis 和 Translation 不再
各自决定 MHTML、Legacy Office、MinerU 或 OCR 的执行路径。公开 Blueprint、请求/响应字段、
状态码、空响应体、Progress、Callback 和 `docs/接口文档/` 均未修改。

MHTML 浏览器命令继续固定传入 `--no-sandbox`，并在 Processing Profile 中冻结
`noSandbox=true`；本阶段未增加开关。

## 2. 主要实现

### 2.1 统一本地 Artifact 桥

- 新增 `LocalDocumentPreparationAdapter`，作为宿主路径进入共享 Artifact 内核的唯一桥；
- 源文件先发布为任务级 SOURCE Artifact，再按格式执行确定性处理链：
  - Markdown/TXT：严格 UTF-8 直通；
  - MHTML：浏览器 PDF 主流程，确认失败后 Markdown 降级；主流程成功后继续 MinerU；
  - Legacy Office：LibreOffice OOXML 后继续 MinerU；
  - PDF：按冻结扫描件策略选择 MinerU OCR 或内置 OCR；
  - OOXML/图片：MinerU Markdown；
- 所有步骤共用 LocalArtifactStore、SQLite Processing Record、外部操作观察器和进程内 FIFO
  重型许可；`outcome_unknown` 不触发第二条处理链；
- MHTML 内容检测不只依赖扩展名；扩展名漂移会记录脱敏告警。

### 2.2 Report

- 生产 `LegacyReportFileAdapter.normalize_source()` 只调用一次统一流水线；
- 最终 prepared Artifact 通过 `LocalReportArtifactAdapter.publish_document_artifact()` 映射为
  既有 `ReportArtifactRef`，业务 Port 和公开合同不变；
- `prepare_upload_files()` 在新路径只映射 `RAG_INPUT` 类别，不再重复执行 OCR/MinerU；
- 旧函数签名只保留给离线兼容测试，生产 Container 不选择旧链。

### 2.3 Analysis

- `PreparedAnalysisDocument` 增加内部 `prepared_artifact` 引用，不进入 Task Codec 或 Callback；
- 生产文件 Adapter 只生成一份 prepared Markdown/Text：
  - RAG 使用该 Artifact 的受控本地映射；
  - `original_text` 直接从该 Artifact 读取；
  - 全文翻译直接传递同一 `ArtifactRef`；
- raw/processing/upload 既有资源恢复字段仍保留，公开结果和 Callback 无 Artifact 字段；
- 旧 Application Fake 没有 Artifact 时仅保留测试兼容分支，生产组合根不会进入。

### 2.4 Translation 与 Weaponry

- 新增 `ArtifactAnalysisTranslationAdapter`：
  - 全文调用 `TranslatePreparedDocument`；
  - 摘要只调用 `TranslationEnginePort`；
- 新增惰性 HYMT Engine Adapter，Container 构造阶段不探测 Ollama；锁只覆盖单次引擎调用，
  不包含文档准备、Artifact 读取、分段或 Renderer；
- Weaponry 纯文本翻译改为直接使用同一个 TranslationEngine，不再经过文档翻译 Service；
- `use_minerU` 兼容方法参数未删除，生产路径不再以它决定格式处理。

### 2.5 兼容 Facade

- `rag_pipeline.py` 直接委托 DocumentProcessing OCR 唯一实现；
- MHTML 路径式兼容实现迁入 `document_processing/adapters/path_compat.py`；
- `services/utils/mhtml_normalizer.py`、`ocr_preprocessor.py` 仅保留薄 Facade；
- Analysis/Report 不再反向导入上述 utils Facade。

- 单路径专项测试：Report 只调用一次 DocumentProcessing，Analysis 三类消费者共享同一
  prepared Artifact，Translation 全文/摘要边界清晰；
- 扩大离线回归：72 个模块，discovered 956、executed 956、failures 0、errors 0、
  skipped 1；
- `compileall app tests` 通过；
- `git diff --check` 通过，仅有既有 Windows CRLF 提示；
- AST 消费者清单通过，业务模块不再导入 Translator Converter 或 utils 转换 Facade；
- `docs/接口文档/` 工作区状态为空；

unittest 最终结果为通过。

## 5. 边界与下一步

- 本阶段使用本地文件 Store、SQLite Record 和进程内 FIFO，只证明单实例离线行为；
- 未启动 `run.py`，未执行真实 MinerU/OCR/浏览器/LibreOffice/Ollama Smoke；
- 共享 Artifact 的长期保留/清理引用、旧 Handler/Converter 和测试兼容分支由 1H-7 的三类
  引用矩阵与关闭验收决定，不能在引用未清零前直接删除；
- 1H 完成不代表可靠任务队列、多实例全局限流、MinIO/MySQL 或跨数据库一致性已经完成。
