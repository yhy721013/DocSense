# 阶段 1E-3R：分类节点变更适配一致性修正执行记录

| 项目 | 结论 |
| --- | --- |
| 修正范围 | 1E-3 全面审查发现的预算用途、请求隔离、步骤门禁、workspace 归属、异常分类、日志脱敏和 SQLite/Fake 一致性问题 |

## 2. 已修正问题

### 2.1 预算用途由 Saga Step 自动选择

- 普通前向写和确定性写后确认只使用前向预算，不再无条件消耗补偿预留；
- `compensate_target_document` 与 `compensate_source_document` 的写入及确认自动使用恢复预算；
- 超时、断连、协议异常等“写可能已生效”场景的只读查回允许使用恢复预算；
- 在 HTTP 调用前发现前向预算耗尽时，按“调用未发出”的已知事实分类，不再错误声称可能已有副作用。

该规则由 Adapter 根据固定 `step_name` 决定，Application 不能通过自由布尔参数选择预算。

### 2.2 Knowledge Port 改为请求级 Factory

`ReassignmentPortBundle` 不再保存可跨请求共享的 Knowledge Port 实例，而是保存
`ReassignmentKnowledgePortFactory`。生产 Factory 和严格 Fake Factory 都要求每个 Operation
取得新的端口实例，避免单调 deadline、调用期望或 Transport 状态跨线程串扰。

### 2.3 生产 Adapter 增加步骤—动作门禁

- 删除只接受 `detach_source_document` 或 `compensate_target_document`；
- 加入只接受 `attach_target_document` 或 `compensate_source_document`；
- Pin 只接受 `attach_target_document`。

错误步骤会在创建 Transport 前立即失败，生产实现与严格 Fake 不再存在行为分叉。

### 2.4 workspace 创建归属改为显式三态

内部契约和持久化统一使用：

- `created_by_operation`：可以证明由当前 Operation 创建；
- `preexisting`：可以证明是复用既有资源；
- `unknown`：已查回唯一可用资源，但供应商协议无法证明创建者。

创建超时、断连或 408/409/425/429 后，如果按确定性名称只查回一个 workspace，则保存 slug 和
`unknown` 并允许后续成员关系确认。该状态绝不能作为自动删除整个 workspace 的所有权证据。
SQLite 对早期 1E 开发库的布尔列执行加法回填，不重建表、不丢弃待恢复 Operation。

### 2.5 异常分类与日志脱敏

- 408、409、425、429 不再一律视为“明确无副作用”的普通 4xx；可写调用必须先查回；
- 已有业务异常时 Transport 关闭失败只记录关闭异常类型，不输出原始异常正文或 traceback；
- 日志反回归测试使用敏感哨兵文本，验证业务异常与关闭异常正文均不会进入日志。

## 3. 新增反回归门禁

离线测试新增或加强以下场景：

1. 前向预算耗尽后，补偿加入仍能使用预留窗口完成写与确认；
2. 正常加入及写后确认均不越过前向窗口；
3. 错误 Step 在任何远端调用前被拒绝；
4. workspace 创建 409 后只读查回并保存 `unknown` 归属；
5. `unknown` 归属可以原子持久化，且不会伪造 `CONFIRMED_EFFECT/CONFIRMED_NO_EFFECT`；
6. 早期布尔归属列可原位迁移为三态；
7. Transport 双异常日志不包含任一原始异常正文。

## 4. 仍需在后续阶段闭合的边界

1. 当前 Adapter 的 409 查回只能处理供应商已拒绝重复创建的情况。若供应商允许两个同名创建同时
   成功，仍需 1E-4 Application 在创建前取得“目标 architecture 准备权”的持久化 claim；
   该 claim 必须具备 lease/fencing 和过期接管语义，不能使用进程内锁。
2. 同步总预算当前只接受正有限值，但生产允许的最大值仍需根据接口网关、反向代理和线程容量确定。
   在该数值确认前，不擅自写入任意上限。
3. Python `requests` 的超时是底层连接/读取边界，不等同于可强杀线程的端到端硬中断。1E-4/1E-6
   组合与容量验收必须确保上游、网关和应用线程预算一致；未来可靠队列不能复用同步请求线程模型。

## 5. 回滚与兼容

- 本修正只修改尚未接线的 `app/modules/reassign` 内部契约、Adapter、SQLite 加法 Schema 和测试；
- 不删除早期 `target_workspace_created` 列，旧开发库升级后仅停止读写该列；
- 如需回滚代码，已写入的 `target_workspace_ownership` 为内部加法列，不影响现有公开表字段和
  `/llm/reassign` 契约；
- 任何后续公开接口文案或结构变化仍必须单独确认。
