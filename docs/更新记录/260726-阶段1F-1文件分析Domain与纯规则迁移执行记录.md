## 完成内容

1. 新建 `app/modules/analysis/` 垂直切片骨架，并为 Domain、Application、Ports、Adapters 分层
   补充中文 README。当前只实现 Domain；Application、Ports、Adapters 保持空骨架，避免提前接线。
2. 将下列确定性规则迁入 `app/modules/analysis/domain/`：

   - 配置常量、值对象与默认范围；
   - 领域树索引、范围归并和本地确定性召回；
   - Prompt 构造、分类与身份重选规则；
   - LLM 结果映射、相关技术字段归一化与 callback payload 投影。

3. Domain 内没有 Flask、SQLite、HTTP、文件解析器、旧服务或集成层依赖。领域树/召回的既有
   进程内缓存只使用受限标准库容器、锁和 Future 去重；它不是跨实例缓存，也不代表多实例能力。
4. 保留旧路径兼容：

   - `app.services.core.architecture_tree` 与
     `app.services.llm_service.architecture_recall_service` 直接别名到新的同一模块对象，确保缓存、
     私有辅助函数和既有测试替身的对象身份不改变；
   - `app.services.core.config` 继续导出既有 Analysis 常量，`core.prompts` 保留聊天/报告 Prompt 并
     复用 Analysis Domain Prompt；
   - `analysis_service` 保留任务 I/O、资源交接、审计、回调和日志边界，只通过兼容导出使用 Domain
     规则。结果映射外层保留历史相关技术诊断日志，Domain 不产生日志或任何外部副作用。

## 架构与可维护性约束

- 新增 `test_analysis_domain.py`，以 AST 与模块对象身份验证 Domain 的依赖方向、旧模块别名和兼容
  导出；不依赖脆弱的文本匹配。
- 既有架构导入规则仅为 Analysis Domain 增加最小的进程内缓存标准库白名单，未放宽其他业务 Domain
  的依赖边界。
- 所有迁移均为算法位置调整和兼容层收口，没有改变分类、抽取、翻译、任务或回调语义；接口文档仍是
  唯一公开契约权威。

## 复查后修复

1. `build_effective_analysis_ranges` 对调用方范围和全局默认范围执行深复制，确保返回的嵌套
   `list/dict` 是任务级独立快照，后续修改不会污染请求、默认值或其他任务。
2. 文件回调载荷在 Domain 投影边界深复制映射结果，避免终态之后的嵌套字段修改影响待发送或待恢复的
   callback 事实。
3. 所属技术规范化新增不可变诊断结果，由旧 Service 日志边界精确区分非中文、正文缺失、证据缺失和
   数量截断；Domain 仍不写日志。证据充分的第 11 项只记录数量超限，不再误报证据缺失。
4. Prompt 规范化恢复旧实现的非字符串 `TypeError("prompt 必须是 str")` 行为，不把内部契约错误
   漂移为 `AttributeError`。
5. Analysis Domain 的额外标准库白名单收窄到具体文件，并增加 `open`、`Path.read_*`、
   `Path.write_*` 等文件 I/O AST 门禁。领域树/召回缓存继续保留既有锁、Future 和时钟能力，普通
   分类、Prompt、映射模块不能继承这些进程级权限。
6. Domain 的兼容 `__all__` 改为显式字面量清单，并以测试校验；新增私有函数不会再自动扩散到旧
   Service 兼容面。现有导出集合和旧调用路径保持不变。

上述修复未修改 `docs/接口文档/`、公开路由、前后端参数、请求/响应字段、状态码、Progress 或
callback 格式。
