# 知识谱系解析指定文件范围改造

## 1. 目标

为 `/llm/weaponry` 的 `params` 增加可选 `filePathList`：

- 缺省或空数组时，保持原有全类别文档解析行为。
- 非空时，只允许选中文件参与 INPUT 和 TABLE 的向量检索、模型抽取及回调溯源。
- 元素兼容完整下载 URL和裸哈希文件名。
- 任意文件不存在或不属于当前类别时，整个请求同步失败。

## 2. 参数标准化

服务端对每个列表元素执行：

1. 校验为非空字符串。
2. 去除 URL query 和 fragment。
3. URL 解码路径。
4. 提取路径末尾文件名。
5. 按文件名大小写不敏感去重，并保留第一次出现的顺序。

该过程不下载 URL。任务库仍保存前端提交的原始请求，标准化后的哈希文件名只作为本次后台任务的内部参数。

## 3. 同步校验

路由在创建任务前逐项查询 `documents` 表：

- 未找到 `file_name`：返回 404。
- `documents.architecture_id` 与请求 `architectureId` 不一致：返回 400。
- 校验全部通过后才创建任务并启动后台线程。

后台任务会再次按类别和选中文件名收敛文档记录，防止任务执行前数据状态变化导致越界检索。

## 4. 临时 workspace 隔离

AnythingLLM `/vector-search` 不支持按 document ID 过滤，并且 `topN` 在过滤前生效。因此非空选择不能在原类别 workspace 检索后再做本地过滤，否则未选文件可能占满召回结果。

非空选择采用以下流程：

```text
documents 选中记录
  -> 提取 doc_path（缺失时以 anything_doc_id 构造回退路径）
  -> 创建唯一任务级 RAG workspace
  -> update-embeddings 只引用选中文档
  -> 创建临时 Thread
  -> 构建只包含选中文档的 WeaponryRetrievalContext
  -> INPUT/TABLE 检索与抽取
  -> 删除 Thread 和临时 workspace
```

原类别 workspace 不做文档增删，因此不会影响其他读取该类别知识库的业务。

## 5. 清理与失败处理

- 临时 workspace 创建、文档引用或 Thread 创建失败时，任务按 weaponry 失败协议回调。
- `finally` 负责恢复可能临时移动的术语文档、删除 Thread 和删除临时 workspace。
- 清理失败只记录告警，不覆盖已经生成的业务结果。

## 6. 验证范围

离线 Mock 覆盖：

- URL、裸哈希名、query、fragment、去重和原始请求持久化。
- 缺省/空数组的全类别兼容行为。
- 非法类型、未解析文件和跨类别文件。
- 选中文档顺序及检索上下文收敛。
- 临时 workspace 仅绑定选中文档并在任务结束后删除。

不启动 `run.py`，不执行依赖 AnythingLLM 等后台服务的测试。
