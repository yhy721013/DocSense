# 知识谱系解析回调来源详情改造

> 2026-07-18 修订：本记录最初采用的 Chunk 数量/字符截断已被阶段 1D 全面审查决策取代。
> 当前口径为：所有通过来源、相关性、正文质量和同文档精确去重门禁的 Evidence 完整进入
> Prompt 与 `rows`，不设置单条、总量或单文档数量/字符配额。以下内容已按现行口径同步。

## 1. 目标

调整 `/llm/weaponry` 成功回调中 `analyseDataSource` 的文件与 Chunk 溯源结构：

- `source` 返回 `documents.original_name` 文件原名。
- `fileName` 返回 `documents.file_name` 哈希文件名。
- `rows` 返回实际提交给模型完成本次抽取的 Chunk 正文列表。
- `content`、`time`、`translate` 保持现有语义。

当前运行配置使用 `WEAPONRY_ANALYSE_MODE=2`；已废弃的模式 1 不在本次兼容范围。历史任务结果不迁移，`/llm/check-task` 补发历史任务时仍会原样使用已持久化的旧 payload。

## 2. 数据来源

文件解析成功后，`documents` 表已经保存以下信息：

```text
file_name      -> 哈希后的业务文件名
original_name  -> 用户可读的文件原名
doc_path       -> AnythingLLM 文档路径
anything_doc_id -> AnythingLLM 文档 ID
```

weaponry 检索上下文同时建立上述来源别名到 `original_name` 和 `file_name` 的映射，兼容向量检索 metadata 返回文件名、文档路径或文档 ID 的情况。只有一份目标文档且 Chunk 缺少来源 metadata 时，使用该文档作为回退。

## 3. Chunk 口径

`rows` 采用 Evidence 规范化与质量门禁后的输出，即：

- 已去除 `<document_metadata>` 前缀。
- 不截断单条正文，不限制全部 Evidence 总字符数或单文档贡献量。
- 与实际构造模型 Prompt 的 Chunk 内容一致。

未实际进入 Prompt 的向量召回候选不进入 `rows`。只有模型从该文件提取出有效结果时，才为该文件生成正式来源对象。

## 4. 处理链路

### INPUT 模式 2

```text
vector-search
  -> 按内部来源文件聚合 Chunk
  -> 保留通过门禁的完整 Prompt Evidence
  -> 模型按文件抽取
  -> 解析文件原名和哈希文件名
  -> analyseDataSource { source, fileName, rows }
```

### TABLE

TABLE 同样按文件聚合并限制 Chunk。模型生成的数据行在跨文件合并时，每个非空单元格的来源对象会继续携带对应文件的 `source`、`fileName` 和 `rows`。相同内容、文件和 Chunk 组合会去重。

## 5. 空来源约定

接口沿用“无来源时返回一个空内容对象”的既有约定，并补齐新字段：

```json
{
  "content": "",
  "source": "",
  "time": "解析时间",
  "fileName": "",
  "rows": [],
  "translate": ""
}
```
