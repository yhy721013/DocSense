## 2. 已修复问题

### 2.1 恢复授权与终态保护

1. `recovery_required` Operation 保存进入隔离时的 fencing。只有过期接管取得更大的 fencing 后，
   才能使用恢复授权离开隔离；原 owner 不能仅设置 `recovery_authorized=True` 继续执行。
2. 已知失败 Step 保存最后一次尝试的 fencing。重试必须使用更大的 fencing，并清除旧
   `probe_outcome`，避免把上一轮探测事实误用于新尝试。
3. 已进入 `succeeded`、`failed` 或 `compensated` 的 Operation 禁止续租和启动新 Step。
4. 通用状态转换禁止进入任何释放文档保护的终态。成功只能由本地 CAS 专用入口完成；失败与
   补偿终态等待 1E-5 的专用事实校验入口，不能提前用通用转换绕过证据。

### 2.2 成功事实与步骤一致性

1. 远端文档的本地成功提交必须已经持久化目标 workspace 引用与创建归属，并确认目标准备和
   目标挂载；存在来源 workspace 映射时还必须确认源解绑。
2. 本地-only 文档不得伪造远端步骤，三个远端前向 Step 必须保持 `pending`。
3. `ReassignmentStepCompletion.next_state` 只接受强类型枚举；状态与探测结论使用确定矩阵：
   成功对应已确认有/无副作用，已知失败对应确认无副作用，结果未知对应未知探测。
4. SQLite 与严格 Fake 对重复 Operation ID、目标 ArchitectureId 的 SQLite INTEGER 投影、
   stale lease 和冲突结果使用相同的内部异常/结果语义。

### 2.3 恢复扫描、审计与无副作用探测

1. Repository 增加只读 UoW；SQLite 只读事务使用 `BEGIN`，不使用 `BEGIN IMMEDIATE` 抢占写锁。
2. 恢复扫描使用显式 `1..500` 上限和 `(lease_expires_at, operation_id)` 稳定游标，只返回已过期且
   仍持有保护的 Operation，为后续多实例分片扫描保留确定顺序。
3. 审计事件补充 fencing、尝试次数、探测结论、操作者摘要和原因码；原始 owner/token 不落审计。
4. Knowledge Port 增加无副作用的目标 workspace 查回结果，区分存在、不存在和结果未知，
   用于 1E-3 处理“远端创建完成但本地检查点未提交”的崩溃窗口。

### 2.4 线程隔离与数据库升级

1. 严格 Fake 的事务活动状态改为线程本地上下文；一个线程的 UoW 不会把另一线程的正常外部调用
   误判为“事务内网络 I/O”。Fake 与 SQLite 都明确拒绝同线程嵌套 UoW，避免 `RLock` 掩盖非法
   事务边界或等待 SQLite busy timeout。
2. 早期 1E-2 开发库以加列方式增加恢复 fencing、步骤 fencing 和审计列，并对已有现场执行保守
   回填；不删除或重建 Operation/Step/Event。
3. 活动文档部分唯一索引的状态谓词在初始化时与当前领域集合比较。谓词过期时在同一事务内重建；
   若历史数据违反新唯一约束则明确启动失败，不静默削弱并发隔离。
4. 当数据库已经存在 `reassign_operations` 时，`DatabaseService` 的旧 `documents` 表重建流程
   必须停止并要求协调迁移，防止冻结的 `documents.id` 和外键事实失配；不涉及 reassign 的旧表
   仍按原兼容路径迁移并保留已有 ID。
5. `busy_timeout_seconds` 在进入 SQLite `PRAGMA` 前拒绝 NaN/Infinity 等非有限值，避免泄漏底层
   转换异常。

## 5. 后续硬边界

1. 1E-3 才实现请求级 AnythingLLM Transport、有限单次 HTTP 超时、内部总预算、补偿预留和真实
   workspace 探测；任何网络调用都不得进入 Repository UoW。
2. 1E-4 的成功路径必须复用本波次的步骤事实和专用本地 CAS 入口，不得另建无检查点捷径。
3. 1E-5 必须为失败、补偿完成和恢复待处理提供专用事实校验入口，并实现有界接管、探测和反向补偿；
   本波次的扫描 Port 不是生产恢复调度器。
4. 1E-6 在再次确认接口文档不变后才能接入 Container、Parser → Application → Presenter 和公开路由。
5. SQLite 的短事务和部分唯一索引是当前单库事实边界，不等于跨数据库分布式事务。后续多实例、
   可靠队列和数据库升级必须继续依赖 fencing、条件写、稳定扫描和显式迁移治理。
