## 2. 已完成的改造

### 2.1 显式恢复与 fencing 接管

1. 新增 `RecoverReassignmentOperation` 和 `RecoverReassignmentCommand`。命令必须同时给出精确
   `operation_id`、预期 fencing token、操作者和原因码；恢复器不会接受“扫描后批量重试”或无审计
   主体的写操作。
2. 恢复器只尝试接管已过期的活动 Operation。接管在短 SQLite 事务内递增 fencing，并把匹配的
   活动 workspace preparation claim 转为新 owner/token/fencing；旧 owner、旧 token 和旧 fencing
   无法再写检查点或释放 claim。
3. 恢复服务不创建线程、不登记内存队列、不启动后台扫描器。未来 Dispatcher/可靠队列只可复用这一
   Application Service，不能绕开它直接修改 Operation。
4. 空 `doc_path` 的 local-only 路径不会构造 Knowledge Port；严格 Fake 覆盖了这一无网络边界。

### 2.2 恢复观测和终态原子收口

1. SQLite 加法创建 `reassign_recovery_observations`。表只保存脱敏的本地提交结论、两侧成员关系
   枚举、操作者摘要和原因码，并使用追加式触发器保护历史；不会保存文件路径、token 或供应商正文。
2. 新增恢复观测记录与终态专用 Repository 请求。成功、无副作用失败和补偿完成都必须引用当前
   fencing 下最新的一条观测，Adapter 会再次核对本地权威行与远端成员关系。
3. 恢复成功额外复用正常本地 CAS 的前向事实门禁：target workspace mapping、prepare Step、目标挂载
   Step 以及需要时的来源解绑 Step 不完整时，即使一次远端探测看似一致，也不能伪造 `succeeded`。
4. 终态更新与已接管 claim 的精确释放在同一 SQLite 事务内提交。旧观测、旧 fencing、旧 claim 或
   中途本地文档变更会拒绝收口并继续保持文档保护。

### 2.3 写后检查点和补偿策略

1. 恢复器在 UoW 外探测冻结本地行、已持久化 target slug（或确定性名称）及来源/目标完整
   `doc_path` 成员关系；严格 Fake 拒绝任何事务内网络调用。
2. 覆盖来源解绑、目标 workspace 准备、目标挂载、本地提交、目标解绑补偿和来源恢复补偿的
   “HTTP 已返回、检查点未提交”窗口。下一次恢复仅在探测明确满足目标状态时补齐对应 Step，
   不会盲目重发外部写。
3. 补偿顺序固定为先删除目标绑定、后恢复来源绑定。首次补偿外部写前，`running`/`recovery_required`
   会先持久化进入 `compensating`；目标解绑失败或结果未知时不继续恢复来源，避免双绑定。
4. workspace 被视为永久资源。创建后 mapping 检查点丢失时，只补记准确 slug 和三态归属；不会删除
   workspace，也不会创建第二个 workspace 猜测现场。

### 2.4 默认只读诊断脚本

新增 `scripts/inspect_reassign_operations.py`：

1. 默认 dry-run 以 `SQLiteReassignmentRepository(..., initialize_schema=False)` 打开**既有**数据库，
   有界列出过期可恢复 Operation；不执行 DDL、不写事件或状态、不读取 AnythingLLM 配置、不创建
   HTTP Client。
2. `--apply` 只能恢复单个 Operation，且必须显式提供 `--operation-id`、
   `--expected-fencing-token`、`--actor`、`--reason-code`、`--lease-owner` 和
   `--lease-duration-seconds`。参数不完整会在构造恢复服务前拒绝。
3. 机器可读结果通过显式 stdout JSON 输出，运行日志仍使用 logging；没有遗留 `print()` 调用，
   符合项目静态运行时代码门禁。

## 5. 剩余边界与后续约束

1. 1E-6 只有在再次确认接口文档保持不变、公开黄金测试通过后，才能由 Container 装配执行设置、
   SQLite Repository 和 Knowledge Factory，并将 `/llm/reassign` 切换为
   Parser → Application → Presenter。
2. 当前恢复是显式人工入口，不是可靠任务队列、自动 reaper 或多实例调度器；不得把它误述为已经
   完成后台任务隔离或自动恢复治理。
3. SQLite lease/fencing 只保护当前单库事实和精确 Operation 写入权，不能替代跨数据库一致性、
   供应商幂等协议或生产级高并发容量证明。
4. 在随机隔离 workspace、测试文档、真实 AnythingLLM 故障注入和生产预算校准完成前，不得标记
   production ready。
