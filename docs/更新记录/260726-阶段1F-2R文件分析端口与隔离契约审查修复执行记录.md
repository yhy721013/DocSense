## 1. 修复结论

本轮把“类型存在但仍可能误用”的内部边界收紧为可支持后续任务隔离、恢复和多实例演进的明确
契约。生产 Blueprint 仍走原执行链，所有新 Analysis Web Adapter、Port 与 Codec 继续保持未接线。

### 1.1 RAG 与审计证据链

- RAG 改为显式打开、查询、关闭任务级 Session；打开结果、失败现场和关闭结果携带严格排序的
  生命周期事件，并区分 confirmed、known-not-applied 与 outcome-unknown。
- 领域召回审计改为 reserve/finalize 两步，确保创建远端资源前已有本地事实。
- 模型交互一次原子保存 Prompt、全部 attempt、原始响应、来源和初始生命周期；关闭与清理事件
  只能按持久 Receipt 幂等追加。
- 按 execution 与幂等键联合读取交互审计，消除仅凭全局字符串跨任务串读的可能。

### 1.2 资源、Callback 与结果不变量

- Resource 推进显式携带 expected state/version；创建、推进和恢复延期均要求版本可判定，延期记录
  同时保存下次时间与原因。
- Callback 明确 acquire、wait、deliver、complete 和过期冻结；Acquire 结果本身绑定 execution，
  网络发送必须持有 token/version lease，等待参数拒绝 NaN/Infinity。
- 外部写、关闭和 Callback 的非成功结果必须携带内部 detail code；翻译成功必须包含两个非空展示
  结果，空字符串按可降级失败记录，不能伪装成成功。
- batch sequence 在 Execution、持久任务输入和批量结果三个边界统一限制为 1～32。

### 1.3 Codec、Parser 与不可变快照

- JSON Codec 使用 `object_pairs_hook` 拒绝 envelope 或任意嵌套对象的重复键，避免解析器差异造成
  持久任务歧义。
- Worker 解码重新执行受理快照范围校验；默认化后必须非空的 country/format/maturity/security/
  architectureList 若被篡改为空，将 fail closed。
- Web Parser 只捕获已知 `AnalysisContractError` 并映射为既有 400；意外 `RuntimeError` 不再被误报为
  调用方错误。冻结请求只创建一次，Parser、Batch Command 与 Submission 复用同一不可变对象。
- Flask Adapter 包入口不再传递导入未接线 Analysis 模块，生产 Blueprint 的直接和传递依赖均保持
  隔离。

### 1.4 严格 Fake 与并发证明

- Fake 支持全局顺序脚本和按 execution 的独立线程安全队列；不同任务可任意交错，同一任务仍保持
  严格副作用顺序。
- 文件、RAG、知识、审计、翻译、资源和 Callback 的每个返回 DTO 都重新核对 execution；RAG 额外
  核对 session/operation，审计核对 Receipt/幂等键。
- 新增 50 个并发任务脚本测试，并补充跨 execution 错投、重复 JSON 键、损坏范围、空翻译、意外
  Parser 异常和未接线传递导入门禁。

## 4. 后续阶段硬门禁

1. 1F-3 Application 必须先持久化召回 reserve 和资源 tracking，再创建任何远端 RAG 资源。
2. 审计 Receipt 未成功返回时，不得永久入库、成功终态或清理审计现场。
3. Callback outcome unknown 与资源 outcome unknown 均不得盲目重发；恢复器必须依据持久事实判定。
4. 真实 Adapter 必须实现 state+version CAS、幂等 lifecycle append 和 execution 关联校验，不能只满足
   Protocol 的方法签名。
5. 后续若需要修改公开路由、参数、响应、状态码、Progress 或 callback，仍须先确认并同步接口文档；
   禁止增删前后端接口参数。
