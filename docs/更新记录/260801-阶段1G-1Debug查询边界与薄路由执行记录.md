## 1. 实施结果

1. 新建 `app/modules/debug/`，形成不可变结果、只读 Port、文件/SQLite Adapter、Query 和无 Flask
   组合根。
2. Callback Application 统一收敛空目录、指定记录缺失、读取失败、编码失败、非法 JSON 和非对象
   JSON；Adapter 保留 50 条限制、稳定倒序、路径穿越防护及删除竞态容忍。
3. Chat Adapter 只读本地 Session、Active Scope、当前 binding 和知识库文件快照，过滤 deleted 会话，
   严格投影 JavaScript 安全 `chatId`，不发起 AnythingLLM 请求。
4. `app/presenters/debug.py` 成为 Debug JSON 唯一投影点，聚合计数仅写脱敏日志，不进入响应。
5. `app/blueprints/debug.py` 只读取 `record` 查询参数、调用 Query/Presenter 或渲染模板；已经不导入
   Preview、`DatabaseService`、`ChatPersistenceStore`、`Path`、SQLite、线程或 AnythingLLM。
6. 两个旧 Preview 文件保留为薄兼容 Facade，只构造新 Adapter/Query/Presenter，并记录
   `compatibility_path=true`；其中不再保留第二份读取算法。
7. `ApplicationServices` 显式持有 `DebugApplicationServices`，生产、离线和既有测试容器均完成装配。

## 2. 可靠性、并发与日志边界

- Query 和结果使用冻结 dataclass/tuple；同一 Chat Query 的 50 次并发 Fake 读取无共享列表和跨请求污染；
- Callback 文件读取只在 Adapter 中发生，Application 和 Blueprint 均不可见绝对路径；
- INFO 只记录状态和数量，WARNING 只记录恢复类别，ERROR 只记录阶段和异常类型；
- 日志不记录 Callback payload、文件名列表、消息正文、外部 document/workspace/thread 引用或凭据；
- Chat Debug 失败响应为了逐字段保持既有内部调试行为，仍保留 `读取失败: <异常文本>`；本波次未把
  脱敏策略变更混入结构迁移。
