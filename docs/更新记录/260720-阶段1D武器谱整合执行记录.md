## 3. 最终实现事实

### 3.1 检索、证据与抽取

1. Retrieval Query 与最终 Extraction Prompt 是不同类型；字段说明进入正确阶段，抽取指令不得污染召回 Query。
2. Evidence Selection 保留完整候选证据，使用合法 score 或稳定 rank 做确定性选择，不把未经证明的绝对阈值伪装为生产门禁。
3. INPUT 与 TABLE 具有独立纯规则；TABLE 行身份和重复列边界失败关闭，来源规则不依赖共享父会话。
4. 每个来源只消费当前文档的最终 Selected Evidence；Provider 原始结构先在 Adapter 边界规范化。
5. 文档身份使用完整、规范化位置；仅文件名相同不能证明同一远端文档。

### 3.2 任务、审计与外部资源

1. 请求在受理时冻结文档范围、策略和 Schema v2 快照；Worker 只按 TaskId 恢复执行。
2. Retrieval、Extraction、辅助语境、Translation、Audit、Callback、Resource 和 Dispatcher 均通过 Port 隔离。
3. 外部资源创建前先持久化 Creation Intent；崩溃后只能精确查回或隔离，禁止盲目再次创建。
4. 清理意图必须先于远端删除持久化；409 或连接中断等未知副作用进入 outcome unknown。
5. Callback 正常发送和 check-task 同步恢复共用持久 Guard；旧任务、过期 lease 和 fencing 不匹配均不得外发。

### 3.3 运行与配置

1. Report 与 Weaponry 共用业务无关的本地持久扫描内核，但保留各自的业务 Application、配置、资源和恢复策略。
2. Weaponry 使用单执行 Worker 和独立维护线程；公平限流避免一个来源长期占用共享许可。
3. 严格配置只冻结已验证的内部策略，不把离线校准值冒充生产供应商能力。
4. 当前单实例锁和 SQLite 事实只支持本地恢复；可靠队列、跨实例 fencing 与共享容量控制尚未实现。

## 4. 关键审查修正

- 修正校准资产中的正负例和字段真值；确认原始 score 在代表性不足的语料上不可单独形成生产阈值。
- Evidence 不截断；ArchitectureId 使用唯一规范化规则；成功终态必须具备完整结果事实。
- Audit reserve 区分首次、pending 和 completed，慢 I/O 前再次复核 latest。
- 供应商创建、绑定和删除的未知结果一律保守处理；资源恢复不得用名称前缀推断所有权。
- 外部 HTTP 租约覆盖连接、读取和安全余量；超时未知不能当成明确失败重试。
- production attestation v2 绑定供应商版本、配置、语料和资源指纹；失效后不得继续标记 ready。
- 人工处置必须走可审计命令和 CAS，不允许直接修改 SQLite 绕过活跃任务或 fencing。

## 5. 验证证据

最终审查后的历史证据包括：

- Weaponry 相关测试 251 项通过；
- Stage 1D 资产测试 40 项通过；
- 门禁、运维、容器、Dispatcher 与生产 Adapter 定向测试 80 项通过；
- 安全全仓动态发现 1,181 项，精确排除 13 项环境/平台测试后执行 1,168 项；按稳定测试 ID 分为两个 584 项批次，失败 0、错误 0、跳过 0。

一次单命令全仓运行因 120 秒工具上限在结果输出前终止，因此不计为通过；随后等价分批覆盖了同一执行集合。以上是 Windows、SQLite 单实例、Fake/受控 Transport 和有限只读协议核验，不是生产 E2E 或容量结论。

## 6. 当前与未来边界

- production attestation 具有时效性；四类生产指纹未冻结或失效时，readiness 必须为 false。
- 真实 AnythingLLM 多文档语料、模型抽取质量、生产限流和故障恢复仍需明确维护窗口验收。
- 进程内 FIFO 和 limiter 不是跨实例全局公平；阶段 2 以后需统一 Task Attempt、checkpoint、Reaper、可靠队列和数据库 fencing。
- Callback 网络结果未知仍可能造成接收方重复观测，接收方必须使用业务幂等键。
