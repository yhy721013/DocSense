## 1. 实施结果

1. 新增 `app/blueprints/dependencies.py`，成为唯一读取 Flask `current_app.extensions` 的容器访问
   Adapter；容器缺失或类型错误均明确失败，不创建全局单例或临时生产依赖。
2. `app/container.py` 删除 Flask 导入和 `get_application_services()`，`ApplicationServices` 注释与
   AST 均明确为框架无关依赖集合。
3. `llm.py`、`debug.py` 统一从 Flask 依赖 Adapter 获取容器，既有局部测试 patch 符号保持稳定。
4. 保留 `APPLICATION_SERVICES_EXTENSION`、`create_application_services()` 和 `create_app()` 的命名与
   生命周期：显式注入容器不 start、不注册 close；生产自建容器 start 一次并注册 close 一次；
   start 失败仍 close 后重新抛出。
5. `DebugApplicationServices` 为 `ApplicationServices` 的严格必填字段，仓库中 4 个实际构造点均
   显式装配；没有通过默认值、全局补丁或网络依赖掩盖缺失能力。
6. 增加永久 `FRAMEWORK_FREE_CONTAINER_RULE`，阻止 Flask、Werkzeug、FastAPI、Starlette 或动态
   Web 框架导入重新进入生产组合根，并提供可失败自测。
