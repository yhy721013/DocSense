# 阶段 1H 共享文档处理整合执行记录

## 1. 整合说明

本文整合阶段 1H-0～1H-7 及关闭后全面审查。它记录 DocumentProcessing、Artifact 和 Translation 从重复业务实现收口为共享模块的实际过程；Legacy Office 分支集成的 Git/平台验收另见对应整合记录。

- 阶段状态：共享处理内核和业务调用方单路径切换已完成。
- 公开契约：未增删任何接口参数、响应字段、状态码、Progress 或 Callback 合同。
- 证据边界：主要为 Windows、临时 SQLite/Fake 和受控工具；平台能力跳过项单独保留。

## 3. 最终实现事实

### 3.1 共享处理内核

1. `Artifact`、`Profile`、`Lineage` 是不可变内部契约；幂等键由内容、处理 Profile 和实现指纹稳定生成。
2. Application 只依赖文件读取、Processor、Artifact Store、Processing Record 和资源许可 Port，不依赖具体业务路由。
3. Artifact 先写临时文件，再进行完整性校验和原子发布；只有数据库成功事实拥有最终 Artifact。
4. Processing Record 显式表达 pending、succeeded、failed 和 outcome_unknown；未知结果必须先对账。

### 3.2 格式处理与外部副作用

1. Legacy Office、MHTML、MinerU、OCR 和通用格式各有独立 Processor，但共享 Artifact、Profile、资源和审计边界。
2. LibreOffice/OOXML 只保留一套安全内核；兼容 Facade 不得复制转换逻辑。
3. MinerU 外部提交先持久化意图和供应商身份；超时未知不能直接重提。
4. MHTML 浏览器调用保留既定固定参数和任务级工作目录；只有明确失败才允许受控降级。
5. 重型任务使用进程内有界许可和 FIFO；这不是跨实例全局容量控制。

### 3.3 Translation 与业务接线

1. Translation 只接收 prepared Artifact，不再自行重复解析或管理业务临时文件。
2. HYMT、Argos、Ollama 和 Renderer 位于 Translation Adapter；引擎锁只覆盖单次实例调用。
3. Renderer 按表示类型保留 Markdown 标题、列表、表格、链接和图片；失败单元保留原文，不把异常结果标记为成功。
4. Analysis、Report、Weaponry 和工具入口均切换为统一处理路径，同一请求中不存在新旧双执行。

## 4. 关键审查修正

- 修复 PDF 降级类型漂移，确保降级结果与 Profile/Lineage 一致。
- 富 Markdown 和图片资源跟随 Artifact 生命周期，不引用已清理的临时目录。
- MinerU Processor 只接受恰好一个 Markdown 主结果；结果目录所有权和清理责任明确。
- Processing Record 的未知状态不允许被缓存命中或兼容 Facade伪装为成功。
- Profile 和日志移除敏感路径/配置，只记录稳定指纹、格式、任务标识和脱敏错误。
- 增加 Artifact Catalog、读租约、锁回收和有界容量，降低单实例长运行泄漏风险。

## 5. 验证证据

关闭后最终历史记录：

- 分波次门禁均通过，R5 为 86 项成功、2 项平台能力跳过；
- 最终架构/内核门禁 23 项通过；
- 安全全仓动态发现 2,145 项，精确排除 13 项后执行 2,132 项；成功 2,129 项、失败 0、错误 0、跳过 3。

三个跳过项为平台能力门禁，不是本轮功能失败。以上结果不证明真实 MinerU/OCR/翻译模型容量、多实例全局限流或对象存储一致性。

## 6. 当前与未来边界

- accepted 事务尚需在后续 Task Input Schema 中冻结完整 OCR、MinerU、Renderer、Translation Engine 与依赖指纹。
- 当前 Artifact Store 仍是本地文件系统；MinIO、共享 Catalog、跨实例 GC 和数据库一致性属于后续阶段。
- 进程内缓存、读租约和许可不提供跨实例协调；多实例前必须引入共享所有权和 fencing。
- 兼容源码和遗留测试的物理删除由阶段 1G 的价值迁移与引用门禁负责，不在 1H 中直接删除。
