## 2. 冻结的合同事实

- `architectureId` 与 `fileNames` 按字段存在性严格互斥；
- `architectureId` 已出现但值为 `null` 时返回 `architectureId不能为空`；
- 两个选择器字段都未出现时保持既有 fileNames 合同，返回 `fileNames必须为数组`；
- 首轮只冻结精确类别的直接文件，后续同 ID 只复用 Scope Head；
- 同一会话的范围模式和规范化 architecture ID 永久不可变；
- architecture user history 只返回 JSON number `architectureId`，file user 继续只返回
  `files`，assistant 不返回范围字段；
- SSE 事件、成功 Content-Type 和单字段错误体保持不变；
- 既有 `chat_scope_state_machine.json` 以 SHA-256
  `97C4D99DBEBD1F73E85B006B831B135A0594F21582111348E545D88380910611`
  做字节级冻结。

黄金测试只读取静态资产，不调用尚未切换的生产路由，因此不会以长期红测阻塞阶段 1～4。
