## 3. 最终实现效果

1. `architectureId` 与 `fileNames` 按字段存在性严格互斥；ID 复用既有 64 位正整数规范化；
2. architecture 首轮精确读取直接文件并冻结有序成员/文档引用；后续每轮携带同 ID 但只复用
   原 Scope Head；
3. chatId 的范围模式和 architecture ID 由不可变 Session Binding 永久绑定；
4. Binding、Scope Revision/Head、run、run input 和 pending user message 在一个
   `BEGIN IMMEDIATE` 事务内提交，失败整体回滚；
5. Worker 只按 `run_id` 恢复 Effective Scope，远端 Workspace 的额外文档和当前类别变化均不能
   扩大模型范围；
6. architecture user history 只有 JSON number `architectureId`、没有 `files`；assistant
   二者均无；file history 保持原合同；
7. 文档绑定租约继续使用原持久化身份做幂等，但日志只输出 SHA-256 短 `lease_token`，不暴露
   文件名、document ref、外部位置或消息正文。
