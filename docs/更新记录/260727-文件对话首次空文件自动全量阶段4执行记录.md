## 2. 执行链核对

`SynchronousChatRunExecutor` 当前已经具备阶段 4 要求：

1. `execute_chat_run(run_id)` 只读取持久化 run 与 `chat_run_inputs`；
2. `_request_from_persisted_input()` 从不可变输入重建文档快照，不重新访问知识库 Resolver；
3. 自动文件和显式文件统一进入 `_attach_new_documents()`；
4. 新版本统一创建 document-binding resource lease、调用任务级 Chat Port 的
   `attach_documents()`、追加 binding revision 并更新 current head；
5. 模型流统一调用 `stream_message(..., document_refs=active_documents)`；
6. 运行终态统一提交本地 pending user 和 assistant 消息，历史接口只读取本地 committed 消息；
7. 无本轮新文档时直接选择既有 current heads，不调用 `attach_documents()`。

因此本阶段没有修改生产执行器。这样既避免出现第二条自动文件远端流程，也避免把候选来源
泄漏给 AnythingLLM Port、SSE 或历史展示层。

## 3. 严格 Fake 补强

`FakeChatConversationPort` 新增每个请求级实例独立保存的只读测试轨迹：

- `attach_document_calls`
- `stream_message_calls`

轨迹记录不可变的会话、文档和 document refs 快照，只用于离线断言。Factory 仍然为每次执行
创建新的 Port；不同请求不会共用 Port 实例或可变网络 Session。

## 4. 新增验收场景

### 4.1 自动与显式文件同链等价

分别以相同两份文件执行显式请求和首次空数组请求，并断言：

- 两者都只创建一个任务级 Chat Port；
- attach 文件顺序和 document refs 相同；
- 模型流接收的 document refs 相同；
- workspace、thread 和 document-binding 租约类型与状态相同；
- current binding heads 相同；
- 首轮 committed user 历史中的原始文件名与顺序相同；
- 均产生既有 `chatInfo/textChunk/done` 事件，`isNewChat=true`。

### 4.2 受理快照不受目录后续变化影响

首次空数组受理完成后修改 Resolver 的全量候选，再执行已受理运行。实际 attach、模型引用与
binding 仍只包含受理时冻结的文件，证明执行阶段没有重新查询知识库。

### 4.3 后续空数组只复用 current heads

首次自动全量执行完成后向知识库新增文件，再使用相同 `chatId` 发送空数组：

- 不再次调用全量 Resolver；
- run input 的本轮新增文件为空；
- 不调用 `attach_documents()`；
- 模型继续引用既有 current heads；
- 新增知识库文件不进入 binding；
- `isNewChat=false`；
- 后续 user 历史的 `files` 为空，不伪装成本轮新增附件。

### 4.4 空知识库自由对话

首次全量候选为空时：

- 不调用 `attach_documents()`；
- 模型流的 document refs 为空；
- 仍正常产生 `chatInfo/textChunk/done`；
- 只创建 workspace/thread 租约；
- 首轮历史文件列表为空。

### 4.5 公开路由与历史

公开 `/llm/chat` 路由测试进一步断言自动选择文件：

- 只创建一个任务级 Chat Port；
- attach 和模型检索引用按稳定顺序传递；
- resource lease 全部激活；
- `/llm/chat/history` 按冻结顺序返回原始文件名；
- SSE `isNewChat` 语义没有被改成“是否自动全量”。
