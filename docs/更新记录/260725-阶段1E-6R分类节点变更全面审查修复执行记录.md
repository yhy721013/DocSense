# 阶段 1E-6R：分类节点变更全面审查修复执行记录

## 1. 范围与契约

本轮修复阶段 1E-0～1E-6 全面审查发现的同步补偿、ArchitectureId 存储投影、SQLite 删除一致性、
运行模式保护、领域结果不变量、故障资产消费和恢复结构治理问题。

经负责人确认，本轮允许同步 `docs/接口文档/分类节点变更.md` 的兼容边界与五类稳定失败文案；没有
增删或改名请求参数、响应字段、HTTP 状态码、Header，也没有改变同步接口语义。内部 Operation、
lease、fencing、Step 和恢复事实仍禁止出现在公开响应中。

## 2. 已完成修复

### 2.1 有界同步补偿

- 目标 workspace 准备明确失败、目标挂载明确失败和远端成功后的本地 CAS 冲突，会在同一请求级
  Knowledge Port 与有限 deadline 内执行补偿；固定顺序仍是先解绑目标、后恢复来源。
- 每笔补偿在外部写前保存意图、写后保存四分类结果；结果未知、检查点冲突、预算耗尽或本地状态
  无法证明时立即保留 `recovery_required`，不盲目重放。
- 补偿完成、补偿明确失败和仍待恢复分别返回已经批准的稳定 message；结果类别与公开 message
  在领域模型中形成合法组合矩阵，非法组合构造时 fail-fast。

### 2.2 ArchitectureId 有限兼容白名单

- `newArchitectureId` 只保留已经冻结的 JSON `false`、有符号 64 位整数和十进制整数字符串兼容。
- `true`、浮点数、小数/科学计数法字符串、非数字文本、对象、数组和越界整数在创建 Operation、
  申请 workspace claim 或执行任何远端副作用前拒绝。
- 继续保留原始值比较与公开响应回显，不把 `1`、`"1"` 和 `false` 合并为同一个请求值。

### 2.3 SQLite 审计历史与删除一致性

- `reassign_operations.document_row_id` 改为独立审计快照字段，不再以外键依附可删除的
  `documents` 当前行；加法初始化会原子迁移早期 1E 开发库的错误外键，并完整保留 Operation、
  Step、Event 和索引。
- `DatabaseService` 的 SQLite 连接统一启用外键检查。按文件名和按 workspace/location 删除文档前，
  先以 `BEGIN IMMEDIATE` 取得写锁，再在同一事务内检查活动 Operation 并删除，关闭 TOCTOU 窗口。
- `reserved`、`running`、`compensating`、`recovery_required` 阻止删除；终态 Operation 保留审计历史，
  但不阻止业务文档按正常流程删除。

### 2.4 单实例运行门禁与故障资产

- 新增内部 `DOCSENSE_REASSIGN_RUNTIME_MODE`，当前只允许 `single_instance`。SQLite lease 仍使用进程
  本地时钟，配置为集群模式会在 Container 装配前 fail-fast。
- `approvedTargetFaultMatrix` 的 8 个场景全部绑定到实际可执行测试，不再只是未消费的 JSON 描述。
- 增加旧外键迁移、删除事务写锁、目标 ID 白名单、同步补偿、补偿失败和结果/message 不变量回归。

## 3. 恢复结构与未来计划修正

全面审查确认 `recover_reassignment.py` 中 Observer、Checkpoint Reconciler、Compensator、Finalizer
当前主要是 callback 职责接缝，实际算法仍集中在大型 Facade。为避免在功能修复中同时进行高风险搬迁，
本轮纠正了“职责拆分已经完成”的过度表述，并新增 1E-7 前置阶段：

- 将四类实际逻辑下沉到独立文件和最小 Port 依赖；
- 禁止仅转发 Facade 绑定方法的 callback wrapper 被计为完成；
- 增加协作器直接单测、callback-only AST 门禁和文件规模/复杂度基线；
- 必须在可靠任务队列或多实例恢复接入前完成，且不改变公开接口或持久化 Schema。
