# 武器谱术语目录自动上传恢复执行记录

## 1. 已实施

- 新增严格本地术语清单：只接受普通 UTF-8 `term_rule_*.md`，拒绝空文件、重复
  `card_id`、符号链接和目录越界。
- 删除人工术语目录版本配置依赖，按路径、卡片 ID 和内容自动生成版本化 SHA-256 指纹。
- 新增启动期 AnythingLLM 协调器：精确创建/复用版本化 workspace、补齐缺失卡、绑定并
  完整查回；完整代际重复启动不产生远端写入。
- 上传 metadata 携带托管类型、卡片 ID、卡片内容摘要和目录指纹；远端展示文件名同时携带
  内容摘要前缀，便于无 metadata 的 workspace 文档列表进行确定性验证。
- 新增 SQLite 目录/卡片状态事实；未知写入结果持久隔离，禁止自动重放。
- 新增按 execution 目录指纹的多代只读路由；兼容升级前人工指纹的旧任务。
- 通用本地 Dispatcher 新增获取进程锁后、启动线程前的 `startup_gate`；目录失败时释放锁，
  不启动 Worker。
- 新增 `scripts/sync_weaponry_terms_catalog.py --dry-run/--apply`，与生产启动复用同一协调器；
  `--apply` 还会取得同一 Weaponry 单实例锁，拒绝与在线服务并发写入。
- 修复武器谱目录诊断脚本在 Windows 下未及时关闭 SQLite 连接的问题，并使纯 dry-run
  延迟加载第三方依赖；PowerShell 包装脚本同时补齐项目既定 `venv` 路径识别。

## 2. 合同

未增删或修改任何公开请求、响应、Callback、Progress、Header 或状态码。接口文档只同步
内部启动期目录准备、失败语义和历史任务路由说明。

## 3. 验证边界

已使用项目 `venv` 执行静态编译及 Fake/临时 SQLite 离线测试；没有启动 `run.py`，也没有
连接真实 AnythingLLM。真实供应商上传标题、处理完成时延和大目录启动耗时仍需在隔离联调
环境验证后才能形成生产证据。当前仅支持 SQLite/文件锁单实例，不代表可靠队列或多实例安全。

安全回归共发现 1808 项测试，明确排除 13 项会启动本地服务、依赖特定 POSIX 文件权限或
仅校验本地 LLM 测试资产的用例；实际执行 1795 项，1795 项全部通过，失败 0、错误 0、
跳过 0。排除项未被计入通过数。最终自审补充 `--apply` 共享进程锁后，又执行术语目录、
启动门禁与架构边界定向回归 34 项，全部通过；实际 `terms/` 的 61 张规则卡也已完成
只读清单构建和自动指纹校验。
