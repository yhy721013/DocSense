## 3. 最终实现事实

### 3.1 持久 Saga 事实

1. Operation、Step、Event 和恢复观察均为追加/条件更新的 SQLite 事实；公开同步响应不直接暴露内部 operation_id、lease 或 fencing。
2. 文档保护、目标 workspace preparation claim 和前向步骤在短事务中取得；事务内不执行网络 I/O。
3. 每个远端动作前后都有步骤状态、预算和写后探测；只有持久事实允许时才能继续或补偿。
4. 活跃状态在 Domain 与数据库约束中保持同一集合，新增状态若未同步触发永久门禁。
5. 数据库提交确认丢失时先重读权威 Operation，不能把“响应未知”直接当成“提交失败”并错误补偿。

### 3.2 外部调用与补偿

1. AnythingLLM Client/Transport 按请求创建并关闭，不跨线程或任务共享有状态 Session。
2. 目标 workspace 以 existing、created_by_operation、ownership_unknown 三态表达，只有明确所有权才能进入删除补偿。
3. 前向步骤失败后按固定逆序补偿；外部副作用结果未知时保留 recovery_required 现场，不盲目重放或删除。
4. 预算按 Saga Step 选择并以单调 deadline 约束；同步总预算必须为补偿预留空间。
5. Pin 等非关键动作按 best-effort 审计，不得掩盖文档移动和本地 CAS 的权威结果。

### 3.3 恢复与运维

1. 显式恢复通过过期 lease 接管和新的 fencing token 获得权限；旧 owner 的条件写必须失败。
2. 恢复只从持久 Step 和探测结果继续，不依赖进程内回调、请求对象或内存缓存。
3. 诊断脚本默认只读，并用机器可判定退出码区分不存在、可恢复、需人工和读取失败。
4. 人工恢复不得直接改库绕过 Repository/UoW、lease、claim 或追加审计。

## 4. 关键审查修正

- 释放文档保护必须提供成功终态或明确无副作用证据。
- 本地 architecture 映射与远端目标绑定必须同时成立，不能只凭其中一项宣称成功。
- 补偿使用独立 Step，不覆盖前向步骤历史。
- 事务等待时间不计入可用外部 lease：lease 在真正取得事务/所有权后计算。
- Application 入口统一校验有限、非负时间输入；时钟异常时 fail-closed。
- 生产动作由步骤—动作白名单约束，禁止 Adapter 被错误步骤调用。
- SQLite 读取失败与“记录不存在”分流，防止数据库故障被误判成可新建操作。

## 6. 当前与未来边界

- 当前同步 Saga 依赖 SQLite 单实例约束；多实例启用前必须提供数据库权威时间、可取消的锁/语句截止和跨实例 fencing。
- 可靠队列、Outbox、自动 Reaper 和跨实例恢复尚未接入；同步请求超时也不能简单转成后台无界重试。
- 生产预算仍需按真实 AnythingLLM P95/P99、补偿耗时和网关超时联合校准。
- outcome unknown 必须保留现场并由有权恢复入口处理，不能为了“尽快成功”牺牲一致性。
