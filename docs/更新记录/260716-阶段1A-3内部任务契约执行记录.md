## 1. 执行结论

阶段 1A-3 已完成，并同时通过 1A-4 的当前阶段门禁。此次不是把旧实现移动到新
目录，而是先建立可由 Fake 独立证明的最小内部契约：

1. 任务执行身份与业务键分离，所有 DTO 不可变；
2. Task Read、Callback Recovery、Progress Snapshot/Subscription 成为独立 Port；
3. check-task 的副作用由应用服务显式编排，恢复后无条件只按原 TaskId 重读，并校验恢复返回值与持久化状态；
4. Progress 应用服务只返回类型化当前快照与订阅令牌，不持有 WebSocket；
5. 应用服务完全不依赖 Flask、SQLite、遗留 Task Service 或 Progress Hub；
6. 生产路由尚未切换，已批准的目标外部契约仍由波次 1B 实现。

因此，当前可以宣称“tasks 内部契约已建立并可离线测试”，不能宣称
`/llm/check-task`、`/llm/progress` 已迁移，也不能宣称系统已经具备线程安全
InMemory Hub、跨实例通知、共享数据库、可靠队列或 50 长连接能力。

## 2. 实际修改

### 2.1 领域对象

| 文件 | 实际作用 |
| --- | --- |
| `app/modules/tasks/domain/models.py` | 定义 TaskId、TaskBusinessRef、TaskSnapshot、TaskLookupItem、ProgressKey、ProgressSnapshot、ProgressSubscriptionRequest 和当前 callback 状态常量。 |
| `app/modules/tasks/domain/__init__.py` | 只导出纯领域对象，不重新导出遗留实现。 |

领域对象具有以下约束：

- 使用 frozen dataclass，运行期间不能修改；
- TaskId 只代表一次执行，不与公开业务键混用；
- TaskLookupItem 同时保存规范化内部业务引用和既有公开键值类型；
- progress 必须是有限的 0～1 比例，并按当前公共边界精度规范化；
- callback 状态只允许当前 `pending/success/failed/skipped`；
- Progress sequence 为内部非负整数，不属于 WebSocket 响应字段；
- 不接收 request、Row、任意 dict、数据库 Session、网络 Session 或回调函数。

阶段 1A-3 没有提前实现完整任务输入快照、Dispatch 信封、租约、fencing 或统一状态
迁移；这些内容仍按阶段 1C～4 和阶段 2 的门禁实施。

### 2.2 抽象端口

| 文件 | 实际作用 |
| --- | --- |
| `app/modules/tasks/ports/task_read.py` | 按 TaskId 读取、按业务引用读取最新投影、按有序引用等长批量读取并保留 None 缺失位置。 |
| `app/modules/tasks/ports/callback_recovery.py` | 按 TaskId 触发一次 check-task 显式恢复，返回 attempted、replayed、最终 callback 状态和内部 delivery outcome。 |
| `app/modules/tasks/ports/progress.py` | 定义最新进度快照读取、类型化 subscriber、订阅令牌和幂等释放协议。 |
| `app/modules/tasks/ports/__init__.py` | 汇总稳定 Port 类型，不依赖具体 Adapter。 |

Task Read 明确禁止 Callback 或 Progress 副作用。Callback Recovery 独立存在，是因为
`/llm/check-task` 不是纯查询；它可能执行外部 HTTP，也可能在未配置 Callback URL 时
把终态任务从 `pending` 收敛为 `skipped`。Progress Port 的线程安全、锁外通知和
subscriber 故障隔离要求已经写入契约。2026-07-16 审查修正已提前实现连接侧有界
缓冲、初始快照屏障和慢连接隔离；底层 InMemory Adapter 的锁外通知与并发测试仍
属于波次 1B。

### 2.3 应用服务

| 文件 | 实际作用 |
| --- | --- |
| `app/modules/tasks/application/check_status.py` | 实现有序批量任务检查、缺失保留、回调恢复、同 TaskId 无条件重读、持久化状态一致性校验和框架无关结果。 |
| `app/modules/tasks/application/progress.py` | 实现订阅建立、当前快照选择、已有令牌复用、失败补偿、连接关闭释放和框架无关结果；失败异常保留完整令牌供 Registry 重试。 |
| `app/modules/tasks/application/progress_delivery.py` | 实现连接级有界队列、初始快照屏障、按 key 合并、慢连接隔离和丢弃/合并计数。 |
| `app/modules/tasks/application/__init__.py` | 导出用例请求、结果、服务与稳定内部异常。 |

`CheckTaskStatusService` 的实际顺序为：

```text
有序业务引用批量读取
  → 缺失位置保留
  → 对存在项按 TaskId 调用 Callback Recovery
  → 无条件按同一 TaskId 重读
  → 校验恢复最终状态与持久化 callback 状态一致
  → 返回有序内部结果
```

恢复异常会记录 business type/key、TaskId 和 trace ID 后原样传播，不会被悄悄转换为
成功。批量读取长度、业务引用、重读 TaskId 或业务引用不一致时，应用服务会以端口
契约错误失败，防止错误 Adapter 造成跨任务串读。

`ProgressSubscriptionService` 的实际顺序为：

```text
复用连接 Registry 已有令牌
  → 为缺失 key 建立类型化订阅
  → 按请求顺序选择 Progress 最新值 / Task 投影 / missing
  → 返回 current items、active subscriptions、added subscriptions
```

同一帧中的重复 key 保留重复当前快照位置，但只建立一条底层订阅。建立过程中任一
Port 失败会逆序释放本次新增令牌，不影响连接原有令牌；连接关闭时遍历全部唯一令牌，
不会因一项释放失败跳过其余项。补偿或释放异常携带完整失败令牌，供 Registry 在底层
故障恢复后重试。应用服务从不调用 `ws.send`，JSON、error 消息、连接循环和 finally
Registry 清理仍归波次 1B 的 Web Adapter。

## 3. 关键设计说明

### 3.1 为什么批量读取必须等长

如果 Repository 删除缺失项，应用层就无法区分“第二项不存在”和“结果被数据库重排”。
因此 `get_latest_many()` 必须为每个输入位置返回 TaskSnapshot 或 None；长度不一致直接
视为 Adapter 缺陷。该规则为未来 MySQL 批量查询和多任务隔离保留了确定语义。

### 3.2 为什么恢复后不能再次按业务键读取

同一业务键可能在检查期间被提交为新执行。如果恢复后再次按业务键读取，结果可能从
旧任务跳到新任务，甚至把旧回调结果错误归给新执行。应用服务保存首次命中的 TaskId，
恢复后只使用 `get_by_id(TaskId)`，为波次 1B 的 expected execution ID 条件写奠定边界。

### 3.3 为什么 Progress 先订阅再读快照

如果先读旧快照再注册，两个操作之间发布的进度可能完全丢失。先建立订阅后再读取，
至少保证后续发布能够被 connection subscriber 接收。2026-07-16 增加的连接投递器
会在订阅前打开屏障：并发通知先进入固定容量缓冲，Web Adapter 发送完初始快照后才
按内部 TaskId/sequence 放行；这些内部字段不得加入现有 WebSocket 消息。

### 3.4 为什么 Registry 不放进应用服务

Registry 的生命周期等于一个 WebSocket 连接，属于入站 Adapter 所拥有的资源。应用
服务接收已有令牌并返回变更，使它既不持有连接对象，也不创建进程全局订阅表；未来
Flask 迁移 FastAPI 时只替换 Web 生命周期适配，不需要重写任务用例。

## 5. 接口、数据与并发边界

本阶段没有接口文档修改，也没有任何接口参数变化。以下已批准目标仍只是波次 1B 的
待实现外部行为：check-task 成功 200 空响应体、严格 params 元素校验、Progress
显式 action 返回 error 后保持连接且无 ack。

本阶段也没有数据库迁移或 Adapter，因此：

- 尚未实现 expected execution ID 条件写；
- 尚未实现线程安全 InMemory Progress Adapter；
- 已实现框架无关的连接有界缓冲和慢订阅者隔离，但尚未接入生产 WebSocket，也未完成 50 长连接实测；
- 尚未接入 MySQL、Redis、RabbitMQ、Celery 或 MinIO；
- 尚未实现可靠投递、跨实例通知、租约、fencing、Outbox 或死信队列。

这些限制不是缺陷隐藏，而是波次 1A 的明确范围边界。
