## 1. 根因复核

### 1.1 召回 Query 混入抽取指令

旧 INPUT 流程把包含角色、回答格式、示例、“未找到”和多值规则的完整抽取 Prompt 直接交给
向量检索。大量跨字段重复的程序性文本会稀释 `fieldName` 与 `fieldDescription`，并使不同字段的
检索 Query 变得过于相似。

### 1.2 原始向量分数缺少独立相关性证明

现有语料上，高分只表示候选在当前 embedding profile 下排在前面，不能证明 Chunk 真正回答了
目标字段。旧 `_get_score` 还会把缺失或非法分数折叠为 `0`，使“供应商协议异常”和“真实低分”
无法区分。

### 1.3 MHTML 入库包含大量页面结构噪声

对现有本地 MHTML 做只读结构审计后发现，导航、参考文献和外链列表与正文一起进入了知识索引。
同一类高频结构噪声会在多个 Chunk 中重复，导致无关查询也召回相同候选。

| 指标 | 旧通用文本 | 检索专用正文 |
| --- | ---: | ---: |
| 字符数 | 14,298 | 6,580 |
| 行数 | 392 | 164 |
| 年份 token | 68 | 0 |
| URL token | 6 | 0 |
| `USNI News` 出现次数 | 12 | 0 |

检索专用提取减少约 `53.98%` 字符。随后获批的隔离验证没有找到已被旧流程删除的原始 MHTML，
因此不能直接复现该 `mhtml-main-content-v1` 产物；本次改为从只读的既有 AnythingLLM 处理 JSON
提取 `pageContent`，明确删除 PDF 页眉/页脚、纯引用标记和参考文献尾部后建立临时索引。它证明
“清洗后的处理文本”可改善真实索引中的噪声结构，但**不等价于原始 MHTML 主正文重建**。

### 1.4 校准语料并不代表三个独立文档

只读审计到 3 个 workspace、3 条文档记录，但正文哈希显示它们是同一业务文档的副本，实际只有
1 份独立语料。初始 7 个查询中，有 6 个候选哈希出现在全部查询，有 8 个候选出现在至少 6 个
查询。因此当前集合不能用于批准生产 profile。

### 1.5 旧负例标签有一项错误

旧资产把 `wrong-missile` 标为自然语言负例，但文档正文实际包含 `RIM-7`、`RIM-116` 和 missile
launcher。该查询现已纠正为正例，并同步修正旧阈值评估。纠正后原结论仍成立：已验证的农业
负例 Top-1 为 `0.850500`，仍高于精确标题正例的 `0.829718`，所以原始 score 仍不存在可诚实
证明字段相关性的固定阈值。

### 1.6 动力字段的预期词遗漏

第一次隔离复校准中，动力查询仍显示预期词未命中。只读复核源正文后确认，正文原文是
`4座蒸汽涡轮发动机`，旧资产只列出了“蒸汽轮机/蒸汽渦輪/steam turbine”。这属于校准地面
真值遗漏，不是向量检索漏召回。资产已增加原文词但不修改 Retrieval Query；纠正后的第二次
隔离复跑中，五个正例的预期事实均位于质量门禁后的第 1 名。

## 2. 已实施修复

### 2.1 专用 Retrieval Query

新增 `field-semantic-v2` Query Builder：

- INPUT 只使用字段名、`fieldDescription` 和可选扩展词；
- TABLE 额外使用表格列名及列说明；
- 禁止混入抽取输出格式、模型角色、示例和“未找到”指令；
- 显式多词同义词保持完整短语，不自动拆成宽泛单词；ASCII 锚点按词边界匹配；
- Query 版本随未来 execution profile 冻结，版本不一致时拒绝选择。

`fieldDescription` 继续完整参与向量召回语义，但首版不会把整段自然语言说明中的每个词都当成
硬内容锚点，避免“提取、正式、信息”等通用词制造新的假阳性。跨语言锚点或 reranker 必须在
代表性语料上单独校准。

### 2.2 Chunk 规范化与质量门禁

新增无外部依赖的纯规则：

- 删除正文起始位置完整闭合的 `<document_metadata>`，并兼容真实 vector-search 返回的固定
  `passage: <document_metadata>...` 包装；
- 统一换行、NFKC 和 PDF 常见 CJK 字间空白，不拼接跨 Chunk 内容；
- 识别空/过短、metadata 占比过高和参考文献密集候选；
- 质量诊断只输出字符数、比例和原因，不把业务正文写入日志。

MHTML 新增检索专用清理入口，优先提取 `main/article/role=main`，跳过导航、页脚、广告、目录和
引用列表。它当前没有接入既有分析、报告或武器谱生产入库，避免在未建立可靠入库 execution
前暗中改变远端文档。

### 2.3 Evidence Selection 纯规则

新增 `EvidenceCandidate`、`EvidenceSelectionProfile`、`SelectedEvidence` 和
`select_evidence`，强制以下不变量：

1. 候选来源必须属于 execution 冻结的文档集合；
2. provider score 必须是 `[0, 1]` 内有限数字，缺失/非法值不能转换成 `0`；
3. 原始 provider score 只能参与排序，不能单独选中候选；
4. 候选还必须命中内容锚点，或通过未来独立 reranker；
5. 去重在稳定排序之后执行，只在同文档内做规范化精确全文去重；
6. 不跨文档去重，不为凑满 TopN 补回被拒绝候选；
7. 全部通过门禁的正文完整保留，不设置单条、总量或单文档数量/字符配额；
8. provider/query profile 指纹不一致时直接停止，不能沿用旧任务阈值。

资产中的 `minimumRerankerScore=0.8` 只用于证明算法分支，明确标记为“未校准、不可生产”。

### 2.4 AnythingLLM 只读校准能力

Workspace Adapter 增加 Python 内部可选 `score_threshold`：

- 只有调用方显式传值时才发送 AnythingLLM `scoreThreshold`；
- 普通业务调用不传该字段，既有 workspace 行为不变；
- 校准脚本固定显式传 `0.0` 观察完整返回区间；
- 该参数不属于 DocSense HTTP 接口。

校准工具直接使用 fail-fast 的只读 Workspace Adapter。网络或协议错误会终止校准，不再通过
legacy Facade 被伪装成合法零命中。输出只包含计数、分数和正文哈希，不输出 API Key、Base URL、
workspace slug、文档名或 Chunk 正文。

### 2.5 隔离重建与清理工具

新增 `reindex_weaponry_retrieval_quality_isolated.py`，只服务于经批准的校准写窗口：

1. 执行前读取全部 workspace 及绑定文档并计算不外泄原始身份的快照摘要；
2. 输入必须位于本机 AnythingLLM `custom-documents`，且始终只读；
3. 临时 workspace 名和上传文件名携带 32 位随机 execution token；
4. 删除权只来自本次创建/上传返回值，或本地存储中唯一匹配该 token 的资源；
5. 上传若异常复用执行前已绑定位置，拒绝取得删除权；
6. 嵌入后验证临时 workspace 只有本次一个文档，并排除临时 workspace 后再次比对既有快照；
7. `finally` 中依次删除临时 workspace 和全局文档；DELETE 结果不确定时先读状态，再做至多一次
   有界补偿；
8. 进程内与进程外都验证基线摘要恢复、临时 workspace 前缀为零、execution token 文件名残留为零；
9. 输出只含哈希、计数和分数，不记录 URL、密钥、slug、文档路径或 Chunk 正文。

## 3. 只读复校准结果

质量门禁后每个查询保留 8 个候选。简化 Query 的 Top-1 结果如下：

| 类别 | 查询 | Top-1 |
| --- | --- | ---: |
| 正例 | 舰艇名称 | 0.892592 |
| 正例 | 舰级名称 | 0.875737 |
| 正例 | 动力系统 | 0.857930 |
| 正例 | 雷达型号 | 0.868536 |
| 正例 | 导弹发射装置 | 0.877727 |
| 负例 | 农业数据 | 0.846160 |
| 负例 | 药物剂量 | 0.848398 |
| 负例 | 芯片制程 | 0.838050 |

上述旧含噪索引的查询级最小正例 Top-1 与最大负例 Top-1 之间暂时出现 `0.009532` 间隔，但
**不得据此批准生产阈值**。动力字段的空预期命中现已确认是旧地面真值遗漏；其余限制仍成立。

### 3.1 隔离清洗副本复校准

清洗副本从既有处理文本的 13,530 字符/412 行缩减为 5,854 字符/259 行，删除 37 行纯引用、
8 行页眉页脚，在删除 `file:///` 页脚时保留了 4 行紧随页码的正文后缀；参考文献从第 301 行
开始整体截断。第四次复跑采用修正后的动力预期词和真实 `passage` 元数据清理规则，结果如下：

| 类别 | 查询 | Top-1 | 预期事实首名次 | 参考文献型候选 |
| --- | --- | ---: | ---: | ---: |
| 正例 | 舰艇名称 | 0.894344 | 1 | 0 |
| 正例 | 舰级名称 | 0.879307 | 1 | 0 |
| 正例 | 动力系统 | 0.865630 | 1 | 0 |
| 正例 | 雷达型号 | 0.875381 | 1 | 0 |
| 正例 | 导弹发射装置 | 0.874578 | 1 | 0 |
| 负例 | 农业数据 | 0.847800 | — | 0 |
| 负例 | 药物剂量 | 0.845546 | — | 0 |
| 负例 | 芯片制程 | 0.843647 | — | 0 |

查询级最小正例与最大负例的暂定间隔为 `0.017830`，五个正例均在第 1 名包含预期事实，
八个查询返回的候选也都不再被 Chunk 质量规则判为参考文献型。这证明隔离清洗副本的真实索引
已去除本次识别的引用尾部噪声。

### 3.2 `passage` 元数据修复与重复性

前两次隔离执行虽然使用相同清洗正文，但候选正文哈希集合不一致。结构化只读探针确认真实
AnythingLLM 返回在 XML 前还有 9 字符的 `passage: `，导致旧正则没有移除 134 字符元数据；
修复后同一探针由 1,109 字符规范化为 974 字符正文。

第三、第四次使用相同清洗正文和修复后的规则重复执行：所有查询的候选正文哈希集合完全一致，
证明证据内容身份不再受随机临时文件名污染；但候选顺序并非全部一致，Top-1 最大漂移为
`0.001721919`。因此只能说“候选集合可重复”，不能声称供应商排序和小数分数完全确定。

### 3.3 为什么仍不能批准生产 profile

`scoreThreshold=0.0`、`topN=100` 且临时文档只有 8 个 Chunk 时，8 个候选仍会出现在多个查询
中；这说明“返回了候选”本身不等于相关。当前仍不得批准生产阈值，原因是：

- 该间隔只是 Query 级 Top-1，尚未对每个 Candidate 做人工相关性标注；
- 真实语料只有 1 个独立业务文档，没有近似干扰、跨文档冲突和多格式分布；
- 本次输入是历史处理文本清洗副本，不是已经丢失的原始 MHTML，也没有接入生产入库；
- 独立 reranker 或等价额外信号尚未实现和校准。

此前翻译锚点诊断实验的“动力字段漏召回”也受到同一旧预期词遗漏影响；该历史实验仍只用于
定位方向，不能升级为生产 profile。生产 Selection 仍必须要求内容锚点或独立 reranker，不能
把本次查询级分数间隔直接写成固定阈值。

## 6. 当前边界与下一步

本地修复没有数据迁移，也没有部署生产。若需要回滚，只需移除尚未接管路由的新模块、检索专用
清理入口和内部显式阈值能力；既有 `/llm/weaponry` 仍保持当前行为。

本次获批的随机隔离资源已完成创建、嵌入、校准与清理，证明了保护流程和去噪方向。要关闭
1D-0R，下一步不再是“取得临时写授权”，而是：为未来新上传的原始 MHTML 接入
`mhtml-main-content-v1` 生产入库 execution；重新取得或重建可追溯的原始来源样本；准备用户确认
的代表性多文档校准集；完成人工 Candidate 标注和版本化独立相关性信号。不得直接覆盖当前文档，
也不得把三个 workspace 副本当成代表性语料。

在上述条件满足前：

- `candidateProfile.status` 保持 `evaluation-only`；
- `productionEligible=false`；
- 1D-3B 生产 Retrieval Adapter 和 1D-6 路由切换继续阻塞；
- 不修改接口文档，不增删任何前后端参数。
