## 2. 领域一致性修正

### 2.1 释放保护必须提供终态证据

新增 `ReassignmentTerminalEvidence` 和 `ReassignmentTerminalEvidenceKind`：

- `succeeded` 只接受 `forward_success_confirmed`；
- `failed` 只接受 `no_side_effect_failure_confirmed`；
- `compensated` 只接受 `compensation_confirmed`；
- 非终态转换禁止携带终态证据。

因此调用方不能再仅传 `RUNNING -> FAILED` 就释放同文档保护。Repository 后续仍必须独立执行
lease/fencing 条件更新；领域证据不能替代持久化所有权。

### 2.2 本地提交与远端绑定必须一致

`ReassignmentCompensationFacts` 新增来源/目标绑定状态和
`remote_membership_required`：

- 本地 CAS 已生效且目标绑定已确认存在，来源绑定已确认删除或按缺映射兼容策略跳过时，
  才允许保留本地提交；
- 本地已切换但目标缺失、目标未知、来源意外仍存在时，进入 `recovery_required`；
- 空 `doc_path` 使用 `not_applicable` 明确表达本地-only路径；
- 任一写结果未知仍优先保留现场，禁止盲目补偿。

### 2.3 补偿只使用独立 Step

删除 Step 层的 `compensating/compensated/compensation_failed` 第二套状态。前向和补偿外部写
统一使用：

```text
pending -> mutation_started -> succeeded
                            -> known_failed
                            -> outcome_unknown
```

补偿动作由 `compensate_target_document`、`compensate_source_document` 独立 Step 保存写意图、
幂等键和结果；Operation 保留 `compensating/compensated` 表示总体阶段。未知结果必须先探测；
明确失败只有恢复服务取得新 fencing 后才可再次进入 `mutation_started`。

### 2.4 内部事实边界

- 原始旧 ArchitectureId 与 Web Adapter 已解析查询值必须一致；Domain 不拥有首次转换和 HTTP
  失败语义，只执行防御性一致性断言；
- lease 到期时间必须是带时区 ISO-8601，并规范化为固定 UTC 文本；
- 外部引用最大 512 字符、错误码最大 128 字符、错误摘要最大 1024 字符；
- Adapter 后续必须先脱敏再截断，Domain 拒绝直接构造超长事实。

## 3. 公开消息与契约

经负责人确认，接口文档和机器资产冻结以下 `data.message`：

| 场景 | 文案 |
| --- | --- |
| 远端失败 | `知识库节点迁移失败` |
| 本地 CAS 冲突 | `文档状态已变化，分类变更失败` |
| 同文档并发占用 | `文档分类正在变更，请稍后重试` |
| 补偿明确失败 | `知识库关联恢复失败` |
| 结果未知或等待恢复 | `变更结果暂无法确认，请稍后重试` |

原有 `变更成功`、`文档记录不存在`、`分类不一致，变更失败` 保持不变。所有失败仍返回 HTTP
500、顶层 `msg="变更失败"` 和原有 `businessType + msg + data` 字段，不增加错误码或内部 ID。

当前遗留路由只修改远端异常文案，日志保留异常类型但不记录异常正文；公开响应不再包含
API Key、Authorization、供应商响应、数据库路径或堆栈。

## 4. 契约资产补强

`stage1e0_reassign_contracts.json` 和对应测试新增：

- 正常远端删除、加入、本地更新的精确 HTTP 200 黄金响应与调用顺序；
- 远端异常的稳定 500 JSON、`application/json` Content-Type 和敏感文本禁止泄漏；
- 领域公开消息枚举、机器资产与接口文档三方一致性；
- 来源删除结果未知、目标加入明确失败、同文档活动 Operation、硬预算耗尽等目标故障；
- 八类目标故障必须引用已批准公开文案，内部 Operation/lease/fencing/step 仍禁止输出。

这些目标矩阵仍是后续 1E-2～1E-6 的验收输入；测试不会把尚未实现的 Saga 行为误报为当前能力。

## 6. 后续硬边界

1. 1E-2 Repository 的终态 API 必须要求匹配的 `ReassignmentTerminalEvidence`，同时校验
   lease token 与 fencing token。
2. Step 表只保存统一五态；补偿动作使用独立 Step 行，不得恢复已删除的第二套补偿状态。
3. Codec 必须严格校验 UTC lease、诊断字段上限和来源/目标绑定状态，损坏数据不得静默修复。
4. 1E-3～1E-5 必须把成员探测结果转换为明确绑定状态，并覆盖调用完成但检查点未提交的崩溃窗口。
5. 1E-6 Presenter 只能从 `ReassignmentPublicMessage` 映射公开文案，禁止自由字符串。
6. 生产 HTTP/总预算/补偿预留秒数仍等待隔离集成环境校准。
