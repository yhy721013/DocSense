## 1. 合同范围与身份规则

### 1.1 接口路径

知识谱系对话包含以下五个独立接口：

| 功能 | 方法 | 路径 |
| --- | --- | --- |
| 发送消息并接收流式回答 | POST | `/llm/weaponry-chat` |
| 生成标题 | POST | `/llm/weaponry-chat/title` |
| 获取历史 | GET | `/llm/weaponry-chat/history` |
| 中断当前流 | POST | `/llm/weaponry-chat/abort` |
| 删除对话 | POST | `/llm/weaponry-chat/delete` |

除历史接口使用 Query 参数外，其余接口的请求体均使用现有 LLM 接口的
`businessType + params` 外层结构，且 `businessType` 固定为 `"weaponryChat"`。

### 1.2 对话唯一身份

1. `userId` 和 `architectureId` 两个值共同表示一条知识谱系对话。
2. 同一 `userId` 在同一 `architectureId` 下同时只能存在一条未删除对话。
3. 公开接口不接收、返回或暴露 `chatId`、内部 `conversationId`、`runId`、租约、围栏令牌、
   AnythingLLM Workspace/Thread ID 等实现身份。
4. 删除完成后，原对话不再占用该身份。相同 `userId + architectureId` 再次发送消息时创建
   一条新对话，并重新冻结当时的类别直接文件快照。
5. 删除尚未完成或远端资源清理失败时，不得为相同身份并行创建新对话，避免同时存在两套
   远端资源和不明确的历史归属。

### 1.3 userId 规则

`userId` 是 **DocSense 业务用户标识**，与 AnythingLLM 用户标识没有任何关系：

- POST JSON 中必须是 JSON number 类型的正整数；
- 合法范围为 `1..9007199254740991`，保证 JavaScript 能精确表示；
- 拒绝字符串、布尔值、浮点数、指数形式、`0`、负数、对象、数组和超出上限的值；
- JSON/SSE 响应中的 `userId` 始终为 JSON number；
- GET Query 中以无正负号、只包含 ASCII 数字的十进制文本传递，允许前导零；例如
  `userId=00010001` 与 `userId=10001` 表示同一用户；
- 后端不得把该值作为下游用户标识或写入下游用户请求头；现有固定下游用户上下文继续沿用
  项目当前配置。

本合同明确采用**可信调用方边界**：调用方传入的 `userId` 是已经由 DocSense 业务侧确认的
权威用户身份，知识谱系对话后端不再要求第二个用户证明字段，也不把它解释为 AnythingLLM
身份。调用方或其可信网关必须在请求到达本接口前完成用户身份真实性和类别访问权限校验；本接口
不得直接暴露给能够任意伪造 `userId` 或越权访问 `architectureId` 的不可信调用者。首次文件快照
可以保持不刷新，但访问授权不是快照的一部分，每次请求仍处于上述可信调用边界内。

### 1.4 architectureId 规则

`architectureId` 表示知识谱系类别：

- POST JSON 接受 `1..9007199254740991` 范围内的 JSON 正整数；
- POST JSON 也接受只包含 ASCII 数字的十进制整数字符串；字符串允许前导零，并按整数值
  规范化，例如 `"0001"` 与 `1` 表示同一类别；
- 拒绝布尔值、浮点数、指数形式、正负号字符串、空白字符串、非 ASCII 数字、`0`、负数、
  对象、数组和超出上限的值；
- GET Query 中使用无正负号、只包含 ASCII 数字的十进制文本，允许前导零；例如
  `architectureId=0001001` 与 `architectureId=1001` 表示同一类别；
- JSON/SSE 响应中的 `architectureId` 始终为 JSON number。

知识谱系解析、分类节点变更和武器谱抽取等其他业务的 ID 合同不受本文影响。

### 1.5 类别文件范围语义

本接口保留“直接文件、首次冻结、后续不刷新”的类别范围语义：

1. 相同 `userId + architectureId` 第一次成功受理发送消息请求时，服务端精确读取该类别的
   **直接文件**，不递归包含任何子类别文件。
2. 服务端对全部候选执行文件身份、远端文档身份、来源映射能力和数量上限校验，并按稳定顺序
   冻结不可变对话范围。
3. 后续消息只复用首次冻结的范围，不重新查询类别。后来新增、删除、重新解析或重新分类的文件
   不会进入或退出该对话。
4. 冻结的是文件成员和本轮需要的文档/来源身份，不是复制永久不变的文件内容；执行时仍须通过
   已冻结身份精确选择对应的 AnythingLLM 文档。
5. 类别不存在、没有可用直接文件、存在重复或歧义身份、无法形成完整来源映射、或者有效文件数
   超过配置上限时，首次请求整体失败，不截断、不跳过错误成员，也不创建部分会话事实或远端资源。
6. 只有删除完成后重新进入，才能根据当时类别状态创建新快照。

### 1.6 严格请求字段规则

本接口不提供旧字段兼容，也不忽略调用方拼写错误：

1. 三个 POST 管理接口和发送接口的顶层字段只能是 `businessType`、`params`；请求体必须能够
   解析为 JSON 对象，数组、标量、空请求体和畸形 JSON 均返回 HTTP 400：
   `{"error":"请求体必须为JSON对象"}`。
2. 发送接口的 `params` 只能包含 `userId`、`architectureId`、`message`；title、abort、delete
   的 `params` 只能包含 `userId`、`architectureId`。
3. 任一 POST 出现未定义字段，包括旧 `chatId`、`fileNames` 或拼写错误字段，返回 HTTP 400：
   `{"error":"请求包含未知字段"}`。服务端不得静默忽略。
4. History Query 只能包含一次 `userId` 和一次 `architectureId`。出现未知 Query 字段时返回
   HTTP 400：`{"error":"请求包含未知字段"}`；任一已定义字段重复出现时返回 HTTP 400：
   `{"error":"Query参数不能重复"}`。
5. GET 的两个十进制值都允许前导零，服务端按整数值规范化；空串、正负号、空白、非 ASCII
   数字、小数、指数文本、全零值和超出 JavaScript 安全整数上限的值仍然非法。

### 1.7 会话状态与五接口响应矩阵

下表描述完成请求字段校验后的生命周期结果；History 在所有非删除终态下只返回**已经提交**的
本地历史，不包含正在流式生成的临时文本：

| 当前状态 | 发送消息 | 生成标题 | History | Abort | Delete |
| --- | --- | --- | --- | --- | --- |
| 从未创建或已删除完成 | 创建新 Conversation 和新快照 | HTTP 200，`title=""` | HTTP 200，`[]` | HTTP 200，`aborted=false` | HTTP 404 |
| active，尚无可用历史 | 正常受理 | HTTP 400，历史为空 | HTTP 200，可为 `[]` | HTTP 200，`aborted=false` | 同步删除，成功为 HTTP 200 |
| active 且空闲 | 正常受理 | 根据已提交历史生成 | HTTP 200，返回已提交历史 | HTTP 200，`aborted=false` | 同步删除，成功为 HTTP 200 |
| 发送受理中或流运行中 | HTTP 409 | HTTP 409 | HTTP 200，仅返回此前已提交历史 | HTTP 200，`aborted=true` | HTTP 409，须先中断并等到 `aborted` |
| 标题生成中 | HTTP 409 | HTTP 409 | HTTP 200，返回已提交历史 | HTTP 200，`aborted=false` | HTTP 409 |
| deleting | HTTP 409 | HTTP 409 | HTTP 200，返回已提交历史 | HTTP 200，`aborted=false` | HTTP 409 |
| cleanup_failed | HTTP 409 | HTTP 409 | HTTP 200，返回已提交历史 | HTTP 200，`aborted=false` | 再次同步尝试未完成清理；成功 HTTP 200，失败 HTTP 500 |

标题接口因运行、标题、删除或清理失败状态不可用时，统一返回 HTTP 409：
`{"error":"当前对话暂不可用于标题生成"}`。标题生成占用期间发送消息返回发送接口已经冻结的
HTTP 409 `{"error":"当前对话暂不可用"}`。删除完成后活动复合身份已经释放，尚未创建新会话前
再次调用 delete 按“不存在”返回 HTTP 404，而不是访问旧审计墓碑。

## 2. 发送对话消息接口

**接口路径：** `/llm/weaponry-chat`

**请求方法：** `POST`

**响应方式：** SSE（Server-Sent Events）

**成功响应 Header：**

| Header | 值 | 说明 |
| --- | --- | --- |
| `Content-Type` | `text/event-stream` | SSE 媒体类型；允许框架附加标准字符集参数 |
| `Cache-Control` | `no-cache` | 禁止直接复用缓存的流式响应 |
| `X-Accel-Buffering` | `no` | 要求支持该 Header 的反向代理关闭响应缓冲 |

这三个 Header 属于知识谱系对话的公开成功响应合同。代理或网关可以转发、消费
`X-Accel-Buffering`，但不得因缓冲配置而破坏 SSE 的逐事件交付。

### 2.1 请求参数

| 参数 | 类型 | 说明 | 必填 |
| --- | --- | --- | --- |
| businessType | String | 固定值 `"weaponryChat"` | 是 |
| params | Object | 请求参数对象，不能是数组 | 是 |

### 2.2 params 结构

| 字段 | 类型 | 说明 | 必填 | 示例 |
| --- | --- | --- | --- | --- |
| userId | Integer | DocSense 业务用户 ID，必须是 JavaScript 安全正整数 | 是 | `10001` |
| architectureId | Integer / 十进制整数字符串 | 知识谱系类别 ID | 是 | `20001` / `"20001"` |
| message | String | 用户问题；去除首尾空白后不能为空 | 是 | `"请总结该类别文件的核心观点"` |

调用方不得发送 `chatId` 或 `fileNames`。服务端也不会在响应中生成或返回公开 `chatId`。

### 2.3 请求示例

```json
{
  "businessType": "weaponryChat",
  "params": {
    "userId": 10001,
    "architectureId": "20001",
    "message": "请总结该类别文件的核心观点"
  }
}
```

同一对话后续每一轮仍传入相同的 `userId + architectureId`：

```json
{
  "businessType": "weaponryChat",
  "params": {
    "userId": 10001,
    "architectureId": 20001,
    "message": "请继续比较这些文件中的技术指标"
  }
}
```

### 2.4 SSE 事件类型

| event | data 内容 | 出现次数与说明 |
| --- | --- | --- |
| `chatInfo` | `{"userId":10001,"architectureId":20001,"isNewChat":true}` | 恰好一次且为首个事件；`isNewChat` 由服务端受理事实决定 |
| `textChunk` | `{"content":"..."}` | 零次或多次；大模型回答的文本片段 |
| `sourceChunks` | `{"userId":10001,"architectureId":20001,"chunks":[...]}` | 成功流中恰好一次；位于全部 `textChunk` 之后、`done` 之前 |
| `done` | `{"userId":10001,"architectureId":20001}` | 完整成功的唯一终结事件 |
| `aborted` | `{"userId":10001,"architectureId":20001}` | 中断成功收敛时的终结事件；回答不完整 |
| `error` | `{"error":"..."}` | SSE 建立后失败时的终结事件 |

成功事件顺序固定为：

```text
chatInfo → textChunk（零次或多次）→ sourceChunks（恰好一次）→ done
```

`sourceChunks` 不得提前发送、重复发送或在 `done` 之后发送。`aborted` 和 `error` 路径不发送
`sourceChunks` 或 `done`。

### 2.5 sourceChunks 结构

```text
event: sourceChunks
data: {"userId":10001,"architectureId":20001,"chunks":[{"content":"……","fileName":"internal-a.pdf","originalFileName":"装备体系研究报告.pdf"}]}
```

`chunks` 数组元素结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| content | String | AnythingLLM 本轮检索返回的 Chunk 原文；保持上游 JSON 字符串值不变 |
| fileName | String | 首次冻结快照中的 DocSense 业务文件名 |
| originalFileName | String | 首次冻结快照中的非空文件原名；缺失或空白时整个类别范围非法 |

完整规则：

1. `chunks` 表示 AnythingLLM 为本轮回答检索到的证据列表，不表示每个回答句子或 token 的
   精确引用关系。
2. 保留 AnythingLLM 最终来源数组的顺序，不按正文、文件或文件名静默去重，也不改写 Chunk
   原文。
3. 上游 Chunk 正文必须是 JSON string。服务端不得调用通用字符串化、`strip()`、换行统一、
   Unicode 规范化或 Markdown 清理；非字符串、空字符串或仅包含空白的来源正文整体失败。合法
   正文的首尾空白、换行类型和 Unicode 码点序列必须保持不变。
4. 本轮 SSE `sourceChunks.chunks` 与成功事务保存、随后 History 返回的 assistant `chunks`
   必须在数组顺序及三个字段的字符串值上完全相同；JSON 转义方式不同不属于内容差异。
5. AnythingLLM 最终返回空 `sources` 属于合法成功结果，服务端仍发送一次
   `sourceChunks`，其中 `chunks=[]`。
6. `fileName` 和 `originalFileName` 必须来自该对话首次冻结的 DocSense 文件快照，不得直接
   信任 AnythingLLM 的 `title`，不得通过模糊文件名、URL 子串或来源正文猜测。
7. 服务端使用 AnythingLLM 结构化来源身份与冻结快照执行唯一精确映射。来源身份缺失、格式
   非法、无法匹配、匹配到多个文件，或者映射结果不属于本轮冻结范围时，整个运行失败关闭。
8. 首次冻结的任一文件缺少 `originalFileName`、该字段不是字符串、空字符串或仅包含空白时，整个
   类别范围严格失败，不创建部分会话、快照或远端资源，也不回退为 `fileName`。合法原文件名的
   规范化继续遵循项目既有文件身份规则，本条只冻结“缺失或空白时严格拒绝”的行为。
9. 响应不得包含供应商内部来源标识、URL、分数、距离、Workspace/Thread ID、DocSense 内部
   文档引用或数据库主键。

### 2.6 完整 SSE 成功示例

```text
event: chatInfo
data: {"userId":10001,"architectureId":20001,"isNewChat":true}

event: textChunk
data: {"content":"根据该类别首次冻结的文件范围，"}

event: textChunk
data: {"content":"核心观点包括……"}

event: sourceChunks
data: {"userId":10001,"architectureId":20001,"chunks":[{"content":"用于回答的检索原文……","fileName":"internal-a.pdf","originalFileName":"装备体系研究报告.pdf"}]}

event: done
data: {"userId":10001,"architectureId":20001}
```

### 2.7 成功持久化语义

- 只有 AnythingLLM 的完整最终事件已经到达、来源列表完成严格解析和映射、回答正文满足输出
  限制时，本轮才能成功。
- 完整 assistant 正文与其 `chunks` 快照必须在同一本地事务中提交；不得出现历史中有回答但
  没有对应 Chunk 快照，或者只保存部分 Chunk 的状态。
- `done` 表示上述成功事实已经提交。收到 `done` 后，历史接口应能读取完整 assistant 和
  `chunks`。
- `aborted`、`error` 或客户端在完成前断开时，不保存不完整 assistant，也不保存该轮 Chunk
  列表。已开始执行的失败/中断轮次可以保留已提交 user 消息，沿用共享对话服务的失败语义。

本地成功事务提交是本轮唯一线性化完成点，网络送达不是事务的一部分：

- 服务端在成功事务提交前观察到中断或客户端断开时，本轮不得提交 assistant/chunks；
- 成功事务提交后，即使 `sourceChunks` 或 `done` 因连接断开未送达，完整 assistant/chunks 仍然
  保留在 History 中，客户端可重新读取历史恢复视图；
- `sourceChunks` 和 `done` 只能在提交成功后发送，因此收到 `done` 必然表示历史已可读，但“未
  收到 `done`”不能反向证明事务一定没有提交；
- 完成命令必须以 `abort_requested=false` 作为条件之一。Abort 事务先成功时，后续完成事务不得
  覆盖中断事实；完成事务先成功时，后来的 Abort 返回 `aborted=false`。

### 2.8 建立 SSE 前的错误响应

建立 SSE 前的错误使用 HTTP 状态码和单字段 JSON：`{"error":"..."}`。

| 场景 | HTTP 状态码 | error 文本 |
| --- | --- | --- |
| `businessType` 不是 `"weaponryChat"` | 400 | `businessType必须为weaponryChat` |
| `params` 缺失或不是对象 | 400 | `params不能为空` |
| 请求体不是可解析的 JSON 对象 | 400 | `请求体必须为JSON对象` |
| POST 或 History Query 包含未定义字段 | 400 | `请求包含未知字段` |
| History Query 的 `userId` 或 `architectureId` 重复 | 400 | `Query参数不能重复` |
| `userId` 类型或范围非法 | 400 | `userId必须为1到9007199254740991之间的正整数` |
| `architectureId` 缺失、为空或为 `null` | 400 | `architectureId不能为空` |
| `architectureId` 类型、格式或范围非法 | 400 | `architectureId必须为1到9007199254740991之间的正整数` |
| `message` 缺失、不是字符串或去除首尾空白后为空 | 400 | `message不能为空` |
| `message` 超过文件对话共享长度上限 | 400 | `message超过文件对话长度上限` |
| 首次受理时类别不存在或没有可用直接文件 | 404 | `architectureId对应类别不存在或没有可用于对话的文件` |
| 类别文件无法形成完整、唯一的对话范围，包括缺少非空 `originalFileName` | 400 | `architectureId对应类别文件无法形成有效对话范围` |
| 首次冻结的有效文件超过共享数量上限 | 400 | `类别文件超过文件对话数量上限` |
| 同一 `userId + architectureId` 已有受理中或运行中的流 | 409 | `当前对话已有进行中的流式响应` |
| 对话正在删除、清理失败或当前不可用 | 409 | `当前对话暂不可用` |
| 当前实例流容量已满 | 429 | `文件对话并发流已达上限，请稍后重试` |

所有首次范围校验失败都不得创建会话、快照、运行、消息、文件绑定或远端资源。409 冲突应在
全局流容量 429 之前判定，同一身份的并发请求不能形成两条会话或两份首次快照。

### 2.9 SSE 建立后的失败与中断

AnythingLLM 传输失败、缺失真正的最终事件、来源列表非法、来源无法唯一映射、输出超限或本地
终态事务失败时，通过 `error` 终结：

```text
event: error
data: {"error":"大模型服务响应异常"}
```

已经推送的 `textChunk` 仅供实时展示；收到 `error` 或 `aborted` 后不得把这些片段当作完整
assistant 历史。

客户端主动关闭 SSE 连接时：

- 若内部运行尚未领取，不调用模型，待提交 user 消息不进入历史；
- 若运行已经开始，服务端停止本轮并收敛为失败，保留已提交 user 消息，不保存 assistant 或
  Chunk 快照；
- 当前接口不提供断线续传、SSE 回放或调用方断开后的后台继续生成。

## 3. 生成对话标题接口

**接口路径：** `/llm/weaponry-chat/title`

**请求方法：** `POST`

**功能说明：** 根据本地已提交历史生成最多 20 个中文字符的展示标题。

### 3.1 请求结构

```json
{
  "businessType": "weaponryChat",
  "params": {
    "userId": 10001,
    "architectureId": 20001
  }
}
```

`params` 只使用 `userId` 和 `architectureId` 定位对话，不接收 `chatId`。

### 3.2 成功响应（HTTP 200）

```json
{
  "userId": 10001,
  "architectureId": 20001,
  "title": "装备体系核心观点对比"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| userId | Integer | 请求对应的 DocSense 用户 ID |
| architectureId | Integer | 规范化后的类别 ID |
| title | String | 模型生成并由服务端清理、截断的标题 |

### 3.3 其他响应

对话不存在时正常返回空标题（HTTP 200）：

```json
{
  "userId": 10001,
  "architectureId": 20001,
  "title": ""
}
```

对话存在但没有可用于标题生成的已提交历史时返回 HTTP 400：

```json
{
  "error": "对话历史为空，无法生成标题"
}
```

对话正在运行、已经有标题生成请求占用、正在删除或处于清理失败状态时，统一返回 HTTP 409：

```json
{
  "error": "当前对话暂不可用于标题生成"
}
```

模型调用或临时远端资源清理失败时返回 HTTP 500 与既有单字段 `error` 结构。标题不由后端
持久化，调用方自行保存或缓存。

## 4. 获取对话历史接口

**接口路径：** `/llm/weaponry-chat/history`

**请求方法：** `GET`

**功能说明：** 根据 `userId + architectureId` 返回本地已提交消息，按时间正序排列。

### 4.1 Query 参数

| 参数 | 类型语义 | 传递方式 | 说明 | 必填 |
| --- | --- | --- | --- | --- |
| userId | Integer | Query 十进制文本 | DocSense 业务用户 ID | 是 |
| architectureId | Integer | Query 十进制文本 | 知识谱系类别 ID | 是 |

```http
GET /llm/weaponry-chat/history?userId=10001&architectureId=20001
```

Query 参数必须使用无正负号、只包含 ASCII 数字的十进制文本，允许前导零，并满足 JavaScript
安全正整数范围。服务端按整数值规范化，因此 `0001` 与 `1` 表示同一身份。
非法参数返回 HTTP 400 和对应的 `userId`/`architectureId` 错误文本。

### 4.2 成功响应

历史响应保持与文件对话相似的**裸消息数组**，不增加顶层
`{userId, architectureId, messages}` 包装，也不在每条消息中重复回显对话身份。HTTP 请求和响应
由浏览器请求对象一一对应；前端若在请求期间切换当前类别，应在应用本地用发起请求时的
`userId + architectureId` 校验响应是否仍属于当前视图。

用户消息结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| role | String | 固定为 `"user"` |
| content | String | 用户消息 |
| timestamp | Number / null | 毫秒时间戳 |

assistant 消息结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| role | String | 固定为 `"assistant"` |
| content | String | 完整回答 |
| timestamp | Number / null | 毫秒时间戳 |
| chunks | Array\<Object\> | 与该回答原子保存的来源 Chunk 快照；无来源时为 `[]` |

`chunks` 元素仍严格使用：

```json
{
  "content": "用于回答的检索原文……",
  "fileName": "internal-a.pdf",
  "originalFileName": "装备体系研究报告.pdf"
}
```

### 4.3 响应示例（HTTP 200）

```json
[
  {
    "role": "user",
    "content": "请总结该类别文件的核心观点",
    "timestamp": 1777364120677
  },
  {
    "role": "assistant",
    "content": "根据类别首次冻结的文件范围，核心观点包括……",
    "timestamp": 1777364120678,
    "chunks": [
      {
        "content": "用于回答的检索原文……",
        "fileName": "internal-a.pdf",
        "originalFileName": "装备体系研究报告.pdf"
      }
    ]
  }
]
```

对话不存在或已经删除完成时返回 HTTP 200 和空数组：

```json
[]
```

历史接口只读取本地已提交事实，不调用 AnythingLLM，不重新查询类别，也不根据类别当前状态
刷新首次文件快照或来源 Chunk。

对话处于运行、标题生成、删除中或清理失败状态时，History 仍返回当前已经提交的本地历史；
不会等待活动操作，也不会返回本轮尚未提交的临时文本。当前合同不分页，也暂不对历史累计消息数、
Chunk 数量或 Chunk 总字符数设置 DocSense 业务硬上限。

## 5. 中断流式对话接口

**接口路径：** `/llm/weaponry-chat/abort`

**请求方法：** `POST`

### 5.1 请求示例

```json
{
  "businessType": "weaponryChat",
  "params": {
    "userId": 10001,
    "architectureId": 20001
  }
}
```

### 5.2 中断成功（HTTP 200）

```json
{
  "userId": 10001,
  "architectureId": 20001,
  "aborted": true,
  "msg": "已发送中断信号"
}
```

当前没有活跃流时仍返回 HTTP 200：

```json
{
  "userId": 10001,
  "architectureId": 20001,
  "aborted": false,
  "msg": "当前无进行中的流式响应"
}
```

### 5.3 SSE 流侧行为

执行流观察并收敛中断请求后发送：

```text
event: aborted
data: {"userId":10001,"architectureId":20001}
```

中断后的不完整 assistant 和 Chunk 不进入历史。调用方发出中断请求后应继续保持原 SSE 连接，
等待 `aborted` 到达后再结束消费。当前通知机制可能需要等待上游下一次事件边界，不承诺跨实例
实时唤醒。

`aborted=true` 表示持久化中断请求已经先于成功完成事务取得执行权，原流最终必须收敛为
`aborted`，不能再提交 assistant/chunks 或发送 `done`。如果成功事务已经先完成，则 Abort 返回
`aborted=false`，调用方按原流的 `done` 和 History 处理。

## 6. 删除对话接口

**接口路径：** `/llm/weaponry-chat/delete`

**请求方法：** `POST`

**功能说明：** 删除 `userId + architectureId` 对应的本地对话，并同步清理当前远端资源。远端
清理和本地删除全部成功后，物理删除该 Conversation 的消息正文与 Chunk 原文，只保留不含正文的
最小审计事实。

### 6.1 请求示例

```json
{
  "businessType": "weaponryChat",
  "params": {
    "userId": 10001,
    "architectureId": 20001
  }
}
```

### 6.2 删除成功（HTTP 200）

```json
{
  "userId": 10001,
  "architectureId": 20001,
  "deleted": true,
  "msg": "对话已删除"
}
```

删除完成后，相同身份再次调用发送消息接口将创建新对话和新类别文件快照。

删除成功后的最小审计事实只用于证明删除终态、清理结果和身份世代，不得保留 user/assistant
正文、Chunk 原文或可用于恢复已删除对话的完整历史。活动 `userId + architectureId` 绑定在全部
清理和正文删除成功后才释放；旧审计墓碑不能通过五个公开接口访问。

### 6.3 对话不存在（HTTP 404）

```json
{
  "error": "对话不存在"
}
```

### 6.4 对话忙（HTTP 409）

存在活跃流时，调用方必须先中断并等待 SSE `aborted`，再发起删除：

```json
{
  "userId": 10001,
  "architectureId": 20001,
  "deleted": false,
  "error": "当前对话存在进行中的流式响应，请先中断后删除"
}
```

标题生成占用对话或对话已在删除中时同样返回 HTTP 409，并保持本节已经冻结的
`userId + architectureId + deleted=false + error` 响应结构；对应 `error` 分别为
`当前对话正在生成标题，请稍后重试` 和 `当前对话正在删除`。处于 `cleanup_failed` 时，delete
不直接返回 409，而是按 6.5 同步重试尚未完成的清理。

### 6.5 资源清理失败（HTTP 500）

```json
{
  "userId": 10001,
  "architectureId": 20001,
  "deleted": false,
  "error": "对话资源清理失败"
}
```

清理失败时保留本地恢复事实，并继续阻止相同身份创建新会话；不得通过响应泄露远端资源引用、
内部清理任务 ID 或错误堆栈。

此时再次调用 delete 会同步重试尚未完成的精确清理；重试成功后按 6.2 返回，仍失败则继续返回
本节 HTTP 500。删除完成、活动身份已经释放且尚未创建新会话时，再次 delete 返回 6.3 的
HTTP 404。

## 7. 调用方职责和当前能力边界

### 7.1 调用方职责

1. 调用方使用自己的 `userId + architectureId` 管理知识谱系对话入口，不生成 `chatId`。
2. 调用方必须为五个接口传递相同身份值；SSE 处理以 `done`、`aborted` 或 `error` 为终结。
3. `sourceChunks` 是本轮检索证据列表。前端可以把 Chunk 和文件信息作为“参考来源”展示，但
   不应宣称它是回答逐句引用或精确归因。
4. 历史响应为裸数组。前端应使用发起请求时保存的身份键防止页面快速切换导致旧响应覆盖新视图。
5. 只有收到 `done` 才把流式回答视为完整成功；`aborted` 或 `error` 前收到的文本只作临时展示。

### 7.2 与文件对话的边界

- `/llm/chat*` 和 `/llm/weaponry-chat*` 使用独立公开身份和请求解析；不得互相接受对方参数。
- 两者可以共用内部对话领域模型、运行状态机、持久化、标题/中断/删除用例、AnythingLLM
  Transport/Client/Gateway 和资源清理能力。
- 文件对话继续使用 `chatId + fileNames`，不返回 `sourceChunks`，历史 assistant 不增加
  `chunks`；本次改造不能反向改变这些既有行为。

### 7.3 当前运行能力边界

- 当前 SQLite Chat 存储、内联 Dispatcher、进程内容量限制和持久化中断轮询只证明单实例
  语义，不是共享数据库、可靠队列、跨实例通知或分布式 fencing。
- 实现必须通过端口、内部 `conversationId` 和任务级对象图为未来共享数据库、可靠任务队列、
  多实例部署及高并发执行保留替换边界，但不得把预留结构描述为已经具备对应能力。
- 当前接口不提供公开 `requestId`/`runId`、幂等键、断线续传、SSE 回放或调用方断开后的后台
  继续生成。未来如需这些能力，必须独立设计并确认版本化合同。
- 当前确认暂不设置 Chunk 数量、单 Chunk 字符数、单轮 Chunk 总字符数或 History 累计大小的
  DocSense 业务上限，也不允许静默截断。这是明确的当前容量风险，不得把 AnythingLLM `topN`
  或单机联调结果解释为稳定的对外容量保证；正式高并发或多实例发布前必须重新评估。
- 应用业务日志可以记录规范化 `userId`、`architectureId`、内部关联标识和排障所需的远端资源
  名称/引用；但不得记录 API Key、Authorization、Cookie、Callback 凭据、用户消息、模型完整
  回答、Chunk 原文、文件正文、原始请求/响应体或未脱敏异常响应。由于 History 使用 Query 参数，
  部署层仍应按实际安全要求治理完整查询串访问日志；应用单元测试不能证明代理、网关和浏览器
  链路已经完成该治理。
- 本合同的代码、离线门禁和本机 AnythingLLM v1.15.0 联调已经完成；负责人明确批准以 Flask
  协议级客户端逐帧验收替代真实浏览器/UI 演练。该结果仍不构成生产发布、多实例、可靠队列、
  高并发容量或仓库外前端页面渲染正确性的证明。
