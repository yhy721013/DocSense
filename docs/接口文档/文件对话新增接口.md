## 1. 生成对话标题接口

**接口路径：** `/llm/chat/title`  
**请求方法：** `POST`  
**功能说明：** 根据对话历史内容，使用大模型对对话进行总结，生成一个简短的对话标题，用于在对话列表中展示。

### 请求参数说明

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| businessType | String | 业务类型标识，固定值：`"chat"` | 是 |
| params | Object | 请求参数（非数组） | 是 |

### params 参数结构

| 字段 | 类型 | 说明 | 必填 | 示例值 |
|------|------|------|------|--------|
| chatId | String | 对话唯一标识 | 是 | `"conv-20260401-001"` |

### 请求示例

```json
{
  "businessType": "chat",
  "params": {
    "chatId": "conv-20260401-001"
  }
}
```

### 响应参数说明

| 字段 | 类型 | 说明 |
|------|------|------|
| chatId | String | 对话唯一标识 |
| title | String | 大模型生成的对话总结标题（通常 ≤ 20 字） |

### 响应示例

#### 成功响应（HTTP 200）

```json
{
  "chatId": "conv-20260401-001",
  "title": "美日国防战略核心观点对比"
}
```

#### 参数缺失（HTTP 400）

```json
{
  "error": "chatId不能为空"
}
```

#### 对话不存在（HTTP 404）

```json
{
  "error": "对话不存在"
}
```

#### 对话历史为空（HTTP 400）

```json
{
  "error": "对话历史为空，无法生成标题"
}
```

### 调用方注意事项

- 该接口为同步请求，响应时间取决于大模型推理速度，通常在 1–5 秒内返回。
- 建议前端在**首轮对话完成后（收到 `done` 事件后）**调用一次，即可获得标题用于对话列表展示。
- 每次调用都会基于当前对话历史重新生成标题，多轮对话后再次调用可获得更准确的标题。
- 标题不由后端持久化，由调用方自行管理存储和缓存。

## 2. 中断流式对话接口

**接口路径：** `/llm/chat/abort`  
**请求方法：** `POST`  
**功能说明：** 中断指定对话当前正在进行的 SSE 流式输出。调用后，服务端停止继续向该 SSE 连接推送 `textChunk`，并发送 `aborted` 终结事件后关闭连接。

### 请求参数说明

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| businessType | String | 业务类型标识，固定值：`"chat"` | 是 |
| params | Object | 请求参数（非数组） | 是 |

### params 参数结构

| 字段 | 类型 | 说明 | 必填 | 示例值 |
|------|------|------|------|--------|
| chatId | String | 要中断的对话唯一标识 | 是 | `"conv-20260401-001"` |

### 请求示例

```json
{
  "businessType": "chat",
  "params": {
    "chatId": "conv-20260401-001"
  }
}
```

### 响应参数说明

| 字段 | 类型 | 说明 |
|------|------|------|
| chatId | String | 对话唯一标识 |
| aborted | Boolean | 中断是否成功受理（`true` 表示已发送中断信号） |
| msg | String | 结果描述 |

### 响应示例

#### 中断成功（HTTP 200）

```json
{
  "chatId": "conv-20260401-001",
  "aborted": true,
  "msg": "已发送中断信号"
}
```

#### 当前无活跃流（HTTP 200）

```json
{
  "chatId": "conv-20260401-001",
  "aborted": false,
  "msg": "当前无进行中的流式响应"
}
```

#### 参数缺失（HTTP 400）

```json
{
  "error": "chatId不能为空"
}
```

### SSE 流侧行为

当 `/llm/chat/abort` 被调用时，正在进行中的 SSE 流会推送一个终结事件后关闭：

```text
event: textChunk
data: {"content": "根据文件内容，核心观点"}

event: aborted
data: {"chatId": "conv-20260401-001"}
```

> `aborted` 事件含义等同于 `done`，表示本次 SSE 连接结束，但**本轮回答是不完整的**。前端接收到 `aborted` 事件后应按 `done` 同样的方式结束流式消费流程。

### 中断后继续对话

- 中断后，已产生的**不完整回答不会**保存到对话历史中。
- 因此中断后前端可以直接发起新一轮 `/llm/chat` 请求，对话上下文不会包含被中断的那条不完整回答。
- 前端收到 `aborted` 事件后，应当：
  1. 停止渲染流式文本
  2. 在 UI 上标记该条回答为"已中断"（可选）
  3. 恢复发送按钮可用状态

### 调用方注意事项

- 该接口为同步请求，服务端收到后立即设置中断标记并返回，流的实际终止可能有微小延迟（通常 < 100ms）。
- 仅对当前正在进行中的 SSE 流有效；若流已自然结束（`done`）或尚未开始，返回 `aborted: false`。
- 前端在调用 `/llm/chat/abort` 的同时**不应关闭 SSE 连接**，等待 `aborted` 事件到达后再清理。
