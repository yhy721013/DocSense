# 文件对话新增接口文档

> 本文档是 [文件对话.md](文件对话.md) 的扩展，新增「生成对话标题」和「中断流式对话」两个接口。

> 本文中的 `chatId` 与基础文件对话接口保持同一契约：`POST` JSON 中必须传 JSON number 正整数（如 `10001`），严格拒绝字符串、布尔值、浮点数、`0` 和负数；JSON/SSE 回显也始终为 number 整数。完整 Query 传递规则见 [文件对话.md](文件对话.md#chatid-类型约束)。

## 目录

1. [生成对话标题接口]

## 1. 生成对话标题接口

**接口路径：** `/llm/chat/title`  
**请求方法：** `POST`  
**功能说明：** 根据对话历史内容，使用大模型对对话进行总结，生成一个简短的对话标题，用于在对话列表中展示。

### 请求参数说明

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| businessType | String | 业务类型标识，固定值：`"chat"` | 是 |
| params | Object | 请求参数（非数组） | 是 |

### params 参数结构

| 字段 | 类型 | 说明 | 必填 | 示例值 |
|------|------|------|------|--------|
| chatId | Integer | 正整数对话唯一标识 | 是 | `10001` |

### 请求示例

```json
{
  "businessType": "chat",
  "params": {
    "chatId": 10001
  }
}
```

### 响应参数说明

| 字段 | 类型 | 说明 |
|------|------|------|
| chatId | Integer | 正整数对话唯一标识 |
| title | String | 大模型生成的对话总结标题，最多 20 个中文字符；服务端强制截断 |

### 响应示例

#### 成功响应（HTTP 200）

```json
{
  "chatId": 10001,
  "title": "美日国防战略核心观点对比"
}
```

#### chatId 无效（HTTP 400）

```json
{
  "error": "chatId必须为正整数"
}
```

#### 对话不存在（正常返回空标题，HTTP 200）

```json
{
  "chatId": 10001,
  "title": ""
}
```

#### 对话历史为空（HTTP 400）

```json
{
  "error": "对话历史为空，无法生成标题"
}
```

#### 对话正在删除或清理失败（HTTP 409）

会话进入删除流程后，标题接口不会创建临时远端资源：

```json
{
  "error": "chat session is not available for title generation"
}
```

#### 标题生成或临时资源清理失败（HTTP 500）

标题生成使用与主对话隔离的临时远端会话。模型调用或该临时会话的清理无法完成时，接口返回既有的 `error` 字段；服务端会保留内部清理恢复记录，但不会向调用方暴露内部资源标识或新增任务参数。

```json
{
  "error": "标题生成失败，请稍后重试"
}
```

### 调用方注意事项

- 该接口为同步请求，响应时间取决于大模型推理速度，通常在 1–5 秒内返回。
- 建议前端在**首轮对话完成后（收到 `done` 事件后）**调用一次，即可获得标题用于对话列表展示。
- 每次调用都会基于当前对话历史重新生成标题，多轮对话后再次调用可获得更准确的标题。
- 标题最多 20 个中文字符；服务端会对模型输出做清理并强制截断，调用方可直接展示。
- 若对话不存在，接口返回 HTTP 200 且 `title` 为空字符串，调用方可继续使用默认标题或本地缓存标题。
- 标题不由后端持久化，由调用方自行管理存储和缓存。
- 标题只允许在会话处于可用状态时生成；删除中、已删除或待清理失败的会话返回 HTTP 409。
- 当前单实例模式会在本次标题请求内同步尝试清理临时会话；失败后仅保留内部恢复记录，不会在调用方连接之外持续执行后台标题任务。

## 2. 中断流式对话接口

**接口路径：** `/llm/chat/abort`  
**请求方法：** `POST`  
**功能说明：** 中断指定对话当前正在进行的 SSE 流式输出。调用后，服务端停止继续向该 SSE 连接推送 `textChunk`，并发送 `aborted` 终结事件后关闭连接。

> 同一 `chatId` 同时只允许一个活跃流式响应。若某个 `chatId` 已有未结束的 `/llm/chat` SSE 流，服务端会拒绝同一 `chatId` 的新 `/llm/chat` 请求；调用方需等待该流收到 `done`、`aborted` 或 `error` 终结事件后再继续。

### 活跃流并发约束

该约束适用于 `POST /llm/chat`：

```json
{
  "error": "当前对话已有进行中的流式响应"
}
```

当同一 `chatId` 已存在活跃 SSE 流时，重复发起 `/llm/chat` 返回 HTTP 409。不同 `chatId` 的流式请求互不影响。

### 请求参数说明

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| businessType | String | 业务类型标识，固定值：`"chat"` | 是 |
| params | Object | 请求参数（非数组） | 是 |

### params 参数结构

| 字段 | 类型 | 说明 | 必填 | 示例值 |
|------|------|------|------|--------|
| chatId | Integer | 要中断的正整数对话唯一标识 | 是 | `10001` |

### 请求示例

```json
{
  "businessType": "chat",
  "params": {
    "chatId": 10001
  }
}
```

### 响应参数说明

| 字段 | 类型 | 说明 |
|------|------|------|
| chatId | Integer | 正整数对话唯一标识 |
| aborted | Boolean | 中断是否成功受理（`true` 表示已发送中断信号） |
| msg | String | 结果描述 |

### 响应示例

#### 中断成功（HTTP 200）

```json
{
  "chatId": 10001,
  "aborted": true,
  "msg": "已发送中断信号"
}
```

#### 当前无活跃流（HTTP 200）

```json
{
  "chatId": 10001,
  "aborted": false,
  "msg": "当前无进行中的流式响应"
}
```

#### chatId 无效（HTTP 400）

```json
{
  "error": "chatId必须为正整数"
}
```

### SSE 流侧行为

当 `/llm/chat/abort` 被调用时，正在进行中的 SSE 流会推送一个终结事件后关闭：

```text
event: textChunk
data: {"content": "根据文件内容，核心观点"}

event: aborted
data: {"chatId": 10001}
```

> `aborted` 事件含义等同于 `done`，表示本次 SSE 连接结束，但**本轮回答是不完整的**。前端接收到 `aborted` 事件后应按 `done` 同样的方式结束流式消费流程。

### 中断后继续对话

- 中断后，已产生的**不完整回答不会**保存到对话历史中。
- 因此中断后前端可以直接发起新一轮 `/llm/chat` 请求，对话上下文不会包含被中断的那条不完整回答。
- 前端收到 `aborted` 事件后，应当：
  1. 停止渲染流式文本
  2. 在 UI 上标记该条回答为"已中断"（可选）
  3. 恢复发送按钮可用状态

### 调用方注意事项

- 该接口为同步请求，服务端收到后立即设置中断标记并返回。当前实现会在流式执行循环消费下一条上游事件前、以及处理刚取到的上游事件前检查中断标记；若上游长时间没有新片段返回，SSE 实际收到 `aborted` 事件可能略有延迟。
- 仅对当前正在进行中的 SSE 流有效；若流已自然结束（`done`）或尚未开始，返回 `aborted: false`。
- 同一 `chatId` 同时只允许一个活跃流；重复发起同一 `chatId` 的 `/llm/chat` 会返回 HTTP 409，调用方应在上一条流结束后再发起下一条请求。
- 前端在调用 `/llm/chat/abort` 的同时**不应关闭 SSE 连接**，等待 `aborted` 事件到达后再清理。
