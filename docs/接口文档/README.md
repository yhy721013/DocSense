## 文件对话契约使用流程

1. 修改路由、展示层或应用服务前，先确认接口路径、请求字段、响应字段、状态码、响应头和 SSE 事件是否受影响。
2. `/llm/chat` 的既有字段和 SSE `chatInfo`、`textChunk`、`done` 格式属于冻结行为；其中 `chatId` 的值类型为正整数，JSON 请求严格拒绝字符串、布尔值、零和负数；内部 `run_id`、租约和任务标识不得泄露。首次空数组只改变 `fileNames` 的条件语义，不允许借机扩展协议。
3. 标题、中断、历史和删除接口也必须保持现有 JSON 结构及错误语义与 `chatId` 正整数契约。
4. 如果产品确实需要新的可见运行状态、重放、续传或幂等能力，应独立设计并确认版本化接口，不能修改现有参数列表。

## 维护规则

- 本目录描述的是调用方可观察行为，不记录供应商字段、SQLite 表名或内部实现细节。
- 文档和代码发生冲突时，先暂停可能改变契约的实现，确认后再修复。
- 文档变更必须同步补充路由测试，特别是 SSE 帧格式和未泄露内部标识的断言。
- 已确认但尚未实现的目标契约必须标注实施波次，不能把目标行为误写成当前代码已经具备。
