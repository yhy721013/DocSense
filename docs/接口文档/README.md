# 接口文档目录说明

本目录是项目对外 HTTP、SSE 与 WebSocket 契约的权威来源。任何涉及公开接口的代码改动，必须先核对此目录；若可能影响文档内容，必须先取得确认。除 2026-07-15 已明确批准的任务受理/check-task 成功空响应体和 Progress 显式 action 下线外，不得新增、删除或改变前后端接口参数与消息字段。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `文件对话.md` | 文件对话的基础接口说明，包括创建流式对话、历史查询和删除等既有契约。 |
| `文件对话新增接口.md` | 文件对话新增接口说明，包括标题生成、中断及其返回语义。 |
| `文件处理和报告生成.md` | 文件处理、报告生成相关接口。 |
| `知识谱系解析.md` | 知识谱系解析接口。 |
| `分类节点变更.md` | 分类节点变更接口。 |

## 文件对话契约使用流程

1. 修改路由、展示层或应用服务前，先确认接口路径、请求字段、响应字段、状态码、响应头和 SSE 事件是否受影响。
2. `/llm/chat` 的既有字段和 SSE `chatInfo`、`textChunk`、`done` 格式属于冻结行为；其中 `chatId` 的值类型为正整数，JSON 请求严格拒绝字符串、布尔值、零和负数；内部 `run_id`、租约和任务标识不得泄露。
3. 标题、中断、历史和删除接口也必须保持现有 JSON 结构及错误语义与 `chatId` 正整数契约。
4. 如果产品确实需要新的可见运行状态、重放、续传或幂等能力，应独立设计并确认版本化接口，不能修改现有参数列表。

## 维护规则

- 本目录描述的是调用方可观察行为，不记录供应商字段、SQLite 表名或内部实现细节。
- 文档和代码发生冲突时，先暂停可能改变契约的实现，确认后再修复。
- 文档变更必须同步补充路由测试，特别是 SSE 帧格式和未泄露内部标识的断言。
- 已确认但尚未实现的目标契约必须标注实施波次，不能把目标行为误写成当前代码已经具备。
