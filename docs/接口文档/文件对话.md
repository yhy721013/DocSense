## 1. 发送对话消息接口（SSE 流式）

**接口路径：** `/llm/chat`  
**请求方法：** `POST`  
**响应方式：** SSE（Server-Sent Events）流式输出  
**Content-Type：** `text/event-stream`  
**功能说明：** 基于指定文件内容，向大模型发送用户问题并以 SSE 流式返回回答。若对话 ID 不存在则自动创建对话；若传入新增文件则自动追加引用。

### chatId 类型约束

所有 `/llm/chat*` 接口中的 `chatId` 统一使用**正整数**，例如 `10001`：

- 对于 `POST` JSON 请求体，`chatId` 必须是 JSON number 整数，不能加引号。
- 服务端严格拒绝字符串、布尔值、浮点数、`0` 和负数，统一返回 HTTP 400 与 `{"error": "chatId必须为正整数"}`。
- 所有 JSON 和 SSE 响应中的 `chatId` 也为 number 整数，不会回显字符串。
- `GET` Query 参数受 URL 编码机制限制以文本传输，调用方应使用无符号、无前导零的十进制形式，例如 `?chatId=10001`；`0`、负数、小数、前导零和非数字文本均会被拒绝。
- 不兼容历史字符串会话 ID；调用方需要使用新的正整数 ID 创建或访问会话。

### 请求参数说明

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| businessType | String | 业务类型标识，固定值：`"chat"` | 是 |
| params | Object | 对话参数（非数组） | 是 |

### params 参数结构

| 字段 | 类型 | 说明 | 必填 | 示例值 |
|------|------|------|------|--------|
| chatId | Integer | 正整数对话唯一标识（由调用方生成） | 是 | `10001` |
| fileNames | Array\<String\> | 本次新增引用的文件列表（增量，已解析过的文件）。新对话或继续对话均可为空数组 `[]` 表示不引用新文件 | 是 | `["abc123.pdf"]` |
| message | String | 用户发送的问题内容 | 是 | `"请总结这份文件的核心观点"` |

> 调用方无需传入此前的对话历史消息，后端自动维护对话上下文的连贯性。

### 请求示例

```json
{
  "businessType": "chat",
  "params": {
    "chatId": 10001,
    "fileNames": [
      "abc123def456.pdf",
      "789ghi012jkl.docx"
    ],
    "message": "请总结这两份文件的核心观点"
  }
}
```

### SSE 事件流说明

连接成功后，服务端以 `text/event-stream` 格式逐步推送以下事件：

#### 事件类型

| event | data 内容 | 说明 |
|-------|-----------|------|
| `chatInfo` | `{"chatId": 10001, "isNewChat": true/false}` | 首个事件，返回对话元信息 |
| `textChunk` | `{"content": "..."}` | 大模型回答的文本片段，可能多次推送 |
| `done` | `{"chatId": 10001}` | 流式输出完成 |
| `error` | `{"error": "..."}` | 出错时推送，推送后关闭连接 |

#### SSE 流示例

```text
event: chatInfo
data: {"chatId": 10001, "isNewChat": true}

event: textChunk
data: {"content": "根据文件内容，"}

event: textChunk
data: {"content": "核心观点包括："}

event: textChunk
data: {"content": "1. ......"}

event: done
data: {"chatId": 10001}
```

### 错误响应

参数校验等在建立 SSE 连接前发生的错误，仍以普通 JSON 响应返回：

#### 参数错误（HTTP 400）

```json
{
  "error": "chatId必须为正整数"
}
```

#### 引用文件未解析（HTTP 404）

```json
{
  "error": "文件 abc123.pdf 尚未解析，无法用于对话"
}
```

#### 同一对话已有活跃流（HTTP 409）

同一 `chatId` 的上一条流尚未收到 `done`、`error` 或 `aborted` 时，服务端不会再次调用模型：

```json
{
  "error": "当前对话已有进行中的流式响应"
}
```

#### 进程内流容量已满（HTTP 429）

当前 SQLite 运行模式有明确的单进程流容量上限；达到上限时本次请求尚未创建会话或 run：

```json
{
  "error": "文件对话并发流已达上限，请稍后重试"
}
```

SSE 连接建立后的运行时错误，通过 `error` 事件推送：

```text
event: error
data: {"error": "大模型服务响应异常"}
```

### 客户端主动关闭 SSE 连接

当前接口不支持断线续传、SSE 回放或在调用方断开后继续后台生成。客户端主动关闭连接时，服务端会停止本次执行并按执行进度收敛本地状态：

- 若连接在服务端领取 run 的执行权前关闭，本次请求不会调用模型；待提交的 user 消息会被丢弃，历史接口中不会出现该轮。
- 若服务端已开始执行该 run，服务端会终止流并把 run 标记为失败；user 消息会保留在历史中，不完整的 assistant 片段不会保存。连接已关闭时，调用方可能收不到最终 `error` 事件。

调用方如需继续对话，可重新发起既有的 `POST /llm/chat`；无需也不能传递内部 run 标识。

## 2. 获取对话历史接口

**接口路径：** `/llm/chat/history`  
**请求方法：** `GET`  
**功能说明：** 根据 `chatId` 获取指定对话的历史消息记录。

### 请求参数说明

| 参数 | 类型 | 传递方式 | 说明 | 必填 |
|------|------|----------|------|------|
| chatId | Integer | Query 参数 | 正整数对话唯一标识；URL 中以规范十进制文本传输 | 是 |

### 请求示例

```
GET /llm/chat/history?chatId=10001
```

### 响应参数说明

响应体为数组，数组元素表示一条历史消息（按时间正序）。

### 数组元素结构

| 字段 | 类型 | 说明 |
|------|------|------|
| role | String | 消息角色：`"user"` 或 `"assistant"` |
| content | String | 消息内容 |
| timestamp | Number \| null | 消息时间戳（毫秒） |
| files | Array\<Object\> | 仅当 role 为 `"user"` 时存在，记录该次对话关联文件 |

### files 数组元素结构

| 字段 | 类型 | 说明 |
|------|------|------|
| name | String | 文件原名 |

### 响应示例

#### 成功响应（HTTP 200）

```json
[
  {
    "role": "user",
    "content": "请总结这两份文件的核心观点",
    "timestamp": 1777364120677,
    "files": [
      { "name": "美军2025年度国防战略报告.pdf" },
      { "name": "日本防卫白皮书2024.docx" }
    ]
  },
  {
    "role": "assistant",
    "content": "根据文件内容，核心观点包括：1. ...... 2. ......",
    "timestamp": 1777364120678
  }
]
```

#### chatId 无效（HTTP 400）

```json
{
  "error": "chatId必须为正整数"
}
```

#### 对话不存在（正常返回空状态，HTTP 200）

```json
[]
```

## 3. 删除对话接口

**接口路径：** `/llm/chat/delete`  
**请求方法：** `POST`  
**功能说明：** 删除指定对话，同步清理后端资源

### 请求参数说明

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| businessType | String | 固定值：`"chat"` | 是 |
| params | Object | 删除参数 | 是 |

### params 参数结构

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| chatId | Integer | 要删除的正整数对话唯一标识 | 是 |

### 请求示例

```json
{
  "businessType": "chat",
  "params": {
    "chatId": 10001
  }
}
```

### 响应示例

#### 删除成功（HTTP 200）

```json
{
  "chatId": 10001,
  "deleted": true,
  "msg": "对话已删除"
}
```

#### 对话不存在（HTTP 404）

```json
{
  "error": "对话不存在"
}
```

#### 后端资源清理失败（HTTP 500）

远端资源清理失败时，后端不会删除本地恢复记录；该对话会保留资源租约错误状态，供后续巡检或人工补偿。

```json
{
  "chatId": 10001,
  "deleted": false,
  "error": "对话资源清理失败"
}
```

#### 对话正在运行或删除（HTTP 409）

删除会先取得会话删除权。若该会话仍有活跃流，调用方应先调用 `/llm/chat/abort` 并等待流返回 `aborted`，再发起删除；若该会话正在生成标题，也会返回 HTTP 409，调用方应等待标题请求结束后重试删除：

```json
{
  "chatId": 10001,
  "deleted": false,
  "error": "当前对话存在进行中的流式响应，请先中断后删除"
}
```

## 4. 调用方职责说明

以下数据与功能由调用方自行维护。

### 4.1 对话列表管理

调用方应在自身系统中维护对话列表，记录正整数 `chatId`（对话唯一标识）、创建者等信息。

当调用方不再需要某对话时，应调用 `/llm/chat/delete` 通知后端同步释放资源。

### 4.2 对话历史

调用方可通过 `/llm/chat/history` 接口随时获取指定对话的完整历史消息，用于界面展示和回溯。已删除完成的对话会返回空数组；删除过程中或资源清理失败的对话仍可返回本地已提交历史，便于排查和补偿。

历史以本地已提交消息为准：`done` 时保存完整 user/assistant；`error` 或 `aborted` 时保留 user，但不会保存不完整 assistant。

客户端断开连接的细则见“客户端主动关闭 SSE 连接”：执行尚未开始的请求不会产生历史；执行已开始的请求会保留 user，且不保存不完整 assistant。

### 4.3 当前运行限制

- 当前 `chat_sessions.sqlite3` 仅支持**单应用实例**运行；不得把 SQLite 文件放在共享目录后启动多个副本。
- 单请求文件数、消息长度、输出长度和进程内同时流数受 `DOCSENSE_CHAT_MAX_FILES`、`DOCSENSE_CHAT_MAX_MESSAGE_CHARS`、`DOCSENSE_CHAT_MAX_OUTPUT_CHARS`、`DOCSENSE_CHAT_MAX_CONCURRENT_STREAMS` 限制。
- 当前接口不提供 `requestId`/`runId` 对外幂等、断线恢复或 SSE 回放语义；如未来确有需要，必须通过独立版本化接口重新立项，既有 `/llm/chat*` 契约保持不变。
