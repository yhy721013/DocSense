

# 文档分类节点变更接口

```
接口路径： /llm/reassign
请求方法： POST
```

## 一、功能说明

当前端修改了某个文档所属的分类节点（`architectureId`）后，通过本接口将变更同步至后端，使后续的知识谱系解析等操作能基于正确的分类节点进行。

> 💡 **核心行为**：  
> 本接口为**同步接口**，处理完成后直接返回结果，不涉及后台异步任务、进度推送或回调。若本地记录包含 `doc_path`，服务端会在更新 DocSense 本地分类前，尝试将文档从旧 AnythingLLM workspace 删除并加入新 workspace；不触发重新解析任务。

---

## 二、请求参数字段说明

### 📌 根对象

| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| **businessType** | String | 是 | 业务类型标识，固定值 | `"reassign"` |
| **params** | Object | 是 | 变更参数 | `{...}` |

---

### 📌 params 对象结构

| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| **fileName** | String | 是 | 文件对象名（业务主键） | `"bded228dc94440519d87f97cfb6b520b.pdf"` |
| **oldArchitectureId** | Long | 是 | 变更前的分类节点 ID；当前实现会在查询本地记录时执行 `int(...)` 转换 | `1768464916588441` |
| **newArchitectureId** | Long | 是 | 变更后的分类节点 ID；当前实现仅校验非空，调用方仍应传入 Long 数值 | `1768464916588442` |

> ⚠️ **校验规则**：  
> - `fileName` 必须为非空字符串。
> - `oldArchitectureId` 与 `newArchitectureId` 不能为 `null`。
> - 服务端在原始请求值层面比较 `oldArchitectureId` 与 `newArchitectureId`，相等时返回 HTTP 400。调用方应以同一原生数值类型传入分类 ID，避免 `1` 与 `"1"` 这类语义相同但原始值不相等的请求绕过该校验。
> - `oldArchitectureId` 在本地查询前会执行 `int(...)` 转换；无法转换为整数的值会在当前实现中产生未包装的 HTTP 500。
> - `newArchitectureId` 当前未做严格整数类型校验；接口契约仍要求调用方传入 Long 数值。

---

## 三、请求示例

```json
{
  "businessType": "reassign",
  "params": {
    "fileName": "bded228dc94440519d87f97cfb6b520b.pdf",
    "oldArchitectureId": 1768464916588441,
    "newArchitectureId": 1768464916588442
  }
}
```

---

## 四、响应参数说明

### 📌 变更成功响应（HTTP 200）

| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **businessType** | String | 业务类型标识 | `"reassign"` |
| **msg** | String | 顶层处理结果概述 | `"变更成功"` |
| **data** | Object | 变更结果详情 | 见下方结构 |

### 📌 业务处理失败响应（HTTP 500）

业务处理中未找到本地记录、触发防御性分类一致性校验，或远端知识库迁移抛出异常时，服务端返回 HTTP 500。响应结构与成功响应一致，但 `data.success` 为 `false`，顶层字段仍为 `msg`。

### 📌 data 元素结构

| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **fileName** | String | 文件对象名 | `"bded228dc94440519d87f97cfb6b520b.pdf"` |
| **oldArchitectureId** | Long | 变更前分类节点 ID | `1768464916588441` |
| **newArchitectureId** | Long | 变更后分类节点 ID | `1768464916588442` |
| **success** | Boolean | 本条记录是否变更成功 | `true` |
| **message** | String | 本条记录处理描述 | `"变更成功"` / `"文档记录不存在"` / `"分类不一致，变更失败"` |

---

## 五、响应示例

### 变更成功

```json
{
  "businessType": "reassign",
  "msg": "变更成功",
  "data": {
    "fileName": "bded228dc94440519d87f97cfb6b520b.pdf",
    "oldArchitectureId": 1768464916588441,
    "newArchitectureId": 1768464916588442,
    "success": true,
    "message": "变更成功"
  }
}
```

### 文档记录不存在（HTTP 500）

```json
{
  "businessType": "reassign",
  "msg": "变更失败",
  "data": {
    "fileName": "bded228dc94440519d87f97cfb6b520b.pdf",
    "oldArchitectureId": 1768464916588441,
    "newArchitectureId": 1768464916588442,
    "success": false,
    "message": "文档记录不存在"
  }
}
```

### 分类不一致（HTTP 500）

该分支是防御性校验：当前 `DatabaseService` 已按 `fileName + oldArchitectureId` 查询，本地正常实现通常会在前一分支返回“文档记录不存在”。只有查询服务返回的记录分类与请求旧分类不一致时，才会进入本分支。

```json
{
  "businessType": "reassign",
  "msg": "变更失败",
  "data": {
    "fileName": "bded228dc94440519d87f97cfb6b520b.pdf",
    "oldArchitectureId": 1768464916588441,
    "newArchitectureId": 1768464916588442,
    "success": false,
    "message": "分类不一致，变更失败"
  }
}
```

## 六、错误响应

### 参数校验失败（HTTP 400）

```json
{
  "error": "fileName不能为空"
}
```

```json
{
  "error": "oldArchitectureId与newArchitectureId不能相同"
}
```

```json
{
  "error": "params不能为空"
}
```

```json
{
  "error": "businessType必须为reassign"
}
```

### 当前实现中未包装的旧分类 ID 转换失败（HTTP 500）

当 `oldArchitectureId` 不是可被 `int(...)` 转换的值（例如 `"abc"`、对象或数组）时，转换发生在业务异常处理块之前。当前实现会由 Flask 返回未统一定义的 HTTP 500 响应，而不是本节的 HTTP 400 参数错误结构。

### 业务处理失败（HTTP 500）

下列场景返回第四节所述的 `businessType + msg + data` 结构，且 `data.success=false`：

- 未找到同时匹配 `fileName` 和 `oldArchitectureId` 的本地文档记录；
- 查询服务返回的文档记录与 `oldArchitectureId` 不一致；
- AnythingLLM 文档迁移过程抛出异常。

---

## 七、处理逻辑说明

1. **参数校验**：校验 `businessType="reassign"`、`params` 为对象、`fileName` 为非空字符串、新旧分类 ID 非 `null`，并拒绝原始请求值相等的新旧分类 ID。
2. **精确查询本地记录**：按 `fileName + int(oldArchitectureId)` 查询 DocSense `documents` 表。未命中时返回“文档记录不存在”及 HTTP 500；这也包含“文件存在但已不属于请求旧分类”的情况。
3. **防御性一致性校验**：比对查询结果中的 `architecture_id` 与请求 `oldArchitectureId`。当前 `DatabaseService` 已在查询条件中限定旧分类，因此正常本地实现下该分支通常不可达；若底层查询服务返回分类不同的记录，接口返回“分类不一致，变更失败”及 HTTP 500。
4. **尝试迁移 AnythingLLM 文档**：仅当本地记录存在 `doc_path` 时执行：从旧 workspace 删除文档；查找新 workspace，不存在时创建 `architectureId-{newArchitectureId}` 并保存本地 workspace 映射；随后将文档加入新 workspace，并携带 `file_name`、`architecture_id` metadata。
5. **更新本地分类**：使用 `fileName + int(oldArchitectureId)` 精确限定更新行，将该行的 `architecture_id` 更新为 `newArchitectureId`。若 `doc_path` 为空，则跳过远端迁移，直接执行本地更新。
6. **返回结果**：本地更新完成后返回 HTTP 200、顶层 `msg="变更成功"` 和 `data.success=true`。

> 💡 **说明**：  
> - 远端迁移步骤以“是否抛出异常”为失败判定；当前实现不检查 `update_embeddings_batch`、`update_embeddings` 的布尔返回值，创建 workspace 未取得 slug 时也不会主动抛错。因此接口返回 HTTP 200 表示流程未抛出异常并完成本地更新，不等价于远端迁移结果已被逐项确认。
> - 远端删除、远端加入和本地更新之间没有跨系统事务或补偿回滚；远端步骤抛出异常时，已经完成的前置远端操作不会自动撤销。
> - 本接口不触发重新解析任务。若需在变更后重新解析，请单独调用 `/llm/weaponry` 接口。
