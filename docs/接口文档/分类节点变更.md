

# 文档分类节点变更接口

```
接口路径： /llm/reassign
请求方法： POST
```

## 一、功能说明

当前端修改了某个文档所属的分类节点（`architectureId`）后，通过本接口将变更同步至后端，使后续的知识谱系解析等操作能基于正确的分类节点进行。

> 💡 **核心行为**：  
> 本接口为**同步接口**，处理完成后直接返回结果，不涉及后台异步任务、进度推送或回调。若本地记录包含 `doc_path`，服务端会在更新 DocSense 本地分类前，尝试将文档从旧 AnythingLLM workspace 删除并加入新 workspace；不触发重新解析任务。

---

## 二、请求参数字段说明

### 📌 根对象

| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| **businessType** | String | 是 | 业务类型标识，固定值 | `"reassign"` |
| **params** | Object | 是 | 变更参数 | `{...}` |

---

### 📌 params 对象结构

| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| **fileName** | String | 是 | 文件对象名（业务主键） | `"bded228dc94440519d87f97cfb6b520b.pdf"` |
| **oldArchitectureId** | Long | 是 | 变更前的分类节点 ID；当前实现会在查询本地记录时执行 `int(...)` 转换 | `1768464916588441` |
| **newArchitectureId** | Long | 是 | 变更后的分类节点 ID；接口契约要求 Long，服务端另保留下述有限历史兼容 | `1768464916588442` |

> ⚠️ **校验规则**：  
> - `fileName` 必须为非空字符串。
> - `oldArchitectureId` 与 `newArchitectureId` 不能为 `null`。
> - 服务端在原始请求值层面比较 `oldArchitectureId` 与 `newArchitectureId`，相等时返回 HTTP 400。调用方应以同一原生数值类型传入分类 ID，避免 `1` 与 `"1"` 这类语义相同但原始值不相等的请求绕过该校验。
> - `oldArchitectureId` 在本地查询前会执行 `int(...)` 转换；无法转换为整数的值会在当前实现中产生未包装的 HTTP 500。
> - `newArchitectureId` 的正式契约仍是 Long。为兼容已经冻结的历史调用，当前服务端还接受 JSON `false`、有符号 64 位整数和可按十进制解析的整数字符串（允许前后空白及正负号）；不再接受 `true`、浮点数、小数字符串、科学计数法字符串、非数字文本、对象、数组或超出有符号 64 位范围的值。
> - 在通过前述“原始值不相等”校验后，上述不兼容值会在创建 Saga Operation 和执行任何本地/远端副作用前失败。为避免新增 HTTP 400 契约，该失败沿用当前未包装 HTTP 500 边界，响应体不作统一保证。

---

## 三、请求示例

```json
{
  "businessType": "reassign",
  "params": {
    "fileName": "bded228dc94440519d87f97cfb6b520b.pdf",
    "oldArchitectureId": 1768464916588441,
    "newArchitectureId": 1768464916588442
  }
}
```

---

## 四、响应参数说明

### 📌 变更成功响应（HTTP 200）

| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **businessType** | String | 业务类型标识 | `"reassign"` |
| **msg** | String | 顶层处理结果概述 | `"变更成功"` |
| **data** | Object | 变更结果详情 | 见下方结构 |

### 📌 业务处理失败响应（HTTP 500）

业务处理中未找到本地记录、触发防御性分类一致性校验，远端知识库操作抛出异常或明确返回失败，目标 workspace 未能成功创建，或本地条件更新未成功命中唯一记录时，服务端返回 HTTP 500。响应结构与成功响应一致，但 `data.success` 为 `false`，顶层字段仍为 `msg`。

### 📌 data 元素结构

| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **fileName** | String | 文件对象名 | `"bded228dc94440519d87f97cfb6b520b.pdf"` |
| **oldArchitectureId** | Long | 变更前分类节点 ID | `1768464916588441` |
| **newArchitectureId** | Long | 变更后分类节点 ID | `1768464916588442` |
| **success** | Boolean | 本条记录是否变更成功 | `true` |
| **message** | String | 本条记录处理描述；只返回下表列出的稳定业务文案，不包含内部异常详情 | `"变更成功"` / `"知识库节点迁移失败"` |

### 📌 稳定 message 对照表

以下文案属于公开接口契约。调用方可以直接展示，但不应通过解析自然语言推断内部
Operation、lease、fencing 或供应商错误；服务端不会在这些文案后拼接异常正文。

| 场景 | HTTP | `data.message` |
|------|------|----------------|
| 变更成功 | 200 | `"变更成功"` |
| 文档记录不存在 | 500 | `"文档记录不存在"` |
| 请求旧分类与查询记录不一致 | 500 | `"分类不一致，变更失败"` |
| AnythingLLM 删除、创建、加入或明确远端失败 | 500 | `"知识库节点迁移失败"` |
| 本地条件更新未恰好命中一条记录 | 500 | `"文档状态已变化，分类变更失败"` |
| 同一文档已有活动中的分类变更 | 500 | `"文档分类正在变更，请稍后重试"` |
| 已执行的知识库关联恢复明确失败 | 500 | `"知识库关联恢复失败"` |
| 外部写、提交或恢复结果暂时无法确认 | 500 | `"变更结果暂无法确认，请稍后重试"` |

> 上述场景继续使用既有 `businessType + msg + data` 响应字段；顶层
> `msg` 均保持 `"变更失败"`。本次只冻结文案，不增加错误码、任务 ID 或其他响应字段。

```json

  "msg": "变更失败",
  "data": {
    "fileName": "bded228dc94440519d87f97cfb6b520b.pdf",

    "newArchitectureId": 1768464916588442,
```

### 分类不一致（HTTP 500）

该分支是防御性校验：当前 `DatabaseService` 已按 `fileName + oldArchitectureId` 查询，本地正常实现通常会在前一分支返回“文档记录不存在”。只有查询服务返回的记录分类与请求旧分类不一致时，才会进入本分支。

```json
{
  "businessType": "reassign",
  "msg": "变更失败",
  "data": {
    "fileName": "bded228dc94440519d87f97cfb6b520b.pdf",
    "oldArchitectureId": 1768464916588441,
    "newArchitectureId": 1768464916588442,
    "success": false,
    "message": "分类不一致，变更失败"
  }
}
```

## 六、错误响应

### 参数校验失败（HTTP 400）

```json
{
  "error": "fileName不能为空"
}
```

```json
{
  "error": "oldArchitectureId与newArchitectureId不能相同"
}
```

```json
{
  "error": "params不能为空"
}
```

```json
{
  "error": "businessType必须为reassign"
}
```

### 当前实现中未包装的旧分类 ID 转换失败（HTTP 500）

当 `oldArchitectureId` 不是可被 `int(...)` 转换的值（例如 `"abc"`、对象或数组）时，转换发生在业务异常处理块之前。当前实现会由 Flask 返回未统一定义的 HTTP 500 响应，而不是本节的 HTTP 400 参数错误结构。

### 业务处理失败（HTTP 500）

下列场景返回第四节所述的 `businessType + msg + data` 结构，且 `data.success=false`：

- 未找到同时匹配 `fileName` 和 `oldArchitectureId` 的本地文档记录；
- 查询服务返回的文档记录与 `oldArchitectureId` 不一致；
- AnythingLLM 文档删除、挂载或 embedding 更新抛出异常，或明确返回 `false`；
- 目标 workspace 不存在且创建后仍未取得有效 workspace 引用；
- 本地分类条件更新未成功命中唯一记录；此时必须执行可行补偿，不得返回虚假成功；
- 同一文档已经存在活动分类变更；
- 同步补偿明确失败，或当前请求预算内仍无法证明本地与远端状态已经一致。

公开 HTTP 500 结构不变，但 `data.message` 按已确认事实使用以下稳定文案：

| 场景 | `data.message` |
|------|----------------|
| 远端迁移明确失败，或远端失败后同步补偿已经完成 | `知识库节点迁移失败` |
| 本地条件 CAS 冲突，或冲突后的同步补偿已经完成 | `文档状态已变化，分类变更失败` |
| 同一文档存在活动分类变更 | `文档分类正在变更，请稍后重试` |
| 同步补偿得到明确失败结果 | `知识库关联恢复失败` |
| 结果未知、预算耗尽、检查点冲突，或仍需恢复流程继续处理 | `变更结果暂无法确认，请稍后重试` |

远端异常只记录到服务端脱敏日志。任何公开响应都不得返回 API Key、Authorization、供应商响应正文、
数据库路径、Operation ID、租约、fencing、步骤或堆栈。

## 七、处理逻辑说明

1. **参数校验**：校验 `businessType="reassign"`、`params` 为对象、`fileName` 为非空字符串、新旧分类 ID 非 `null`，并拒绝原始请求值相等的新旧分类 ID；目标 ID 只保留上文列出的有限历史兼容值。
2. **精确查询本地记录**：按 `fileName + int(oldArchitectureId)` 查询 DocSense `documents` 表。未命中时返回“文档记录不存在”及 HTTP 500；这也包含“文件存在但已不属于请求旧分类”的情况。
3. **防御性一致性校验**：比对查询结果中的 `architecture_id` 与请求 `oldArchitectureId`。当前 `DatabaseService` 已在查询条件中限定旧分类，因此正常本地实现下该分支通常不可达；若底层查询服务返回分类不同的记录，接口返回“分类不一致，变更失败”及 HTTP 500。
4. **尝试迁移 AnythingLLM 文档**：仅当本地记录存在 `doc_path` 时执行：从旧 workspace 删除文档；查找新 workspace，不存在时创建 `architectureId-{newArchitectureId}` 并保存本地 workspace 映射；随后将文档加入新 workspace，并携带 `file_name`、`architecture_id` metadata。任一远端步骤抛出异常、明确返回 `false` 或未取得必要目标引用，均按业务失败进入补偿，不继续伪装成功。对已经确认产生的前向副作用，同步请求会优先按“解绑目标、恢复来源”的固定顺序补偿；明确补偿失败或结果未知时保留恢复现场。
5. **更新本地分类**：使用 `fileName + int(oldArchitectureId)` 精确限定更新行，将该行的 `architecture_id` 更新为 `newArchitectureId` 对应的数据库整数，并要求条件更新恰好命中一条记录；未命中或命中数量异常均按业务失败处理，并对已确认的远端副作用执行同样的同步补偿。若 `doc_path` 为空，则跳过远端迁移，直接执行相同的本地条件更新。
6. **返回结果**：本地更新完成后返回 HTTP 200、顶层 `msg="变更成功"` 和 `data.success=true`。

> 💡 **说明**：  
> - 目标契约已于 2026-07-16 确认：远端操作返回 `false`、目标 workspace 创建后未取得有效引用或本地条件更新未成功，均视为业务失败并返回上述 HTTP 500 结构。2026-07-24 的 1E-6 已将内部执行链切换为同步 Saga：写意图、步骤、lease/fencing 与观测事实持久化后再执行远端调用；HTTP 200 只在成功事实已确认时返回。此实现状态更新不改变本接口的请求参数、响应字段、状态码、Header 或同步语义。
> - 远端删除、远端加入和本地更新之间仍不存在跨系统原子事务；同步 Saga 会在当前请求的有限总预算内执行有界补偿，不允许配置为无限等待。任何无法证明一致性的现场都会保留为内部恢复事实，并返回既有 HTTP 500 结构，不向调用方泄露 Operation ID、租约、fencing 或步骤信息。
> - 本接口不触发重新解析任务。若需在变更后重新解析，请单独调用 `/llm/weaponry` 接口。
