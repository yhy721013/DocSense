

# 武器装备知识谱系解析接口及字段详解
```
接口路径： /llm/weaponry
请求方法： POST
```

## 一、请求参数字段说明（任务提交阶段）

### 📌 LLMReq 根对象
| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| **businessType** | String | 是 | 业务类型标识，固定值 | `"weaponry"` |
| **params** | Object | 是 | 武器装备解析参数容器 | - |

---

### 📌 LLMWeaponryReq (params对象)
| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
**status** | String | 是 | **状态**：0未解析 1解析中 2已解析 3解析失败 | `0未解析 1解析中 2已解析 3解析失败` |
| **architectureId** | Long | 是 | **知识谱系ID**：标识解析任务和回调结果所属的知识体系；非空 `filePathList` 的来源文档可来自其他类别 | `1` |
| **filePathList** | List\<String\> | 否 | **解析文件范围**：缺省或空数组表示当前类别全部文件；非空时可指定任意已进入知识库类别的文档。元素可为完整下载 URL 或裸哈希文件名 | `["http://host/download/abc123.pdf", "def456.pdf"]` |
| **weaponryTemplateFieldList** | List | 是 | **待解析字段列表**：定义需要从文档中提取的字段结构 | `[ {...}, {...} ]` |
---

`filePathList` 非空时遵循以下规则：

- 服务端只提取 URL 路径末尾的文件名，不会重新下载文件。
- 自动去除 query 和 fragment、执行 URL 解码，并按文件名首次出现顺序去重。
- 文件名必须与 `documents.file_name` 中的哈希文件名一致。
- 选中文件可以来自任意 `architectureId`，但每个文件名必须在本地知识库中唯一对应一条 `documents` 记录；未解析文件返回 HTTP `404`。
- 若同一文件名存在于多个知识库类别，或不同选中文件指向同一 AnythingLLM 文档位置，现有请求字段无法唯一溯源，整个请求返回 HTTP `400`，且不会启动后台任务。
- 服务端在受理时冻结文件名、来源类别、AnythingLLM 文档位置和实际上传文件名的内部任务快照；该快照不增加请求、响应或回调字段。
- 解析任务使用只引用选中文档的任务级临时 workspace，不修改任何来源类别的永久 workspace；因此非空范围不要求目标 `architectureId` 已有永久 workspace。缺省或空数组仍按原语义使用当前类别全部文件，并要求其永久 workspace 存在。

### 📌 LLMWeaponryTemplateField (字段定义对象)
| 字段 | 类型 | 必填 | 说明 | 请求时要求 | 示例值 |
|------|------|------|------|------------|--------|
| **templateClassifyId** | Long | 是 | **模板分类ID**：字段在知识谱系分类id | 不需要改动 | `1772442376645740` |
| **fieldName** | String | 是 | **字段名称**：业务字段中文名 | 不需要改动 | `"操场长度"` |
| **fieldType** | String | 是 | **字段类型**：`INPUT`=普通文本字段`TABLE`=二维表格字段 | 不需要改动 | `"INPUT"` / `"TABLE"` |
| **fieldDescription** | String | 否 | **字段说明**：指导大模型提取内容的提示语 | 不需要改动 | `"根据文档提取操场实际长度"` |
| **tableFieldList** | List | 条件 | **表格结构**：- 仅当`fieldType="TABLE"`时必填- 请求阶段作为列模板，通常只需传1行列定义- 回调阶段外层List=数据行，内层List=列 | 子字段需清空解析字段 | `[[{...},{...}]]` |

> 💡 **关键规则**：  
> - 所有层级（含`tableFieldList`嵌套字段）的 `analyseData` 和 `analyseDataSource` **必须清空**  
> - 服务端校验：若检测到非空值，将返回 `INVALID_PARAM` 错误
> - `TABLE` 字段会按整表抽取：服务端把请求中的列模板扩展为多行结果，例如同一装备上多种雷达会拆成多行，每种雷达一行、各项指标分别填入对应列。

## 二、回调结果字段说明（服务端返回阶段）

### 📌 回调根对象
| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **businessType** | String | 业务类型标识（用于客户端路由） | `"weaponry"` |
| **data** | Object | 填充完整解析结果的参数对象 | `LLMWeaponryReq` |
| **msg** | String | 处理状态描述 | `"解析成功"` / `"3个字段未匹配"` |

---

### 📌 LLMWeaponryTemplateField (回调填充后)
| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **templateClassifyId** | Long | 是 | **模板分类ID**：字段在知识谱系分类id | 不需要改动 | `1772442376645740` |
| **fieldName** | String | 是 | **字段名称**：业务字段中文名 | 不需要改动 | `"操场长度"` |
| **fieldType** | String | 是 | **字段类型**：`INPUT`=普通文本字段`TABLE`=二维表格字段 | 不需要改动 | `"INPUT"` / `"TABLE"` |
| **fieldDescription** | String | 否 | **字段说明**：指导大模型提取内容的提示语 | 不需要改动 | `"根据文档提取操场实际长度"` |
| **tableFieldList** | List | 条件 | **表格结构**：- 仅当`fieldType="TABLE"`时必填- 外层List=服务端抽取出的数据行- 内层List=每行的列字段 | [[{},{}],[{},{}]]
| **analyseData** | String | **提取结果值**：- 成功提取：具体文本值- 未匹配：空字符串 | `"10米"` / `""` |
| **analyseDataSource** | List | **溯源证据链**：- 至少1条记录（无来源时返回空内容对象）- 按置信度降序排列 | `[ {...}, {...} ]` |

---

### 📌 LLMWeaponryAnalyseDataSourceReq (数据来源明细)
| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **content** | String | **提取结果**：模型基于本来源文件的 Chunk 提取出的字段值 | `"操场实测长度10米"` |
| **source** | String | **来源文件业务原名**：严格取自对应文件解析请求的 `originalFileName` 原值（持久化为 `documents.original_name`）；MHTML/OCR 等预处理生成的内部文件名不会出现在该字段 | `"校园设施验收报告.pdf"` |
| **time** | String | **信息时间**：内容产生时间（非解析时间） | `"2023-08-10"` |
| **fileName** | String | **内部文件名**：文件解析请求使用的哈希文件名，取自 `documents.file_name` | `"3199b401658d49e781469534e8613913.pdf"` |
| **rows** | List\<String\> | **证据片段列表**：同一来源文件中经过数量和总字符限制后，实际提交给模型完成本次抽取的 Chunk 正文 | `["Chunk 1", "Chunk 2"]` |
| **translate** | String | **翻译内容**：- 外文文献：提供中文翻译- 中文文献：空字符串 | `"Translation: Playground length 10m"` / `""` |

> `rows` 只包含实际进入本次模型 Prompt 的 Chunk，不包含向量检索召回后因数量或总字符限制而被裁掉的候选片段。无有效来源时，`source`、`fileName` 为空字符串，`rows` 为空列表。若已进入知识库的开发数据缺少实际上传文件名谱系，服务端会要求先重新执行文件解析，不会从 MHTML/OCR 中间名、文档路径或供应商标题猜测来源展示名。

## 典型场景字段解读

### 场景1：普通字段（INPUT）
```json
{
    "fieldDescription": "操场长度字段描述根据文档中的信息提取",
    "fieldName": "操场长度",
    "fieldType": "INPUT",
    "templateClassifyId": 1772442376645740,
    "analyseData": "解析数据操场长10米",
    "analyseDataSource": [
        {
            "content": "内容",
            "source": "校园设施验收报告.pdf",
            "time": "1999-12-01",
            "fileName": "3199b401658d49e781469534e8613913.pdf",
            "rows": ["这段文献，这里内容"],
            "translate": "翻译后的：这段文献，这里内容"
        }
    ]
}
```
> **字段意义**：`analyseData` 是结构化结果值，`analyseDataSource` 提供可验证的原文依据

### 场景2：表格字段（TABLE）
```json
"tableFieldList": [
  [ // 第1行
    { "fieldName": "姓名", "analyseData": "张三", ... },
    { "fieldName": "分数", "analyseData": "80", ... }
  ],
  [ // 第2行
    { "fieldName": "姓名", "analyseData": "李四", ... },
    { "fieldName": "分数", "analyseData": "66", ... }
  ]
]
```
> **字段意义**：  
> - 外层List = 表格行（2行数据）  
> - 内层List = 每行的列字段（姓名+分数）  
> - 每个单元格独立包含 `analyseData` 和溯源证据
> - 请求时传入的首行通常只是列模板；回调时服务端会根据文档内容扩展出实际数据行。
