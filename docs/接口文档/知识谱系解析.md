

# 武器装备知识谱系解析接口及字段详解
```
接口路径： /llm/weaponry
请求方法： POST
```

## 一、请求参数字段说明（任务提交阶段）

### 📌 LLMReq 根对象
| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| **businessType** | String | 是 | 业务类型标识，固定值 | `"weaponry"` |
| **params** | Object | 是 | 武器装备解析参数容器 | - |

---

### 📌 LLMWeaponryReq (params对象)
| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| **status** | String | 否 | **调用方状态兼容字段**：后端不读取、不校验，也不使用该值决定任务状态；缺省或传入任意既有状态值均不影响解析 | `"0"` |
| **architectureId** | Long / 十进制整数字符串 | 是 | **知识谱系ID**：标识解析任务和回调结果所属的知识体系；服务端规范化为 `1..9223372036854775807` 的 JSON 正整数；非空 `filePathList` 的来源文档可来自其他类别 | `1` / `"1"` |
| **filePathList** | List\<String\> | 否 | **解析文件范围**：缺省或空数组表示当前类别全部文件；非空时可指定任意已进入知识库类别的文档。元素可为完整下载 URL 或裸哈希文件名 | `["http://host/download/abc123.pdf", "def456.pdf"]` |
| **weaponryTemplateFieldList** | List | 是 | **待解析字段列表**：定义需要从文档中提取的字段结构 | `[ {...}, {...} ]` |
---

`filePathList` 非空时遵循以下规则：

- 服务端只提取 URL 路径末尾的文件名，不会重新下载文件。
- 自动去除 query 和 fragment、执行 URL 解码，并按文件名首次出现顺序去重。
- 文件名必须与 `documents.file_name` 中的哈希文件名一致。
- 选中文件可以来自任意 `architectureId`，但每个文件名必须在本地知识库中唯一对应一条 `documents` 记录；未解析文件返回 HTTP `404`。
- 若同一文件名存在于多个知识库类别，或不同选中文件指向同一 AnythingLLM 文档位置，现有请求字段无法唯一溯源，整个请求返回 HTTP `400`，且不会启动后台任务。
- 服务端在受理时冻结文件名、来源类别、AnythingLLM 文档位置和实际上传文件名的内部任务快照；该快照不增加请求、响应或回调字段。
- 解析任务使用只引用选中文档的任务级临时 workspace，不修改任何来源类别的永久 workspace；因此非空范围不要求目标 `architectureId` 已有永久 workspace。

`filePathList` 缺省或为空数组时，服务端同样在**请求受理时**冻结该 `architectureId` 当前类别下
全部文档的身份和稳定顺序。任务排队、重试或恢复期间新增、删除、重新解析或重新分类的文档
不会改变已受理任务的范围。受理时类别中没有文档仍可返回 HTTP 202，后台任务随后按既有失败
回调协议收敛；执行过程使用任务级 workspace，不临时修改永久类别 workspace。

`architectureId` 的十进制整数字符串只能包含 ASCII 数字；允许前导零并在规范化时去除，例如
`"0001"` 等价于 `1`。布尔值、零、负数、小数、指数形式、带正负号字符串、空白字符串及超出
有符号 64 位正整数上限的值均返回 HTTP 400。无论请求使用 JSON number 还是字符串，回调中的
`architectureId` 均为 JSON number。`/llm/weaponry`、`/llm/check-task` 的 weaponry 项和
`/llm/progress` 的 weaponry 订阅共用这一规范化规则和同一个无前导零业务键，不能把 `1`、
`"1"` 与 `"0001"` 识别为不同任务。

### 📌 LLMWeaponryTemplateField (字段定义对象)
| 字段 | 类型 | 必填 | 说明 | 请求时要求 | 示例值 |
|------|------|------|------|------------|--------|
| **templateClassifyId** | Long | 是 | **模板分类ID**：字段在知识谱系分类id | 不需要改动 | `1772442376645740` |
| **fieldName** | String | 是 | **字段名称**：业务字段中文名 | 不需要改动 | `"操场长度"` |
| **fieldType** | String | 是 | **字段类型**：`INPUT`=普通文本字段`TABLE`=二维表格字段 | 不需要改动 | `"INPUT"` / `"TABLE"` |
| **fieldDescription** | String | 否 | **字段说明**：指导大模型提取内容的提示语 | 不需要改动 | `"根据文档提取操场实际长度"` |
| **tableFieldList** | List | 条件 | **表格结构**：- 仅当`fieldType="TABLE"`时必填- 请求阶段作为列模板，通常只需传1行列定义- 回调阶段外层List=数据行，内层List=列 | 子字段需清空解析字段 | `[[{...},{...}]]` |

> 💡 **关键规则**：  
> - 所有层级（含`tableFieldList`嵌套字段）的 `analyseData` 和 `analyseDataSource` **必须清空**  
> - 服务端校验：若检测到非空值，将返回 `INVALID_PARAM` 错误
> - `TABLE` 字段会按整表抽取：服务端把请求中的列模板扩展为多行结果，例如同一装备上多种雷达会拆成多行，每种雷达一行、各项指标分别填入对应列。
> - `weaponryTemplateFieldList` 必须是非空数组且每个元素必须是对象；`fieldType` 只能是
>   `INPUT` 或 `TABLE`。`TABLE.tableFieldList` 及其中的行、列必须符合本文所列数组/对象结构。
>   非对象元素、未知 `fieldType` 或非法 TABLE 结构统一返回 HTTP 400，不会忽略、按 INPUT
>   降级或产生 HTTP 500。

`fieldDescription` 在术语规则辅助关闭时仍然完整生效：INPUT 的字段名与字段说明同时用于目标
文档召回和最终按文件抽取；TABLE 的表说明及各列字段说明同时用于整表召回和最终 JSON 行抽取。
术语规则（若启用）只能补充别名、口径和单位理解，不能覆盖请求中的 `fieldDescription`，也
不能作为正式提取结果或溯源证据。

### 保留字段强制空值合同

服务端将每个 `fieldName` 去除首尾空格后进行精确匹配。以下五个名称属于甲方保留字段：

- `装备编号`
- `一级分类`
- `二级分类`
- `三级分类`
- `四级分类`

该规则同时覆盖顶层 `INPUT` 字段和 `TABLE.tableFieldList` 中的嵌套列。命中后不使用
`fieldDescription` 发起抽取，且跳过术语辅助、目标证据检索、大模型调用和翻译；服务端在最终
回调组装时仍会再次强制空值，避免模型返回额外同名键污染结果。近似名称（例如
`装备编号说明`）以及未命中的普通字段继续走既有抽取链路。

命中字段的回调固定保留原始字段定义、扩展键和顺序，并返回：

```json
{
  "analyseData": "",
  "analyseDataSource": [
    {
      "content": "",
      "source": "",
      "time": "",
      "fileName": "",
      "rows": [],
      "translate": ""
    }
  ]
}
```

混合 `TABLE` 只将普通列送入查询、整表 Prompt、解析和翻译，再按请求冻结的完整列模板与顺序
组装回调；五个保留列始终使用上述空值。仅含保留列的 `TABLE` 完全跳过外部抽取链，并返回一行
包含全部原始列定义的空单元格。该合同不新增或删除任何 HTTP 请求、响应字段。

### 请求校验错误文本

阶段 1D 按以下文本冻结 HTTP 400/404/409 的单字段错误体。表中的 `{index}`、`{row}`、
`{column}` 均从 1 开始，`{fileName}` 使用归一化后的请求文件名。错误响应只包含 `error`，
不增加内部任务标识或调试字段。

| 场景 | HTTP 状态 | `error` 文本 |
| --- | --- | --- |
| 请求体不是 JSON 对象 | 400 | `请求体必须是JSON对象` |

| `architectureId` 缺失 | 400 | `architectureId不能为空` |

| `filePathList` 不是数组 | 400 | `filePathList必须为数组` |
| `filePathList` 第 `{index}` 项不是非空字符串 | 400 | `filePathList中第{index}项不是有效字符串` |
| `filePathList` 第 `{index}` 项无法提取文件名 | 400 | `filePathList中第{index}项无法提取文件名` |
| `weaponryTemplateFieldList` 缺失、不是数组或为空 | 400 | `weaponryTemplateFieldList不能为空` |
| 字段列表第 `{index}` 项不是对象 | 400 | `weaponryTemplateFieldList中第{index}项必须为对象` |

| `fieldType` 不是 `INPUT` 或 `TABLE` | 400 | `weaponryTemplateFieldList中第{index}项fieldType必须为INPUT或TABLE` |

| TABLE 的 `tableFieldList` 缺失、不是数组或为空 | 400 | `weaponryTemplateFieldList中第{index}项tableFieldList必须为非空数组` |

| TABLE 第 `{row}` 行第 `{column}` 项不是对象 | 400 | `tableFieldList中第{row}行第{column}项必须为对象` |
| TABLE 单元格 `fieldName` 缺失或为空 | 400 | `tableFieldList中第{row}行第{column}项fieldName不能为空` |
| TABLE 单元格 `fieldType` 不是 `INPUT` | 400 | `tableFieldList中第{row}行第{column}项fieldType必须为INPUT` |
| TABLE 单元格非 `null` 的 `fieldDescription` 不是字符串 | 400 | `tableFieldList中第{row}行第{column}项fieldDescription必须为字符串` |
| 选中文件尚未解析 | 404 | `文件 {fileName} 尚未解析，无法用于知识谱系解析` |
| 同一文件名在多个分类中存在 | 400 | `文件 {fileName} 在多个知识库分类中存在记录，无法唯一确定引用版本` |
| 多个选中文件指向同一外部文档 | 400 | `选中文件指向同一知识库文档位置，无法唯一溯源` |
| 选中文件分类记录非法 | 400 | `文件 {fileName} 的知识库分类记录无效` |
| 选中文件缺少知识库文档位置 | 400 | `文件 {fileName} 缺少知识库文档位置` |
| 同一 `architectureId` 的任务或回调 Guard 忙/结果未知 | 409 | `任务正在处理中` |

## 受理成功响应（HTTP 202）

请求通过校验并成功受理后，响应体为空。调用方继续使用请求中的 `architectureId` 关联进度和最终回调，不从受理响应取得内部任务记录。

```http
HTTP/1.1 202 Accepted
Content-Length: 0
```

HTTP 400、404、409 等错误响应仍保持既有 JSON 错误体。

相同 `architectureId` 已存在受理中/运行中任务，或上一任务的外部回调正在发送、发送结果未知
时，新请求返回 HTTP 409：

```json
{"error":"任务正在处理中"}
```

上一任务回调明确失败且 Callback Guard 已恢复空闲后允许重新提交。旧任务恢复回调时如果已经
不是该 `architectureId` 的最新 execution，服务端将其判定为过期并跳过网络发送。

> 实施状态：202 空响应体契约已于 2026-07-15 明确确认；文档范围冻结、ID 规范化、严格字段
> 结构校验和 409 Guard 口径已于 2026-07-17 确认。阶段 1D-6 已于 2026-07-19 在当前开发分支
> 将公开入口切换为 Parser → 文档范围冻结 → `SubmitWeaponryTask` → Presenter：成功响应为严格
> 零字节 202，不再返回内部任务快照，也不在路由中创建执行线程。该代码尚未部署到生产环境；
> 本次切换没有增删请求、错误响应或回调字段。

---

### 📌 LLMWeaponryAnalyseDataSourceReq (数据来源明细)
| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| **content** | String | **提取结果**：模型基于本来源文件的 Chunk 提取出的字段值 | `"操场实测长度10米"` |
| **source** | String | **来源文件业务原名**：严格取自对应文件解析请求的 `originalFileName` 原值（持久化为 `documents.original_name`）；MHTML/OCR 等预处理生成的内部文件名不会出现在该字段 | `"校园设施验收报告.pdf"` |
| **time** | String | **信息时间**：内容产生时间（非解析时间） | `"2023-08-10"` |
| **fileName** | String | **内部文件名**：文件解析请求使用的哈希文件名，取自 `documents.file_name` | `"3199b401658d49e781469534e8613913.pdf"` |
| **rows** | List\<String\> | **证据片段列表**：同一来源文件中通过来源身份、分数或排名协议、正文质量和同文档精确去重门禁后，按稳定排名实际完整提交给模型完成本次抽取的 Chunk 正文 | `["Chunk 1", "Chunk 2"]` |
| **translate** | String | **翻译内容**：- 外文文献：提供中文翻译- 中文文献：空字符串 | `"Translation: Playground length 10m"` / `""` |

> `rows` 与实际进入本次模型 Prompt 的 Selected Evidence 逐项、同序一致。服务端不对单条
> Evidence 字符数、全部 Evidence 总字符数、单文档 Evidence 数量或单文档贡献字符数设置
> 二次上限，也不截断已经通过门禁的正文。向量检索的 `candidate_top_n` 仍是一次向供应商请求
> 候选的批次大小，不是 Selected Evidence/`rows` 的截断配额；批次内全部通过质量门禁的正文
> 均完整保留。当前批准的选择口径不设置绝对相关性阈值，也不使用独立 reranker；只要来源、
> 正文和分数/排名协议合法，就按冻结策略中的稳定顺序选取。供应商返回分数时，分数必须满足
> 冻结的方向、范围和类型协议；供应商明确不提供分数时，仅允许进入已冻结的 rank-only 路径，
> 并使用合法、稳定的正整数排名。类型错误、NaN、Infinity 等非法分数不能伪装为“缺失分数”
> 或静默转换为 `0`。无有效来源时，`source`、`fileName` 为空字符串，`rows` 为空列表。若已进入知识库
> 的开发数据缺少实际上传文件名谱系，服务端会要求先重新执行文件解析，不会从 MHTML/OCR
> 中间名、文档路径或供应商标题猜测来源展示名。
>
> 后端只保留“按来源文件聚合多个 Chunk 后抽取”的单一模式。旧
> `WEAPONRY_ANALYSE_MODE=1` 按 Chunk 执行分支已在阶段 1D-1 删除；迁移期若仍显式配置值 `1`，
> 服务端会明确拒绝执行而不会静默切换回调语义。该内部配置不属于请求或回调参数。

成功回调必须完整覆盖本次请求的字段模板：`weaponryTemplateFieldList` 的元素数量、顺序和每个
字段定义与受理时快照逐项一致。字段未检索到内容时仍返回该字段对象并使用既有空值表达，不能
直接省略字段；TABLE 可以没有数据行，但每个已返回数据行都必须完整包含请求冻结的全部列且
顺序一致。该完整性门禁不会增加、删除或重命名任何回调字段。

## 典型场景字段解读

### 场景1：普通字段（INPUT）
```json
{
    "fieldDescription": "操场长度字段描述根据文档中的信息提取",
    "fieldName": "操场长度",
    "fieldType": "INPUT",
    "templateClassifyId": 1772442376645740,
    "analyseData": "解析数据操场长10米",
    "analyseDataSource": [
        {
            "content": "内容",
            "source": "校园设施验收报告.pdf",
            "time": "1999-12-01",
            "fileName": "3199b401658d49e781469534e8613913.pdf",
            "rows": ["这段文献，这里内容"],
            "translate": "翻译后的：这段文献，这里内容"
        }
    ]
}
```
> **字段意义**：`analyseData` 是结构化结果值，`analyseDataSource` 提供可验证的原文依据

### 场景2：表格字段（TABLE）
```json
"tableFieldList": [
  [ // 第1行
    { "fieldName": "姓名", "analyseData": "张三", ... },
    { "fieldName": "分数", "analyseData": "80", ... }
  ],
  [ // 第2行
    { "fieldName": "姓名", "analyseData": "李四", ... },
    { "fieldName": "分数", "analyseData": "66", ... }
  ]
]
```
> **字段意义**：  
> - 外层List = 表格行（2行数据）  
> - 内层List = 每行的列字段（姓名+分数）  
> - 每个单元格独立包含 `analyseData` 和溯源证据
> - 请求时传入的首行通常只是列模板；回调时服务端会根据文档内容扩展出实际数据行。

## 三、目录 runner 合同验证

目录 runner 的普通模式继续使用既有 75 字段模板，五个保留字段不计入
`extractable_field_count`、`non_empty_count` 或 `missing_fields`，任何保留字段非空值会单独
记为合同违规。需要验证本节强制空值合同时，显式增加默认关闭的
`--verify-forced-empty-contract`：

```bash
zsh scripts/test_llm_weaponry_directory.sh "/path/to/fixture-directory" \
  --base-url http://127.0.0.1:5001 \
  --output-dir "/path/to/fresh-runtime/weaponry-forced-empty-contract" \
  --verify-forced-empty-contract
```

该模式使用以下最小探针：

- 5 个顶层保留 `INPUT`；
- 普通字段 `舷号`，用于证明普通抽取链未被整体短路；
- 同时含 5 个保留列和普通列的混合 `TABLE`；
- 仅含保留列的 `TABLE`。

manifest 分别记录顶层、两类 TABLE、普通字段对照、callback 状态和 interaction audit 的核验
结果。`/llm/check-task` 成功响应为 HTTP 200 空响应体，runner 只用它触发必要的 callback
恢复，并从与 DocSense 服务相同的隔离任务 SQLite 读取、轮询任务终态；HTTP 200 后找不到对应
任务行时立即报告数据库路径不一致。执行真实验证前，必须让服务和 runner 指向同一个
`DOCSENSE_LLM_TASK_DB`，使用全新的 `DOCSENSE_RUNTIME_DIR` 和输出目录，并启动已配置为
`CALLBACK_URL` 的本地 mock callback 服务，避免历史任务、回调或审计记录混入。
