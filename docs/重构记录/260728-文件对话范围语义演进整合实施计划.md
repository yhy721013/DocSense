# 文件对话范围语义演进整合实施计划

## 1. 文档状态

- 状态：两个连续专项均已完成并在 SQLite 单实例离线边界内关闭。
- 整合范围：“首次空 `fileNames` 自动全量”与“Requested/Active/Effective Scope 分离”。
- 当前口径：以后一个专项的范围状态机为准；前一个专项只保留首次候选解析和原子受理基础。
- 公开契约：不得增删请求参数、响应字段、HTTP 状态码、Header、SSE 事件名或事件结构。

完整实施结果见 `../更新记录/260728-文件对话范围语义演进整合执行记录.md`。

## 2. 目标

1. 新会话首次空数组只读取一次完整目录快照，并在受理事务内决定是否采用。
2. 调用方本轮选择、会话活动范围、模型本轮有效范围和 Workspace 累计绑定必须分离。
3. 任意非空请求整体替换 Active Scope；后续空请求复用最后 accepted 范围，不动态扩张。
4. History 只展示 Requested Scope，不能泄漏自动全量或内部累计绑定。
5. Worker 仅凭 run_id 和 SQLite 冻结事实恢复，不依赖当前目录或进程内对象。

## 3. 最终状态机

| 会话状态 | 本轮请求 | Requested | Effective | 新 Head |
| --- | --- | --- | --- | --- |
| 新会话 | 空数组 | 空 | 一次目录快照 | 创建初始 Revision |
| 新/旧会话 | 非空数组 | 显式集合 | 显式集合 | 整体替换 |
| 已有会话 | 空数组 | 空 | 当前 Active Scope | 不变 |

补充约束：

- 首次目录为空时可以形成空范围；后续知识库新增文件不会自动进入该会话。
- 非空请求一旦原子 accepted，新 Head 即生效，即使随后模型调用失败也不回退。
- Workspace Binding 可以累计，但模型调用必须显式传入 Effective Scope。
- Revision、Member、Head、run input 或 message 任一损坏均失败关闭，不从其他事实猜测修复。

## 4. 数据与事务设计

- Scope Revision/Member 不可变；Scope Head 使用 CAS。
- requested/effective run input 使用严格版本化 Codec，未知字段或版本失败关闭。
- 候选准备可以在事务外执行，但 session 创建裁决、Scope Head、run input 和 pending message 必须在同一 `BEGIN IMMEDIATE` 事务中提交。
- 超限、目录冲突、重复身份或持久化故障整体回滚，不留下半个 session、Head 或消息。

## 6. 并发与未来部署门禁

- 同一 chatId 的并发请求必须由事务/CAS 得到唯一 accepted Head；不同会话不得共享锁或范围对象。
- 50 线程/会话的 SQLite 测试只证明当前单实例原子性，不代表多实例共享数据库一致性。
- 接入可靠队列后，受理事实与消息发布必须使用 Outbox 或等价协议，不能把 Event 当作可靠投递。
- 多实例前需要共享会话所有权、数据库 fencing、可恢复 Task Attempt 和跨实例通知。

## 7. 回滚

回滚必须在停服排空后进行，并保持 Scope Revision、run input、message 和远端 Binding 的可审计关系。已经产生新 Scope Head 的数据库不得直接回退到不理解 Schema v4 的代码；需要迁移或清库重建时必须先确认数据保留要求和资源所有权。
