## 2. 当前生产调用轨迹

### 2.1 Analysis

```text
RunAnalysisTask
  → LegacyAnalysisFilePreparationAdapter
      → download_to_temp_file
      → Legacy Office?
          → LegacyOfficePreparer.prepare
          → 调用方复制 prepared_path 到 execution/normalized
      → MHTML?
          → services.utils.mhtml_normalizer
          → translator.mhtml2pdf（可选）
      → scanned PDF?
          → services.utils.ocr_preprocessor
          → translator.MinerUConverter
          → builtin OCR
          → original PDF fallback
      → 读取 original_text
  → RAG / 分类 / 抽取
  → SerializedAnalysisTranslationAdapter
      → LLMTranslationService
      → DocumentTranslator
```

已具备的隔离：

- `LocalAnalysisTaskWorkspaceAdapter` 使用 execution `TaskId` 独占目录；
- raw、processing、upload 路径都被限制在任务根目录内；
- Analysis 会把 OCR 和 MinerU 缓存根覆盖为任务目录；
- Legacy Office 处理策略已冻结在 Analysis Task Input V2。

仍存在的耦合：

- `PreparedAnalysisDocument` 对 Application 暴露字符串路径；
- Analysis Adapter 直接调用 utils 中的 MHTML/OCR 生命周期；
- 全文翻译会再次按格式决定是否运行 MinerU/MHTML；
- 文件处理结果没有统一 ArtifactRef 和父子 Lineage。

### 2.2 Report

```text
RunReportTask
  → LegacyReportFileAdapter
      → 下载并发布 SOURCE ReportArtifact
      → Legacy Office / MHTML 规范化
      → 发布 NORMALIZED_SOURCE ReportArtifact
      → OCR/RAG 上传准备
      → 发布 RAG_INPUT ReportArtifact
  → AnythingLLM RAG
  → 生成报告
  → LocalReportArtifactAdapter.persist_report_html
```

已具备的隔离：

- `ReportArtifactRef` 是不透明引用；
- 每个 TaskId 使用哈希命名空间；
- 本地写入采用同目录临时文件、fsync 和 `os.replace`；
- 最终报告记录 size/SHA-256，清理会复核 retained Artifact；
- Report 资源恢复已持久化清理 pending 状态。

仍存在的耦合：

- `ReportArtifactRef` 和 Category 属于 Report 业务，不能直接被其他模块复用；
- `LegacyReportFileAdapter` 仍直接注入 `mhtml_normalizer`、`rag_pipeline` 和 Word 工具；
- Legacy Office 返回路径后由 Report Adapter 再复制一次；
- MHTML/OCR 的处理 profile 和 lineage 没有统一记录。

### 2.3 Translation

```text
LLMTranslationService
  → DocumentTranslator
      → suffix dispatch
          → TXTHandler
          → MarkdownHandler
              → MinerUConverter
          → MHTMLHandler
              → MHTMLToPDFConverter
              → MarkdownHandler / MinerUConverter
      → HYMTTranslator
      → bilingual / monolingual HTML
```

当前格式分派：

| 输入 | 当前处理器 |
| --- | --- |
| PDF、DOCX、PPTX、XLSX | MarkdownHandler → MinerU |
| MHTML、MHT | MHTMLHandler → Browser PDF → MinerU |
| TXT | TXTHandler |
| MD | MarkdownHandler 直接翻译 |

当前 `LLMTranslationService._execution_lock` 串行保护输出目录、MinerU 转换和 HTML 读取。这避免了
单进程覆盖，但也证明 Translation 仍拥有文件转换生命周期，且全部翻译受到同一进程锁影响。

### 2.4 Weaponry 与 Chat

- Weaponry 当前消费已经解析、带来源谱系的 Evidence，不拥有原始 MHTML/MinerU/OCR 转换入口；
- Chat 当前消费知识库文件绑定和冻结 Scope，不执行原始文件转换；
- 1H 不为追求表面统一而强制二者依赖 DocumentProcessing；只有出现真实原始输入处理需求时才通过
  Port 接入。

### 2.5 遗留服务

`app/services/llm_service/analysis_service.py` 和 `report_service.py` 仍保留旧工具导入与兼容测试，
但不是当前公开生产执行主链。后续引用清理必须区分生产、测试、配置三类，不得把遗留服务重新接回
公开路由。

## 5. 全局状态与并发事实

| 状态 | 当前位置 | 当前保护 | 1H 目标 |
| --- | --- | --- | --- |
| Translation Service singleton | `translation_service.py` | 初始化 RLock | 只保留引擎/组合根生命周期 |
| Document translation execution | `LLMTranslationService._execution_lock` | 进程内全局串行 | 文档处理移出锁；只保护确有线程安全限制的翻译引擎 |
| HYMT progress tracker | `HYMTTranslator` 实例 | 随共享实例可变 | 任务级事件/回调，不进入 DocumentProcessing |
| MinerU output directory | `MinerUConverter.output_dir` | Translation 全局锁间接保护 | task/step 独占物化目录 |
| `tempfile.tempdir` | `MinerUConverter` 可能修改 | 进程级全局变量 | 禁止修改；通过子进程环境/显式目录传递 |
| LibreOffice capacity | `LibreOfficeLegacyOfficePreparer` | 进程内 Semaphore | 保留阶段 1 限流；阶段 5 再接独立队列/全局容量 |

当前 50 任务基线只证明 Analysis 目录和 Report Artifact 前缀不冲突，不证明 MinerU、OCR、浏览器或
模型能够 50 路并行，也不证明跨实例安全。

## 8. 当前差距与后续入口

1. 1H-0 初次执行 50 任务门禁时发现 Windows 普通路径与 `\\?\` 扩展路径的并发等价表示竞态；
   经负责人同意增加 1H-0R，复用 Report 已验证的规范化方式修复 Analysis Workspace，未放宽真实
   路径包含校验。
2. 1H-0/0R 定向扩大回归共执行 138 项，失败 0、错误 0、跳过 2；跳过项为既有平台条件用例。
3. 进入 1H-1 前不需要修改公开接口，也没有发现必须改变现有格式支持的事项。
4. Legacy Office 可按既定结论复用，不需要重新讨论供应商选型。
5. 1H-1 必须先决定并实现内部 Artifact/Profile/Lineage 合同；这些都是内部类型，不得写入 Callback。
6. 当前本地 Artifact/Processing Record 只能证明单实例正确性；多实例、MinIO、可靠队列和统一
   Task Attempt 分别留给阶段 2～5。
7. 如后续发现 MHTML 降级、OCR 原 PDF fallback、全文翻译字段映射与接口文档不一致，必须停止并
   与负责人确认，不能在结构重构中顺便改变语义。

### 9.1 Artifact 保留与清理边界

1. 上游系统保存的原始上传文档不属于本地 Artifact Store，DocumentProcessing 永不删除。
2. 任务下载后发布到共享 Store 的 source Artifact，以及由其派生的 normalized/prepared Artifact，
   在 1H 阶段持续保留；Processing Record、lineage、幂等复核和结果未知协调仍可能引用它们。
3. 当前只即时清理 Processor 明确创建、带所有权 marker 的 scratch，以及原子发布失败/完成后的
   `.part` 和无效候选；`outcome_unknown` 现场按既定规则保留，禁止猜测性删除。
4. Artifact 自动 GC 不在 1H 实现。阶段 3 建立 retention class、引用、删除资格、删除状态和审计事实；
   后续 GC 必须在任务终态、无租约/重试/回调恢复/其他引用且保留期到达后领取删除权，并将对象删除
   与 Processing Record/lineage 可恢复状态协调。未确认具体保留期前，删除资格保持为空。
