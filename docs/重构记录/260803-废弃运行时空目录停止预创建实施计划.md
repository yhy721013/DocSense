# 废弃运行时空目录停止预创建实施计划

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 制订日期 | 2026-08-03 |
| 当前状态 | 已完成（2026-08-03） |
| 目标分支基线 | `feat/weaponry-chat` / `c46fe2d` |
| 涉及目录 | `llm_downloads`、`ocr_markdown`、`mineru_markdown` |
| 不涉及目录 | `office_conversion/jobs` 及所有当前任务、Artifact、数据库目录 |
| 公开接口影响 | 无；不修改路由、请求参数、响应字段、状态码、Header、Callback、SSE 或 WebSocket 语义 |
| 数据迁移 | 无；不读取、迁移或兼容三个旧目录中的数据 |

## 2. 背景与判断

当前 `app/services/core/settings.py` 在模块导入时通过 `_ensure_directory(...)`
无条件创建以下三个目录：

- `${DOCSENSE_RUNTIME_DIR}/llm_downloads`；
- `${DOCSENSE_RUNTIME_DIR}/ocr_markdown`；
- `${DOCSENSE_RUNTIME_DIR}/mineru_markdown`。

当前生产组合根已经把文件生命周期迁移到任务私有目录和共享 DocumentProcessing Artifact：

- Report、Analysis 的下载和任务文件位于 `${DOCSENSE_RUNTIME_DIR}/tasks/...`；
- OCR、MinerU 的处理结果由
  `${DOCSENSE_RUNTIME_DIR}/document_processing/artifacts` 管理；
- OCR、MinerU 的转换物化目录位于
  `${DOCSENSE_RUNTIME_DIR}/document_processing/materializations/...`；
- Legacy Office 仍使用 `${DOCSENSE_RUNTIME_DIR}/office_conversion/jobs` 作为短生命周期任务目录。

因此，**仅停止三个旧目录的启动期预创建，不会改变当前正式业务链路**。不过，项目中仍保留
少量旧兼容函数及内部配置字段，可以在非正式装配、直接 Python 调用或旧测试路径中接收这些路径。
为了不把本次目录清理扩大为旧 Python API 物理删除，本计划采用最小安全方案：

1. 保留内部路径解析值和旧兼容函数，本次只移除无条件 `mkdir` 副作用；
2. 不改变 Report、Analysis、DocumentProcessing 的现行注入和处理逻辑；
3. 不承诺仓库外直接调用旧 Python API 的兼容性清理；如需物理删除这些 API，必须另立阶段并重新确认；
4. 不自动删除磁盘上已经存在的目录，避免运行中清理与其他进程产生竞态。

这里的“无需旧数据兼容和迁移”仅表示无需读取或搬迁三个旧目录的数据，不等同于可以在本阶段
顺带删除所有内部配置类型、测试注入点或旧 Python 调用入口。

## 3. 改造目标

### 3.1 业务目标

1. 新建 Runtime 或应用重新启动时，不再仅因导入配置模块而创建三个废弃空目录。
2. Report、Analysis、Weaponry、Chat、Translation 和 DocumentProcessing 的业务结果与失败语义不变。
3. Legacy Office 的 `office_conversion/jobs` 创建、清理和启动恢复行为不变。
4. 不增加后台线程、队列、共享缓存或新的跨任务可变目录。

### 3.2 工程目标

1. 将“路径解析”和“资源创建”分离：只有真实资源所有者才有权创建目录。
2. 用永久测试证明导入 `settings` 和加载核心配置不会创建三个目录。
3. 当前说明文档只展示实际生产路径，不再把三个目录描述为有效缓存。
4. 历史执行记录继续保留历史事实；当前文档与历史审计文档分开治理。

## 4. 明确不在本次范围内的事项

1. 不修改 `docs/接口文档/`，也不修改任何前后端接口参数。
2. 不删除 `LLMIntegrationConfig`、`OCRConfig` 或 DocumentProcessing 中仍被测试/兼容入口使用的字段和函数。
3. 不删除 `app/modules/document_processing/adapters/builtin_ocr.py` 中的 OCR/MinerU 实现。
4. 不删除 Report/Analysis Adapter 的兼容注入点。
5. 不修改 `${DOCSENSE_RUNTIME_DIR}/tasks`、`document_processing/*`、`sqlite`、数据库或 Callback 路径。
6. 不修改 `office_conversion/jobs`，也不改变 Legacy Office 启动扫描和任务后清理。
7. 不启动 `run.py`，不访问 AnythingLLM、MinerU、OCR、LibreOffice 或其他后台服务。
8. 不在应用启动时自动删除既有目录；需要物理清理时，应在服务停止后由维护操作单独执行。

## 6. 分阶段实施与验收门禁

### 阶段 0：基线与契约冻结

#### 实施内容

1. 记录分支、HEAD 和工作区状态，保护用户已有修改。
2. 对三个路径常量、环境变量和目录名执行生产/测试/当前文档/历史文档分类检索。

## 9. 风险与回滚

### 9.1 主要风险

1. 仓库外代码直接导入内部路径常量并假设目录已经存在；
2. 非正式组合根未注入共享 `document_preparer`，意外进入旧兼容处理分支；
3. 开发机环境变量覆盖路径，导致测试误判；
4. 文档清理时误删历史审计记录或误删仍有效的 OCR/MinerU 算法参数。

### 9.2 控制措施

- 生产、测试、配置和文档引用分类检查，不以单次 `rg` 结果代替语义判断；
- 使用全新临时 Runtime 和独立子进程测试导入副作用；
- 保留内部路径值和旧兼容函数，本阶段不物理删除旧 Python API；
- 历史文档白名单与当前文档零引用分开验收；
- 不自动清理运行目录，不产生不可恢复的数据删除。

### 9.3 回滚方式

如果发现正式业务确实依赖预创建行为，只需恢复三个 `_ensure_directory(...)` 包装及对应测试、当前文档，
不涉及数据库回滚、数据迁移、AnythingLLM Workspace 迁移或接口版本回退。
