## 2. 需求目标

当且仅当一次 `/llm/chat` 受理事务首次创建目标 `chatId` 的本地会话，并且调用方显式传入
`fileNames=[]` 时，服务端把受理时刻知识库中全部可用于文件对话的已解析文件，作为本轮的
有效 `fileNames`：

1. 冻结到不可变 `chat_run_inputs`；
2. 记录到首轮 user 消息的文件快照；
3. 绑定到该对话专用 Workspace；
4. 作为本轮模型查询的文档范围；
5. 后续 `fileNames=[]` 只复用会话已有绑定，不重新扫描或自动吸收新文件。

如果首次受理时知识库没有文件，有效范围就是空集合，继续保留无文件自由对话能力。

## 3. 已冻结决策

| 决策项 | 冻结结果 |
| --- | --- |
| “首次新对话”判定 | 以 SQLite 受理事务是否首次插入 `chat_sessions` 行为准；不得在 Blueprint 通过事务外 `get()` 猜测 |
| 首次运行失败后的重试 | 首次 session/run 已受理后，即使执行失败或中断，相同 `chatId` 的下一次请求也不再触发自动全量 |
| 全量文件范围 | 当前 DocSense 实例知识库 `documents` 表中的全局可用记录；当前接口没有用户、租户或分类范围参数 |
| 已解析资格 | 沿用 Chat 当前文档解析规则：记录必须能解析出非空业务文件名、原始文件名、`document_ref` 和远端位置 |
| 数量上限 | 自动展开后的有效文件数继续受 `DOCSENSE_CHAT_MAX_FILES` 约束；超限返回现有 HTTP 400，不绕过、不截断 |
| 空知识库 | 正常创建无文件对话，不新增 404 或其他错误 |
| 重名与重复身份 | 跨分类同名 `file_name`、重复远端文档身份或损坏记录均整体拒绝；禁止随机选择或静默跳过 |
| 文件顺序 | `file_name ASC, architecture_id ASC`；该顺序写入 run input 和首轮 user 历史 |
| 历史展示 | 自动选择的文件与显式 `fileNames` 完全等价，首轮 user 消息的 `files` 返回对应原始文件名 |
| 后续新增文件 | 不自动加入既有会话；调用方仍需在后续请求中通过非空 `fileNames` 显式增量加入 |
| SSE | `chatInfo/textChunk/done/error/aborted` 及 `isNewChat` 现有结构和远端资源语义保持不变 |
| 多实例边界 | 当前只证明 SQLite 单实例；不以本计划宣称跨实例原子性、可靠队列或分布式 fencing |

### 3.1 安全边界

当前 `/llm/chat` 没有调用方身份、租户或文档授权上下文，因此“全部文件”只能是当前实例的
全局知识库范围。部署方必须确认该实例属于单一可信业务域。未来接入多租户时，应从认证上下文
获得 scope，并把 scope 纳入会话键、文档查询和授权条件；禁止通过给现有接口新增前端参数的
方式临时绕过。

### 3.2 失败边界

- 流容量 429、文档目录校验失败、有效数量超限或受理事务回滚时，不得留下 session、run、
  pending user 消息或 run input；同一 `chatId` 后续仍可作为首次请求。
- session 和 run 已在受理事务中提交后，即使远端 Workspace 创建、文件绑定或模型流失败，
  该 `chatId` 也已完成“首次受理”，下一次空数组不会再次自动展开。
- 外部资源失败继续沿用现有租约、失败终态和清理边界；本计划不增加自动重放或后台恢复承诺。

## 4. 阶段 3 完成后的当前结构

当前调用链为：

```text
Blueprint 校验/去重原始 fileNames
  -> SynchronousChatRunExecutor.prepare_chat_run()
    -> ChatDocumentResolver
       ├─ resolve_many(explicit fileNames)
       └─ resolve_all_available()  # 仅 session 尚不存在的空数组候选
    -> ChatCommandService.start_chat_run()
      -> ChatRunLockService.try_acquire_chat_run()
        -> BEGIN IMMEDIATE
        -> INSERT OR IGNORE chat_sessions 并取得 session_created
        -> 事务内选择 explicit/default/empty 有效快照
        -> 校验最终有效数量
        -> 同事务创建 accepted run、run input、pending user
  -> execute_chat_run(run_id)
    -> 创建/复用 Workspace + Thread
    -> 从 run input 读取文档快照并进入既有绑定链
    -> 流式模型调用
```

Blueprint 仍只负责原始数组的协议校验；自动展开后的最终数量由 Chat 受理事务校验。知识库
候选快照可以在事务前只读准备，但只有 SQLite 事务的 `session_created` 结果有权决定是否采用，
从而避免两个并发请求同时把自己视为首次。阶段 4 已证明该快照只从 run input 重建，并与
显式文件复用同一远端绑定、current heads、模型流和本地历史链。

## 5. 目标结构

目标保持 Blueprint 薄、Application 高内聚、供应商 Adapter 可替换：

```text
Blueprint
  -> ChatRunExecutor.prepare_chat_run()
    -> ChatDocumentResolver
       ├─ resolve_many(explicit fileNames)
       └─ resolve_all_available()  # 单次只读目录快照
    -> ChatCommandService
      -> ChatRunCoordinator.try_acquire_chat_run()
         ├─ 原子判定 session_created
         ├─ 选择 explicit 或 new-session default 文档候选
         ├─ 校验有效数量上限
         └─ 同事务持久化 run/input/pending user/files
  -> 既有 ChatConversationPort 执行链
```

知识库和 Chat 当前分别使用不同 SQLite 文件，不能宣称二者具备跨库事务。实现应先以一次只读
查询冻结知识库候选快照，再由 Chat 受理事务原子决定是否采用该快照；一旦受理，后续执行只读
取 `chat_run_inputs`，不得重新查询知识库。未来共享数据库可在不改变 HTTP/SSE 的前提下把该
边界迁移到正式 Unit of Work。

目标：关闭两个并发首次请求同时套用默认全量的竞态。

执行状态：**已完成（2026-07-27）**。公开路由已使用内部候选 DTO；事务以实际插入结果
判定 `session_created`，并在同一提交中写入 run、run input 与 pending user。没有修改任何

事务顺序：

1. `BEGIN IMMEDIATE`；
2. `INSERT OR IGNORE chat_sessions`，以实际插入结果得到 `session_created`；
3. 校验 session 状态并收敛过期 run；
4. 检查同一 `chatId` 是否已有活跃 run；
5. 若 explicit 非空，始终使用 explicit；
6. 若 explicit 为空且 `session_created=true`，使用 default 全量候选；
7. 若 explicit 为空且 `session_created=false`，有效文件为空，由执行链复用当前 binding heads；
8. 对最终有效集合执行 `DOCSENSE_CHAT_MAX_FILES` 校验；
9. 同事务创建 run、不可变 run input、pending user 和 message files；
10. 任一步失败都回滚首次 session 插入。

4. 首轮自动范围完成后，即使知识库新增文件，后续空数组也不再次扫描或 attach，只向模型传入

## 7. 接口错误与兼容策略

- 原始 `fileNames` 非数组、非法元素、显式数量超限继续使用现有 HTTP 400。
- 自动展开后超限继续返回 HTTP 400 和现有错误：

```json
{"error": "fileNames超过文件对话数量上限"}
```

- 全量目录存在同名或重复身份时返回 HTTP 400 的既有 `error` 单字段结构，不新增错误字段；
  同名文案冻结为 `{"error": "全量文件范围存在重复fileName，无法用于对话"}`，重复远端身份
  文案冻结为 `{"error": "全量文件范围存在重复文档引用，无法用于对话"}`。

- 显式文件不存在继续返回现有 HTTP 404；自动全量来自一次数据库快照，不产生“逐个跳过”的
  部分成功。
- 现有会话、历史消息、binding revision 和清理租约不需要数据迁移；本计划不回填旧会话的全量
  文件范围。
