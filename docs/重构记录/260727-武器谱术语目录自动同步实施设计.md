# 武器谱术语目录自动同步实施设计

## 1. 目标与合同边界

恢复本地 `terms/term_rule_*.md` 上传 AnythingLLM 的能力，但不恢复旧 Service 在单任务
准备期间扫描、上传、解绑和恢复 workspace 的实现。公开 `/llm/weaponry` 的路由、请求参数、
HTTP 状态、响应体、Progress 及 Callback JSON 均不改变。

## 2. 分层

- `terms_catalog.py` 归属 Weaponry Adapter 层，负责术语卡清单、自动指纹、目录代际、
  启动协调和历史路由。
- `app/integrations/anythingllm` 继续独占 HTTP Transport、DTO 和原子 Client。
- `TermsRuleGuidanceAdapter` 只把检索结果转换为辅助语境；不拥有上传权限。
- 通用 `LocalPersistentTaskDispatcher` 只新增供应商无关的 `startup_gate`，不知道术语或
  AnythingLLM。

## 3. 自动身份

目录指纹格式固定为 `terms-manifest-v1:sha256:<64 hex>`。摘要输入为协议版本及按相对路径
排序后的路径、`card_id`、原始 UTF-8 内容，使用长度前缀消除拼接歧义；不包含绝对路径、
文件时间、机器名或人工标签。实际 workspace 名称为规范化基础名称加摘要前 16 位。

## 4. 启动与失败语义

启用术语辅助后，生产组合根先冻结本地清单和 execution 策略。Weaponry Dispatcher 取得
跨进程单实例锁后、创建线程前调用协调器：

1. 精确查找或创建版本化 workspace；
2. 以 SQLite 持久化的完整 `document_location` 对照远端集合，只上传可证明缺失的卡；
3. 逐卡绑定并按同一完整 `location` 查回；
4. 按每张卡的 `bound + document_location` 恢复事实校验 workspace 文档集合与本地清单完全一致；
5. 成功后发布 `fingerprint -> workspace_slug` 只读映射，再启动 Worker。

创建异常只允许精确重查一次。上传、绑定或查回结果不确定时，SQLite 保存
`outcome_unknown` 并 fail-closed，后续启动禁止盲目重放。网络调用期间不持有数据库事务。
AnythingLLM 可能把 workspace 文档的展示 `title` 改写成带上传 UUID 的 `location` 文件名，
因此 `title` 不得作为远端所有权或完整性证明。若版本化 workspace 非空但本地恢复事实缺失，
协调器必须拒绝按标题猜测归属，交由运维对账，禁止自动重复上传。
旧版本 workspace 不自动删除；旧 execution 按快照指纹读取旧版本。升级前的人工指纹只读
路由到原 workspace，不允许新写入。

## 5. 运维与演进边界

`scripts/sync_weaponry_terms_catalog.py --dry-run` 只读生成计划，`--apply` 取得与生产
Dispatcher 相同的 Weaponry 单实例锁后调用同一协调器；锁被服务占用时拒绝并发写入。
当前互斥和状态事实仍基于单实例文件锁与 SQLite，只证明本地单实例语义。多实例部署时应将
协调所有权、目录状态和 fencing 迁移到共享数据库/可靠任务系统，不能把当前实现宣称为
分布式安全。
