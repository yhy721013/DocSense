# 知识谱系类别文件对话整合实施计划

## 1. 文档状态与取代关系

- 历史状态：旧 `/llm/chat + chatId + architectureId` 模式阶段 0～7、Schema v6 和离线审查已完成。
- 当前状态：旧公开方向已被 `260801-对话模块迁移与知识谱系独立接口详细实施计划.md` 取代；不再继续原 I7/I8 发布路线。
- 保留价值：直接文件解析、不可变 Binding、原子 Scope、失败关闭和 run_id 恢复规则继续作为内部设计输入。
- 公开契约：当前行为必须以 `docs/接口文档/` 为准，本文不能恢复旧 selector 或旧 History 合同。

实际历史执行结果见 `../更新记录/260729-知识谱系类别文件对话整合执行记录.md`。

## 2. 历史目标

1. 在同一 Chat 内用严格二选一 selector 区分 fileNames 与 architectureId。
2. architecture 首轮解析类别直接文件并冻结 Scope，后续同 ID 只复用快照。
3. 会话永久绑定模式与规范化 ID，冲突优先于目录或容量错误。
4. Binding、Revision、Head、run input 和 message 原子提交并可从 SQLite 恢复。
5. Workspace 额外绑定不得扩大模型实际范围，History 不动态展开当前目录。

## 3. 历史数据与事务设计

- Schema v5 引入 Session Binding、architecture Scope Revision 和版本化 run input。
- Schema v6 增加 Admission Guard、Binding/Revision/Head/message 对称约束和 JavaScript 安全整数门禁。
- 目录查询必须参数化、稳定排序且有界；整体超限或坏记录失败关闭。
- Candidate 的 I/O 错误延迟到事务裁决，先判断既有 Binding/模式冲突，避免错误优先级泄漏状态。
- 外部绑定必须得到精确回执；结果未知或成员缺失不得回退旧引用伪装成功。

## 5. 当前可复用规则

- 业务身份必须显式、规范化并持久绑定；不能从 Workspace 名称或当前目录反推。
- 首轮解析得到不可变直接文件快照；恢复只读持久事实，不重新查询并扩大范围。
- 事务内只处理本地状态，网络 I/O 位于事务外；所有权/结果未知时保守隔离。
- 日志仅记录模式、规范化业务 ID、run/conversation 标识和脱敏计数。
- 多实例前必须补共享 lease/fencing、可靠队列、跨实例通知和数据库一致性门禁。

## 6. 当前迁移结论

后续独立接口将 File Chat 与 Weaponry Chat 的公开身份、路由和删除策略分离，同时复用内部 conversationId、Domain/Application、SQLite 和 AnythingLLM 核心。旧 architecture selector、旧复合 History 字段和旧发布顺序均不得恢复；需要查历史原因时阅读本文和整合执行记录即可。
