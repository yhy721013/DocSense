# 阶段 2-0 直接父节点专项独立阻塞边界

> 冻结日期：2026-08-12  
> 专项计划：`docs/重构记录/260804-知识谱系解析直接父节点文件范围实施计划.md`  
> 结论：专项仍被自身阶段 0/接口确认门禁阻塞；不阻塞阶段 2 通用 Task Kernel

## 1. 已确认但尚未授权实施的范围

专项只可能影响 `POST /llm/weaponry` 在 `filePathList` 缺省或为空数组时的自动文件范围。非空
`filePathList` 继续只代表调用方显式文件；请求 `architectureId` 精确对应永久 Knowledge
`documents.architecture_id`；父关系只允许来自正式 Analysis 受理时已经完整校验的显式 `parentId`，
禁止解析 `path/pathName`、Workspace 名称或文档 metadata 猜测。

即使最终实施，也禁止新增/删除/改名请求参数、响应字段、Callback、Progress、Header、SSE 或
WebSocket 字段。由于空范围的业务语义和错误映射会变化，必须先取得负责人对
`docs/接口文档/README.md` 与 `docs/接口文档/知识谱系解析.md` 的明确修改授权。

## 2. 专项仍未决的五项门禁

1. 服务端兼容默认树能否发布业务父关系；
2. 同节点不同 `parentId` 的批内/跨批受理、冲突态和人工解除规则；
3. 目录未知、冲突、损坏时采用哪个既有 HTTP 状态和错误体；
4. 开关启用前的覆盖率、允许回填来源、阈值和诊断输出；
5. `relation_revision` 粒度、同批来源 execution 选择及是否需要追加 relation event。

这些问题涉及公开失败语义和长期目录权威，不能由阶段 2 Task/Attempt/Step 实现者临场决定。专项
未完成确认前继续保持“计划待实施”，不得修改接口文档或业务代码。

## 3. 与阶段 2 通用内核的隔离

阶段 2 可以为现有 Weaponry v2 任务增加通用 Authority、Attempt、Step、Event、UoW 和恢复能力，
但必须保持当前文档范围快照语义，不得引入以下专项专属资产：

- Weaponry Input v3；
- `DOCSENSE_WEAPONRY_INCLUDE_DIRECT_PARENT_DOCUMENTS`；
- `architecture_parent_relations/revisions/events`；
- `resolution_policy`、`resolved_architecture_ids`、`catalog_relation_revision`。

阶段 2 的 Weaponry Codec 继续写 v2；v3 版本号只由获批后的直接父节点专项使用。未来专项若在 v2
Task Control Store 落地后实施，必须接入新的 Admission UoW/Knowledge Catalog Repository，禁止把
父关系 SQL 重新塞回 `LLMTaskService`。

## 4. 当前检查结论

当前代码仍为 `WEAPONRY_INPUT_SCHEMA_VERSION=2`；上述环境键、Schema 表和 v3 输入字段均未出现在
生产实现或 `.env.example`。因此，本专项的未决讨论被明确封存在专项范围内，不影响继续完成阶段
2-0 的通用内核编码前门禁。当用户正式要求启动该专项时，必须先回到五项决策和接口文档授权。
