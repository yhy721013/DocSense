# 阶段 2-0 Task Control 数据库路径、身份、预检、归档与回滚基线

> 冻结日期：2026-08-12  
> 性质：阶段 2 编码前内部约束，不是公开接口文档  
> 当前能力边界：本文冻结规则与只读诊断；v2 Schema 初始化和生产切换仍属于 2-2，尚未实现

## 1. 路径与数据库身份

- 新内部环境键固定为 `DOCSENSE_TASK_CONTROL_DB_PATH`；默认值固定为
  `${DOCSENSE_RUNTIME_DIR}/db/task-control-v2.sqlite3`。
- 旧路径仍由 `DOCSENSE_LLM_TASK_DB` 或 `${DOCSENSE_RUNTIME_DIR}/llm_tasks.sqlite3` 解析。
- 两个路径必须先解析为绝对路径再比较；Windows 比较折叠大小写。相同路径一律拒绝，禁止原地
  修改旧 CHECK、增量补列或把旧库伪装成 v2。
- v2 `PRAGMA application_id` 固定为十进制 `1146307378`，十六进制 `0x44534332`（ASCII `DSC2`）；
  `PRAGMA user_version=2`。
- metadata 固定为 `schema_name=docsense.task-control`、`schema_generation=2`、兼容范围 `2..2`，
  并必须包含 Schema fingerprint、DB instance UUID 和 UTC 创建时间。
- Schema fingerprint 不直接散列格式不稳定的 `sqlite_master.sql`；2-2 将最终语义 Schema manifest
  按 Canonical JSON v1 编码，再计算
  `SHA-256(schema_name + LF + schema_generation + LF + canonical_schema_manifest)`。

机器可读唯一来源为
`tests/contracts/stage2_task_control_database_contract.json`。上述常量如需改变，必须先更新设计审查，
不能在 Bootstrap 或 Store 编码时临场选择。

## 2. 固定切换算法

1. 只装载并校验类型化 Runtime Config；不得构造旧/新 Store，不得启动后台线程。
2. 解析旧/新绝对路径并确认不同，取得进程级 Schema/启动锁。
3. 以 SQLite URI `mode=ro` 打开旧库；只输出表级计数和路径摘要，不输出任何行身份或秘密。
4. 任一活动 Task、未收敛 Callback、未清理/隔离资源、pending 外部调用审计、未知状态或损坏均
   fail closed；禁止复制、重置、删除或伪造恢复证据。
5. 只有旧库预检通过后，新路径不存在才可在 2-2 原子初始化空 v2；若已存在则必须完整验证身份、
   generation、fingerprint、外键、索引和完整性，禁止 `CREATE TABLE IF NOT EXISTS` 静默修补。
6. Schema 验证成功后才构造 Connection Factory/UoW/Store/Application；最后启动 Executor 与维护调度。

旧库处于 WAL 模式但所在目录只读时，SQLite 可能因无法创建共享内存侧车而拒绝普通 `mode=ro`。
诊断脚本只在“全部相关写进程已停止”得到显式确认且现场没有 `-wal/-shm` 时允许
`immutable=1`；它还会比较检查前后的完整文件集元数据。该模式是离线只读快照手段，不是在线
并发检查，也不能证明生产多实例安全。

## 3. 旧库阻塞事实

预检至少覆盖：

- `llm_task_executions` 的 `accepted/running`，以及未收敛的 `pending/failed/sending/outcome_unknown`
  Callback；
- `llm_tasks` 各业务公开活动投影与未收敛 Callback；
- `callback_delivery_guards` 的 `sending/outcome_unknown`；
- Report/Analysis/Weaponry 非 `cleaned` 资源记录；
- Weaponry 非 `resolved` 创建意图、`pending` Interaction Audit；
- `llm_interactions` 未完成的 Workspace 清理；
- 未 `closed` 的历史 `rag_resource_leases`；
- 契约外状态、缺少必要状态列或 SQLite `quick_check` 失败。

旧版本不存在某张后来新增的表可以继续检查；表已经存在却缺少判断所需列时必须拒绝。诊断工具为
`scripts/preflight_stage2_task_control.py`，退出码 `0/2/3` 分别表示安全、存在待收敛事实、输入或
Schema 非法。

## 4. 文件集归档

`.sqlite3`、`.sqlite3-wal`、`.sqlite3-shm` 是同一权威文件集；若现场出现临时
`.sqlite3-journal` 也必须按未停写处理。应用不得自动删除、移动或归档任一成员。

显式维护归档必须满足：停止所有相关进程、阻止新受理和领取、确认侧车已正确 checkpoint/关闭、
一次性复制整个文件集、记录每个文件摘要与大小、验证归档后再决定是否保留原件。2-0 不执行真实
归档，也不删除任何旧文件。

## 5. 回滚算法

回切旧版本前必须停止全部 v2 Executor/维护任务并只读检查 v2。只要存在以下任一事实就禁止回切：

- `accepted/running/recovery_required` Task 或开放 Recovery Case；
- Callback sending/unknown、cleanup pending/unknown；
- 未对账外部副作用；
- 仍需由公开查询观察的新 Task 事实。

阻塞时只能保留 v2 完整文件集并前向修复。即使允许回滚，也不得让旧、新版本同时消费同一个
Task Control DB；代码回切与数据库选择必须作为一个受控发布动作完成。

## 6. 本次只读现场证据

2026-08-12 对当前配置解析出的旧 `llm_tasks.sqlite3` 做了离线只读检查：检查前没有可见 Python
进程，不存在 WAL/SHM/journal，主库最近修改时间早于本次检查。脚本以
`mode=ro&immutable=1` 打开，检查前后主库大小、修改时间和侧车集合一致。

- 旧路径摘要：`1EF33B617F39BE4AE8B32EE73CDF3C5964D94128540FC22B9FE6B8786F5734BE`；
- 计划新路径摘要：`8A3641D42F9ED6FFD1C8B285D2C8105DA0DD818F82BEFAF0B51E5FF47A4D1B19`；
- 两路径不同，新路径不存在；
- 14 条阻塞规则计数全部为 `0`，Schema 错误为 `0`；
- 结论：`safe_for_empty_v2_initialization`。

这只证明当前 Windows 本机、该时点、该离线 SQLite 快照没有切换阻塞事实；2-2 真正初始化前必须
在启动锁内重新执行预检。它不证明生产库、其他实例、未来时点或多实例并发安全。
