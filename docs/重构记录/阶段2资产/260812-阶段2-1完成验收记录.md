## 3. 核心不变量

1. Task Execution Authority 必须成组携带 `task_id + attempt_no + lease_token + fencing_token +
   lease_expires_at`；`owner_id` 只用于诊断，不能单独授予写权限。
2. Recovery 使用独立 Authority 和 fencing；只有新建 Recovery Case 可以让
   `recovery_generation + 1`，重新领取和决定提交保持 generation 不变。
3. 所有持久时间采用 UTC RFC3339 微秒格式并以 `Z` 结尾；Domain/Application 后续只能通过
   `ClockPort` 取时，时钟回拨必须失败关闭。
4. 业务终态后的 cleanup unknown 不回滚 Task、也不扩大既有受理冲突；核心 unknown 阻止同键，
   Callback unknown 沿用 Guard，不同键不受全局牵连。
5. Event 元数据使用有界简单值并拒绝重复键；外部写 Step 不得声明为无条件安全重放。
6. Port 不导入 SQLite、threading、Web、Celery 或业务 Adapter；网络、模型、文件转换和对象删除
   不得发生在未来的持久化 UoW 内。

## 9. 阶段 2-2 编码前确认的内部契约补充

阶段 2-2 第 3 步进入 Control Store 编码前，通过把既有 Port 与已冻结根 Schema 逐字段对照，发现
阶段 2-1 的抽象仍缺少三项持久化所需信息。该结论不否定当时的纯层验收，而是生产 Adapter 开始前
新增的契约完备性检查。经用户在 2026-08-12 明确确认：

1. `TaskAdmissionRequest` 增加不可变 `TaskBatchRef`；file/Analysis 必须携带，非 file 禁止携带，
   批量必须同一 ID、从 1 连续且保持输入顺序；
2. `TaskClaimRequest` 不再接收模糊 `owner_id`，改为结构化 `TaskOwnerIdentity`，规范 owner 文本只读派生；
3. Recovery 持久化入口改为完整 `classify_candidate_if_current(command)`，用显式 Case ID 或下一动作
   时间覆盖五类结论，并删除无法表达非 Case 分类的 `create_case_if_current` 抽象。

上述全部是内部 Domain/Port/测试契约补充；没有修改 `docs/接口文档/`、公开路由、请求参数、响应
字段、HTTP 状态、Callback、SSE 或 WebSocket 语义。机器权威同步提升为
`stage2_task_execution_contract.json` 当时提升为 schema version 2；阶段 2-2 后续经两轮确认补齐
retry-safe、Step unknown 原子隔离、Recovery heartbeat 和 Terminal Projection 后，当前权威为
schema version 3。
