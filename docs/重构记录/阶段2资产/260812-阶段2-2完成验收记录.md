## 3. 已冻结的核心实现

1. `SQLiteTaskControlStore` 是 v2 Task/latest/Attempt/Step/Recovery/Event 的直接 SQL 实现，不调用
   `LLMTaskService`，不创建连接，不自行提交或回滚。
2. Task Execution 写权限必须完整携带 Task ID、Attempt、lease token、fencing 和租约；owner 文本只
   用于诊断。Recovery 使用独立 lease/fencing，不能复用 Task Authority。
3. Step external intent 必须先于 I/O 持久化；精确相同命令重放返回 `DUPLICATE_STEP_INTENT`，不同
   Attempt/fencing/定义/时间不得伪装成幂等成功。
4. Recovery 外部动作遵循“Operation Intent 提交 → 事务外有界 I/O → Observation 与 Operation 原子
   收敛 → Decision”协议。接管者只能沿稳定 operation ID/幂等键对账，不能换 ID 盲重放。
5. `retry_authorized` 只重置精确 `outcome_unknown` Step 当前投影，保留旧 Step Attempt 历史；新执行
   必须回 accepted 后由普通 claim 创建更大 Attempt/fencing。
6. `finalize_from_checkpoint` 复核来源 Step Attempt、checkpoint code/digest，并在同一事务更新
   Task/latest/Event；Store 不按业务类型猜公开投影值。
7. 阶段 2-2 只读取 Callback Admission Guard，不写 Callback Delivery 表。完整 Delivery 写入由后续
   唯一 Callback Control Store 负责，并随业务切换通过共享 UoW 满足终态原子性。
