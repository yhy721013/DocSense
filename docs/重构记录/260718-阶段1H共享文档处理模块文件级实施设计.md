## 1. 目标与非目标

### 1.1 目标

1. 建立独立 `app/modules/document_processing`，统一拥有格式识别、MHTML、MinerU、OCR、
   PDF/DOCX/PPTX/XLSX/TXT/Markdown 预处理及处理谱系。
2. 让 Translation 只负责语言转换和翻译结果渲染，不再拥有原始文件识别、转换、OCR、
   MinerU 进程、临时目录或中间 Artifact 生命周期。
3. 使用不可变 Request/Result/Profile/Artifact/Lineage DTO；调用方只通过 Port 获取处理结果，
   不依赖供应商路径、打开的文件句柄或进程级单例。
4. 每个任务使用独立目录、稳定步骤身份和幂等 Artifact key；50 个在途任务不得共享可变路径、
   进度回调、Converter 实例或中间文件。
5. 记录原始/规范化 Artifact 的 SHA-256、MIME、处理 profile、父子关系和处理工具指纹，使 1D
   的 `legacy-normalized-artifact-v1` 和未来原始 MHTML 处理都可审计。
6. 保留本地 Artifact Adapter 作为阶段 1～2 兼容实现；阶段 3 只替换为 MinIO Adapter，不重写
   Application 或业务模块。
7. 通过兼容 Facade 小步迁移现有调用方，最后用架构门禁阻止新增代码从
   `app/services/translator/` 导入文档转换能力。

### 1.2 非目标

- 不在 1H 部署 MySQL、MinIO、RabbitMQ、Redis、Celery、FastAPI 或 Docker Compose。
- 不改变文件上传/解析、报告、武器谱、文件对话或翻译接口的参数、状态码、回调字段和时点。
- 不在 1H 承诺 OCR/MinerU 的识别准确率或 50 个重型转换同时执行；重型并发继续限流排队。
- 不把所有文件统一转换成一种格式；不同业务由冻结 profile 选择合适产物类型。
- 不自动删除历史目录、现有 workspace、文档、模型文件或 MinerU 缓存。
- 不把 Translation 专属的双语排版、术语翻译和语言模型 Prompt 放入文档处理模块。

## 3. 目标结构与依赖方向

```text
analysis / report / weaponry / chat / translation application
                         │
                         ▼
             document_processing/application
        PrepareDocument / NormalizeDocument / InspectDocument
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
 document_processing/domain   document_processing/ports
  Artifact/Profile/Lineage     Converter/OCR/Artifact/Resource
                                      ▲
                                      │
                          document_processing/adapters
                  MHTML / MinerU / OCR / Local Artifact / MinIO(阶段3)
```

建议目录：

```text
app/modules/document_processing/
├── README.md
├── domain/
│   ├── models.py              # 文档身份、Artifact、处理请求/结果、lineage
│   ├── profiles.py            # 版本化且不可变的处理策略
│   ├── media_types.py         # MIME/扩展名检测纯规则
│   └── errors.py              # 稳定失败分类
├── application/
│   ├── prepare_document.py    # 按 task/step 恢复并生成目标 Artifact
│   ├── inspect_document.py    # 只读格式与能力判断
│   └── resource_recovery.py   # 有界补偿入口
├── ports/
│   ├── source_files.py
│   ├── converters.py
│   ├── ocr.py
│   ├── artifacts.py
│   └── resources.py
└── adapters/
    ├── mhtml.py
    ├── mineru.py
    ├── builtin_ocr.py
    ├── office.py
    ├── local_artifacts.py
    └── minio_artifacts.py     # 阶段 3 实现
```

依赖规则：

1. Domain 不导入 Flask、数据库、文件系统、subprocess、MinerU、OCR、Translation 或业务模块。
2. Application 只依赖本模块 Domain/Ports 与稳定 TaskId/ArtifactRef。
3. 各业务模块拥有“为何处理、需要哪种产物”的策略；document_processing 拥有“如何安全处理”。
4. Translation 可以调用 DocumentProcessing Application，但 DocumentProcessing 不得反向导入
   Translator、翻译模型、翻译 Prompt 或全局翻译进度对象。
5. 业务模块不得导入本模块 Adapter；组合根选择本地、MinerU、OCR 或未来 MinIO 实现。
6. `app/services/translator/` 兼容 Facade 只能单向委托新模块，不得让新模块回调旧 Handler。

## 4. 内部契约

### 4.1 不可变 DTO

`DocumentProcessingRequest` 至少包含：

```text
task_id / step_id / source_artifact_ref
source_sha256 / declared_media_type / detected_media_type
target_representation = original | pdf | markdown | text | html
processing_profile_id / trace_id
```

`DocumentProcessingResult` 至少包含：

```text
result_artifact_ref / size / sha256 / media_type
processing_profile_id / processor_fingerprint
parent_artifact_ref / lineage_events
warnings / outcome = succeeded | skipped | failed | outcome_unknown
```

所有集合使用不可变结构；不得在任务之间共享可变字典、Converter、Session、临时目录或进度
Callback。日志只记录 task_id、步骤、文件类型、大小、哈希摘要前缀、耗时和错误分类，不记录正文。

### 4.2 处理 profile

profile 是可重试和可审计的运行清单，不是文档质量评分，至少冻结：

- MIME/扩展名冲突处理规则；
- MHTML MIME 解码、主内容清理和降级策略版本；
- MinerU/OCR 引擎、模型/语言/解析模式和供应商指纹；
- 目标产物类型、编码、换行和空文件规则；
- 允许的明确失败降级路径；
- 超时、重试次数、临时资源和 Artifact 命名策略。

同一 task/step 重试必须读取 execution 中的 profile，不能重新读取变化后的环境默认值。profile
变化生成新版本，旧 execution 不迁移。

### 4.3 Artifact 与 lineage

- 原始 Artifact 永不被规范化结果覆盖；每个派生产物保存父引用、SHA-256、size 和 MIME。
- `legacy-normalized-artifact-v1` 明确表示“历史处理文本清洗副本”；必须保存可获得的来源引用、
  清洗器指纹和哈希，且不得标记为 `original` 或 `mhtml-main-content-v1`。
- 本地阶段使用 `{task_id}/{step_id}/{artifact_kind}/...` 任务级命名空间和原子发布；阶段 3 用相同
  逻辑 key 映射 MinIO。
- 处理中间文件属于 execution-owned scratch；共享模型、共享 MinerU 服务和既有业务文档属于
  shared，任务清理器不得删除。
- 外部转换“返回结果未知”时保留资源事实并进入对账，不盲目重新提交或猜测性删除。

## 5. 分波次实施步骤

### 1H-0：现状清单、兼容契约与黄金资产

1. 盘点 translator、utils、report、analysis、RAG 和文件对话的全部处理调用点与配置读取。
2. 冻结 MHTML→PDF/Markdown、扫描 PDF→Markdown、Office/PDF→Markdown、TXT/MD 透传的当前
   成功、明确失败、降级、命名和日志行为。
3. 自建不含敏感数据的最小语料：普通 MHTML、导航/参考文献型 MHTML、文本 PDF、扫描 PDF、
   DOCX、PPTX、XLSX、TXT、MD、空文件、扩展名与 MIME 冲突文件。
4. 冻结“预处理不得调用 Translation”的计数断言，以及 50 个 task 目录/Artifact key 不冲突断言。
5. 输出 current/target 差异；若发现必须改变公开接口或回调，立即停止确认。

**退出门禁：** 所有调用点、配置、临时目录、全局状态、降级路径和资源所有者都有清单；黄金
资产不依赖真实生产文档或现有 AnythingLLM workspace。

### 1H-1：Domain、Port 与 Application 骨架

1. 创建四层目录、职责 README 和 AST 架构门禁。
2. 实现 ArtifactRef、ProcessingProfile、Request、Result、Lineage、Outcome 和稳定错误分类。
3. 定义 SourceFile、Converter、OCR、ArtifactStore、Resource Port 与严格 Fake。
4. 实现 `PrepareDocument(task_id, step_id)`；外部 I/O 前后均持久化/审计明确状态，不在事务中
   执行文件、subprocess 或网络操作。
5. 使用 Fake 验证成功、跳过、明确失败、结果未知、Artifact 提交失败和清理中断。

**退出门禁：** Application 无 Translator/Flask/SQLite/具体 Converter 导入；相同输入/profile
得到相同 Artifact 身份和 lineage；严格 Fake 未配置调用即失败。

### 1H-2：MHTML 独立处理

1. 把 MIME 检测、解码、首选正文选择、导航/metadata/参考文献型内容处理变为纯规则。
2. 把 Chrome/Edge MHTML→PDF 封装为 Adapter；命令、超时、返回码和临时路径不泄漏到 Domain。
3. 固定 PDF 成功、纯文本降级和 outcome_unknown 分类；降级选择必须写入 profile/lineage。
4. `mhtml_normalizer.py` 改为兼容 Facade，单向调用新 Application/Adapter。
5. 用原始自建 MHTML 黄金样例验证哈希、主内容、降级、清理和并发隔离；历史清洗副本仅验证
   `legacy-normalized-artifact-v1` 的可追溯性。

**退出门禁：** 新模块不导入 Translator；现有 workspace/文档零修改；所有临时文件均由任务
作用域拥有并可幂等清理。

### 1H-3：MinerU、OCR 与通用格式 Adapter

1. 把 MinerU 提交、轮询、排队、解压和结果校验迁入 Adapter；稳定 task/step 幂等键和资源记录。
2. 把内置 OCR 与 MinerU OCR 建模为两个可配置实现；环境变量只在组合根解析一次。
3. DOCX/PDF/PPTX/XLSX 处理不再要求构造 `HYMTTranslator`；TXT/MD 透传和编码规范化独立测试。
4. 重型转换使用共享许可限流，正常积压保存在任务事实中，不创建无界线程/内存队列。
5. 覆盖服务不可用、排队超时、处理中断、结果目录缺失、空 Markdown、Artifact 发布失败和
   cleanup 重试；结果未知不得自动重复不可逆步骤。

**退出门禁：** 50 个在途任务可拥有独立输入/目录/状态，实际 MinerU/OCR 并发受配置限制；
没有全局可变 Progress Callback 或跨任务 Converter/Session。

### 1H-4：调用方迁移与 Translator 兼容 Facade

建议顺序：

1. `app/services/utils/mhtml_normalizer.py`、`ocr_preprocessor.py`；
2. report 的 `LegacyReportFileAdapter`；
3. analysis/RAG 调用点；
4. `translation_service.py` 与 `DocumentTranslator`；
5. weaponry/文件对话后续需要的预处理入口。

`DocumentTranslator` 在兼容期只做：调用 DocumentProcessing 取得规范化 Artifact → 调用
TranslationPort 翻译文本 → 生成既有双语/单语输出。它不得再直接构造 MHTML/MinerU/OCR
Converter。每迁移一个调用方都用相同黄金输入比较公开结果和副作用，禁止长期双写或同一文件
被新旧处理器各执行一次。

**退出门禁：** 业务 Application 只依赖 Port；Translator 目录不再拥有转换实现；兼容 Facade
的公开 Python 调用仍可用，且无任何 HTTP/Callback 参数变化。

### 1H-5：关闭验收与遗留清理证据

1. 运行本模块单元/契约/并发/故障测试及 report、analysis、translation、RAG、weaponry 回归。
2. 静态证明 `app/modules/document_processing` 不导入 Translator，且正式调用点不再直接导入
   `translator.mhtml2pdf` 或 `translator.MinerUConverter`。
3. 增加永久 AST 门禁：新的 MHTML/MinerU/OCR/Office 转换代码不得进入 Translator 或 utils。
4. 输出 Translator 旧 Handler、旧 Converter、旧缓存和测试工具的生产/测试/配置三类引用清单；
   只有三类引用均清零后才删除实现文件。
5. 更新根 README、模块 README、测试索引、上位计划和执行记录，明确未部署生产及阶段 3 MinIO
   责任。

**阶段关闭条件：** 文件处理与 Translation 单向依赖成立；Artifact/lineage 可确定性重放；50 个
控制面任务无路径/状态串扰；所有降级和未知结果可审计；公开接口零变化。

## 6. 与 1D、1G 和后续基础设施的关系

### 6.1 与 1D

- 1D-3B 不再等待原始 MHTML 忠实重建，可使用明确标记的
  `legacy-normalized-artifact-v1` 实施 Retrieval Adapter。
- 1D production profile 必须记录 document processing profile/Artifact provenance；处理指纹变化
  时生成新 profile，不重写旧 execution。
- 1D 仍必须完成来源身份、score/rank 协议、正文质量、Evidence/rows 和无二次 RAG 门禁；1H
  不替代这些业务正确性要求。
- 新的生产文件入库流程完成 1H 后必须改用独立 DocumentProcessing Application；不得继续让
  Translator 拥有转换生命周期。

### 6.2 与 1G

1H 可以与 1D/1E/1F 的后续波次并行设计和按调用点迁移，但 1G 的最终旧路径删除必须等待
1H-5 的三类引用证据。阶段编号表达独立工作流，不表示可以绕过依赖强行按字母顺序关闭。

### 6.3 与阶段 2～5

- 阶段 2：把处理步骤纳入 Attempt/Step/Checkpoint、lease/fencing 和统一本地执行器。
- 阶段 3：实现同步 SQLAlchemy Artifact Repository 和 MinIO ArtifactStore Adapter；数据库保存
  引用/所有权/删除资格，MinIO 不是任务状态真相源。
- 阶段 4：需要异步派发的处理步骤通过 Outbox 与任务事实同事务提交。
- 阶段 5：MinerU/OCR/摄取使用独立队列和资源许可；积压无业务数量上限，Worker 持续排空。

## 8. 回滚与完成边界

1. 每次只切换一个调用点，旧 Facade 暂时保留；同一请求只能由新旧实现之一拥有处理权。
2. 新增 Schema/Artifact 类型只增不删；回滚组合根不删除已生成 Artifact 和 lineage。
3. 回滚不得让新 execution 读取旧环境默认值；不能解码目标 profile 时明确失败，不静默降级。
4. 1H 完成不等于 MinIO、可靠队列、多实例或生产容量完成；这些仍属于阶段 2～5、10。
5. 只有 Translator 不再拥有文件转换实现、全部调用点迁移、架构门禁和扩大回归通过后，才能
   宣称“文件处理已从 Translator 独立”。
