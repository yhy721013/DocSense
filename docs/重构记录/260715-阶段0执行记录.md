## 2. 目标契约与当前实现差异矩阵

`docs/接口文档/` 是唯一对外权威来源。下表中的“待实现”不能理解为当前路由已经具备目标行为。

| 接口/协议 | 当前实现基线 | 已批准目标 | 实施波次 |
| --- | --- | --- | --- |
| `POST /llm/analysis` | 202 + 任务 JSON | 202 空响应体；请求、400/409、批量顺序和回调不变 | 1F |
| `POST /llm/generate-report` | 202 + 任务 JSON；活动 reportId 仍可能重复受理 | 首次 202 空响应体；活动任务 409 且无新任务/线程 | 1C |
| `POST /llm/weaponry` | 202 + 任务 JSON | 202 空响应体；请求、400/404/409 和回调不变 | 1D |
| `POST /llm/check-task` | 成功返回任务、进度、callback 状态和 replay 结果；混合 params 会过滤非对象元素 | 原文档已列 file/report：成功 200 空响应体；任一非对象 params 元素整次 400；内部仍同步检查/补发并审计；其他 400/404 不变 | 1B |
| `WS /llm/progress` | 无 action 订阅 + 显式 subscribe/query/unsubscribe + ack；混合 params 会过滤非对象元素 | 只保留无 action 的 file/report 订阅与既有进度消息；action/非对象 params 整条失败，返回 error 后保持连接且无 ack；关闭连接清理全部订阅 | 1B |
| `POST /llm/reassign` | 同步响应 | 不变 | 1E 只重构内部 |
| `/llm/chat*` HTTP/SSE | 现有 JSON、SSE 和断连语义 | 不变 | 后续阶段只替换适配器 |
| file/report/weaponry 出站回调 | 现有业务键、状态和结果字段 | 不变；report 失败继续带 `details: ""` | 各业务波次 |
| `/debug/*` | 始终注册 | 仍为非生产接口，生产必须由代理/网络拒绝 | 1G/部署阶段 |

本次没有新增、删除或改变任何请求参数。weaponry 的 check-task/Progress 虽然当前代码可处理，但现有甲方接口文档没有将它们明确冻结为对应公开能力，因此阶段 0 不把内部扩展升级为外部承诺；若未来需要公开，必须另行确认接口文档。

### 2.1 显式 Progress action 的来源结论

- Git 历史显示显式 `subscribe/query/unsubscribe` 与 ack 来自 2026-03-16 的多任务兼容扩展（提交 `2b7b0f12`）。
- 当时的设计文件明确把甲方正式协议和项目兼容扩展区分开。
- 当前仓库调用方只发现历史计划、内部测试和 `scripts/test_llm_progress.*`，未发现生产前端调用。
- 因此按用户确认，目标契约删除显式 action/ack；收到 action 时拒绝整条消息、返回 error、保持连接且无 ack。历史文档只增加“已失效”提示，不抹除历史事实。

### 2.2 混合 params 校验结论

- 当前共享解析 helper 会过滤混合数组中的非对象元素，再继续处理剩余对象。
- 该容错没有甲方契约依据，且会让一条非法批量消息产生部分副作用。
- 因此按用户确认，波次 1B 改为严格校验：任一非对象元素使整次 HTTP 请求或 WebSocket 消息失败，不部分处理；WebSocket 返回 error 后保持连接。

## 4. 容量口径、工具与待测 SLO

### 4.1 已冻结口径

| 维度 | 阶段 0 工作负载 | 含义 |
| --- | --- | --- |
| 短请求 | 50 并发、500 次 history 请求 | 验证 Web/数据库轻请求稳定并发，不触发模型 |
| Progress 长连接 | 50 个 WebSocket，同一时刻保持并接收初始快照 | 验证无 action 订阅、连接保持和释放 |
| 混合负载 | 上述两个场景用 `--parallel-scenarios` 同时运行 | 验证 50 条长连接存在时仍承载 50 并发短请求 |
| Chat SSE | 50 条流，默认禁用的模板场景 | 必须先生成 50 个互不冲突的 chatId，并准备完整 AnythingLLM/模型和专用数据 |
| 在途任务 | 50 个 accepted/queued/running 混合任务 | 不要求 50 个重任务同时执行；重型步骤按资源队列限流 |
| AnythingLLM 摄取 | 初始执行并发 1 | 只有错误率、完整性和资源指标允许时再试 2、4 |

`scripts/stage0_load_baseline.py` 默认只允许回环地址，不启动服务、不记录正文；访问其他离线服务器必须显式使用 `--allow-non-loopback`。重型场景同时要求场景 `enabled=true` 和 `--allow-heavy-services`，避免误触发模型费用或资源占满。

当前 WebSocket 样本在首帧后持续调用 `receive`，并交由 simple-websocket 的
Ping/Pong 机制识别对端失活；仅 `sleep` 到保持窗口结束不再算成功。报告中的
`latencyMs` 只统计成功样本，失败耗时进入 `failedLatencyMs`，长连接另列
`readyLatencyMs` 与 `holdDurationMs`。客户端 close 只能证明本地关闭调用完成，
服务端订阅是否清零仍必须结合内部 Registry/指标验证。

### 4.2 实测必须采集

- 总样本、成功率、吞吐、P50/P95/P99/max、HTTP 状态和异常类型。
- Web/Worker CPU、RSS、线程、文件句柄、临时磁盘、连接建立/释放时间。
- MySQL 连接池/锁等待、RabbitMQ ready/unacked、Redis 通知、MinIO 耗时。
- 任务 accepted→queued→running→terminal 各阶段耗时、最大/平均排队时间和积压恢复时间。
- AnythingLLM/模型 429、5xx、超时、Document Processor 错误和实际重型并发。
- 回调耗时、明确失败、结果未知、人工/check-task 补发次数。

成功率、P95/P99、稳态持续时间、断连率、最大排队时间和故障恢复时间必须基于专用环境首轮结果评审，当前不得擅自填入“看起来合理”的数字。该项延期不阻塞结构改造，但完成并通过这些数值前，不能签署生产容量承诺、确定生产池大小或宣称 50+ 目标完成。

| `data/runtime/llm_tasks.sqlite3` | 237,568 B | llm_tasks=10 | status `2`=10；callback_status `pending`=10 |

共同事实：SQLite `user_version=0`、页大小 4096、journal mode 为 `delete`，没有视图或触发器；当前文件中的任务表仍是早期 12 列投影，不包含新代码可能按需初始化的 execution/audit 表。由于这些数据已明确仅供测试且无需迁移，阶段 3 不从旧行推导生产数据，但必须从当前代码、Repository 契约和测试建立完整 MySQL Schema、Alembic 空库升级及种子验证。

当前 `scripts/stage0_sqlite_inventory.py` 在显式只读事务中输出 DDL、列名、索引/外键
数量、可选行数和可选状态聚合，不输出 request/result/payload 正文；同时记录
`PRAGMA data_version` 前后值、主文件/WAL/SHM 元数据和变化标记。`sha256` 是盘点结束
后主文件与存在的 WAL 的物理指纹，不冒充逻辑快照版本；状态聚合扫描可用
`--skip-status-distributions` 关闭。

## 6. 单服务器 Docker Compose 目标拓扑

### 6.1 组件边界

| 组件 | 目标职责 | 关键约束 |
| --- | --- | --- |
| Reverse Proxy | TLS/访问控制、连接超时、`/debug/*` 拒绝、Flask→FastAPI 灰度 | 不执行业务，不缓存 SSE/WS 正文 |
| Web 实例 | HTTP/SSE/WS、鉴权、校验、用例调用和 Presenter | 至少两个逻辑实例验证无进程内真相；同机不等于高可用 |
| Outbox Relay | 从 MySQL 安全领取并发布消息 | 发布确认、重复发布可容忍、单一执行权 |
| Scheduler/Recovery | 租约回收、超时扫描和补偿调度 | 需要 leader/租约，不能多实例重复调度 |
| Celery Worker 池 | 按 callback/light、analysis、report、weaponry 等队列隔离执行 | 重型队列按 CPU/GPU/AnythingLLM 配额限流，不跟 Web 抢执行线程 |
| MySQL | 任务、业务状态、chat、租约、事件和 Outbox 真相源 | Redis/RabbitMQ 均不能替代数据库事实 |
| RabbitMQ | 可靠路由、确认、重投递、DLQ | 消息只传稳定 ID/版本，不传大文件或可变请求对象 |
| Redis | 跨 Web 实例进度唤醒、短缓存、可选限流 | 通知可丢，不能作为任务最终状态真相 |
| MinIO | 输入、报告和中间产物的唯一共享存储 | 按 task/attempt 命名空间，数据库提交后再发布最终引用 |
| AnythingLLM/模型/文件源/回调方 | 受控本地离线环境中的外部能力 | 当前不建设 URL 白名单/DNS/重定向策略；若拓扑或信任边界改变则重审，也不纳入 DocSense 单机 HA 承诺 |

### 6.2 网络与故障边界

- Reverse Proxy 只暴露正式入口；MySQL/RabbitMQ/Redis/MinIO 管理端口不直接暴露给业务调用方。
- Web 与 Worker 使用不同账号和最小权限；管理面、数据面和外部能力访问按网络分区控制。
- 同一物理服务器宕机仍会同时影响所有容器，因此本方案只实现进程级隔离、可靠重启和数据恢复，不宣称节点级高可用。
- 数据库、Broker 和对象存储的备份必须落到与主数据不同的故障介质；准确介质、周期、RPO/RTO 和责任人仍待 Runbook 确认。
- 组件版本、CPU/内存/磁盘配额、连接池和 Worker 数量必须在阶段 3/5 前根据宿主机资源与基线确认，本阶段不臆造固定值。

开发阶段继续使用当前环境；本记录不授权现在创建 Compose 文件、启动基础设施或切换持久化。

## 7. 安全基线与剩余门禁

### 7.1 已冻结策略

> 2026-07-16 决策更新：当前生产被确认为受控本地离线环境，负责人决定暂不建设 URL
> 安全策略。因此域名/IP 白名单、DNS 重绑定和重定向目标复核不再是波次 1C 或当前上线
> 门禁；若部署拓扑、URL 来源或信任边界变化，必须重新进行安全评审。下载/callback 的
> 既有功能超时继续保留，但本记录不授权新增 URL Policy。

- `/debug/*` 在生产 Reverse Proxy/防火墙层默认拒绝，不能只依赖 `APP_DEBUG=false`。
- MySQL/RabbitMQ/Redis/MinIO/AnythingLLM 使用独立最小权限账号；凭据不写入镜像、仓库、URL 或日志。
- 日志不记录 Authorization、密钥、完整 Prompt、文件正文、回调正文或带敏感查询参数 URL；只记录 trace/task/业务键、阶段、耗时和错误类型。
- 临时目录与 MinIO key 必须包含不可变 task ID/attempt，并在 `finally`/补偿任务中清理；不同任务不得共享可变目录。
- 上传和解压路径必须校验扩展名、MIME、大小、路径穿越和压缩炸弹；恶意文件扫描能力在生产安全评审中确认。

### 7.2 后置重审条件

D0-11 已按“当前不建设 URL 安全策略”关闭，不再要求波次 1C 提供服务器白名单。只有
实际生产不再是受控本地离线环境、URL 可由不受信任调用方控制，或出现跨网段/重定向等
新拓扑时，才重新登记主机/IP/端口/TLS/认证和重定向策略。
