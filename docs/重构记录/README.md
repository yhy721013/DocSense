1. `docs/接口文档/`：唯一公开契约权威。

5. 当前问题对应的文件级设计；已完成事实转到 `docs/更新记录/` 的整合记录核验。
6. `阶段0资产/`：模块/表/资源所有权与阶段交接矩阵。

## 当前架构边界

- `app/container.py` 是框架无关组合根；正式 Blueprint 不直接构造数据库、供应商客户端或后台线程。
- `/debug/*` 只读但必须由生产网络/反向代理限制访问。
- 当前离线证据主要是 Windows、SQLite 单实例和 Fake/受控 Transport，不能证明可靠队列、多实例、共享数据库一致性、生产容量或 exactly-once。
- 本地 Dispatcher 的 Event 只负责唤醒；SQLite accepted 事实和启动/周期扫描才是恢复依据。
- 外部副作用结果未知时保守隔离，不盲目重放、查名删除或覆盖权威终态。
- 阶段 2 的结构整理以事实所有权为准：新 Store 直接拥有 SQL，旧入口只可短期单向委托；
  `app/adapters/web` 保留为目标协议边界，Knowledge DatabaseService 的物理迁移留到阶段 3A。
- `.env` 只是本地环境变量来源，类型化 Runtime Config 才是应用装配输入；Callback 本地 JSON 是
  Debug 诊断副本，不是 Callback 或 Task Recovery 的权威事实。

## 维护规则

- 计划与执行分离：本目录写目标、文件边界、门禁与回滚；`docs/更新记录/` 写实际结果。
- 连续子阶段不再逐篇建文档，优先在一篇计划/整合记录中维护里程碑表。
- 必须区分目标、实施中和当前能力；历史计划被取代后应整合或缩为兼容导航。
- 任何接口文档变更必须先确认，禁止擅自增删前后端接口参数。
