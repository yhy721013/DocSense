# 文件对话运行协调目录说明

本目录负责“哪一个执行器有权推进某条运行”的协调边界。当前实现使用 SQLite 单实例互斥；接口形状已为未来共享持久化、租约续期和围栏令牌预留，但不宣称现阶段具备跨实例保证。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `__init__.py` | 导出运行协调协议、租约类型和 SQLite 锁服务。 |
| `lease.py` | 定义执行租约、能力声明、租约丢失异常和 `ChatRunCoordinator` 协议。 |
| `lock_service.py` | 当前 SQLite 单实例实现：同一会话运行互斥、删除准入、运行领取、心跳、过期收敛和终态提交。 |

## 工作流程

1. 受理请求时，锁服务在 SQLite 写事务中检查同一会话是否已有活动运行，并写入 `accepted` 运行与待处理用户消息。
2. 真正执行前，执行器通过 `issue_execution_lease()` 将运行条件迁移到执行中状态。
3. 事件记录期间定期心跳，并在终态提交时校验执行归属。
4. 删除会话会在同一临界区拒绝活动运行和临时标题线程，防止删除与远端创建竞争。
5. 过期运行会被标记失败并按是否真正开始执行决定保留或丢弃用户消息。

## 未来演进

- SQLite 能力对象明确声明仅支持单实例；不要把当前所有者字段当作分布式锁。
- 接入共享数据库后，应实现条件领取、租约到期、续期和围栏条件更新，并在心跳和终态写入中一并校验。
- 队列消费者只能拿到 `run_id`，必须在执行时领取租约；禁止依赖生产者进程内锁或回调。
