# 文件对话应用服务目录说明

本目录实现文件对话用例编排。应用服务负责决定何时创建运行、租约、事件和清理任务，但不直接知道 AnythingLLM API 路径、HTTP/SSE 序列化或具体 SQL 表结构。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `__init__.py` | 导出应用服务、调度器协议和关键结果类型。 |
| `command_service.py` | 运行生命周期命令门面：受理、终态提交、未启动收敛、执行租约和删除准入。 |
| `run_executor.py` | 主流执行边界：冻结输入、领取运行、创建或复用资源、绑定文档、调用端口并记录事件。 |
| `dispatcher.py` | 运行调度抽象和当前内联实现；调度器只接收持久化 `run_id`。 |
| `document_resolver.py` | 将业务文件名解析为不可变文档引用；数据库查询细节与执行器分离。 |
| `history_service.py` | 按接口所需结构读取本地已提交历史与标题输入快照。 |
| `title_service.py` | 根据本地历史生成标题，跟踪临时线程租约并安排清理。 |
| `abort_service.py` | 持久化运行中断请求，并可通过可替换通知器降低观察延迟。 |
| `delete_service.py` | 删除会话的准入、清理任务创建与已冻结 HTTP 结果语义。 |
| `cleanup_service.py` | 按持久化任务执行远端资源清理、失败记录和指数退避。 |
| `cleanup_dispatcher.py` | 清理任务调度协议和当前内联实现；只传递持久化 `job_id`。 |

## 运行执行流程

1. `RunExecutor.prepare_chat_run()` 校验文件和消息限制，解析文档，并通过 `CommandService` 在同一事务中受理运行与输入快照。
2. `Dispatcher` 将 `run_id` 交给执行器；执行器重新加载快照后领取执行租约。
3. 执行器经 `ChatConversationFactory` 创建任务级对话端口，创建/复用工作区和线程、记录租约、绑定文档并消费上游流。
4. `ChatRunEventRecorder` 先写事件账本再向外产出，终态时原子提交/丢弃消息并更新运行。
5. 路由层仅负责将事件交给展示层，不参与应用状态机。

## 删除与清理流程

1. `DeleteService` 调用命令层使会话进入删除中，拒绝活动运行和标题生成竞争。
2. 创建持久化清理任务后，`CleanupDispatcher` 调用 `ChatCleanupJobExecutor`。
3. 清理执行器从本地租约重新加载资源身份，调用端口删除线程或工作区，并将成功或失败写入租约和任务。
4. 当前公开删除接口要求同步完成；未来异步调度器可以替换调度器，但不能静默改变该接口响应语义。

## 维护规则

- 应用服务不能导入 Flask、Response、AnythingLLM 原子客户端或直接 SQL。
- 新队列执行器必须复用 `run_id`/`job_id` 入口，并在执行时重新领取和校验归属。
- 任何影响标题、删除、历史或流事件的对外语义，都需先核对接口文档，且不得增删接口参数。
