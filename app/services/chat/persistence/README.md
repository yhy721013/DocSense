# 文件对话持久化目录说明

本目录提供文件对话的本地权威数据能力。当前由 SQLite 实现会话、运行、输入快照、消息、文档版本、外部资源租约、清理任务和内部事件账本；上层只依赖聚合存储与仓储协议，不直接依赖表结构。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `__init__.py` | 导出持久化聚合、仓储、租约和事件账本类型。 |
| `store.py` | 定义持久化能力声明、聚合存储协议、当前 SQLite 聚合入口及显式禁用的发件箱边界。 |
| `repositories.py` | SQLite 连接、带版本的架构迁移，以及会话、文档绑定、运行、运行输入、清理任务和消息仓储。 |
| `resource_lease_service.py` | 外部工作区、线程和文档绑定的租约状态机，确保资源身份与清理失败可追溯。 |
| `event_repository.py` | 内部流事件账本：严格递增序号、唯一终态事件，并支持与运行状态同事务写入。 |

## 本地权威数据流程

```text
请求受理事务
  -> chat_sessions / chat_runs / chat_run_inputs
  -> 待处理 chat_messages

运行执行
  -> chat_resource_leases（计划 -> 激活 -> 清理）
  -> chat_document_bindings 与当前版本投影
  -> chat_run_events（先持久化，再展示）

终态或删除
  -> 原子收敛消息和运行
  -> chat_cleanup_jobs 记录可重试远端清理
```

## 架构与一致性原则

- `ensure_chat_schema()` 使用有编号迁移保存架构演进；不要在业务服务里临时创建表或自行修改迁移版本。
- 运行输入快照、消息状态、租约和清理任务是恢复依据。未来工作进程必须重新加载这些数据，不能依赖内存对象。
- SQLite 仅提供单实例本地事务和条件更新，不能被当作可靠队列、跨实例锁或事务发件箱。
- `store.py` 明确暴露能力声明；未来改用共享数据库或可靠发件箱时，应增加新的适配器并更新能力校验。

## 维护规则

- 对表字段、索引、触发器、状态迁移或 JSON 结构的修改都属于数据模型改动，必须同步补充迁移和离线仓储测试。
- 保持资源引用不透明；不要把供应商专有字段拆散进应用层或公开响应。
